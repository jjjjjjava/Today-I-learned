## 正文内容

两块，一张图各自收口。

### 一、纹理系统：对象 / id / 单元 / 类型

| 概念 | 一句话 | API |
|---|---|---|
| 纹理对象 | 显存里真正存「图像数据+参数」的东西 | glGenTextures 建 |
| 纹理 id | 对象的句柄，**当 fd/token 用，不是数据** | glGenTextures 返回 |
| 纹理单元 | 环绕 GPU 的**工位**（GL_TEXTURE0/1…），有限（16~32 个） | glActiveTexture 选 |
| 纹理类型(目标) | 工位接受的纹理种类，区别在**底层数据结构不同**（2D=RGBA，OES=YUV/私有） | glBindTexture(target,id) |

**取值链路**：`glActiveTexture` 选工位 → `glBindTexture` 把对象卡到工位的对应类型槽 → 着色器里 `glUniform1i(uTexture, 0)` 传的是**工位号 0，不是 id**。

> 一句话：**GPU 从「纹理单元的某个类型槽」取值，实际取到的是卡在那里的纹理对象。** 零拷贝就是 `updateTexImage` 把对象内部那根指针指向最新一帧的 GraphicBuffer——id/对象都没变，只换指向。
>
> 单元这层间接的意义：让一个着色器**同时**采样多张纹理（双路混合、LUT 滤镜）。

### 二、FBO：一组指针，关键是颜色附件

> **FBO 本身不存像素，它是一组附件挂载点（颜色/深度/模板）。真正存像素的是挂在颜色附件上的东西。**

| | FBO0（默认） | 自定义 FBO |
|---|---|---|
| 颜色附件挂的是 | **Surface**（EGL 关联默认 display） | **一张你建的纹理对象** |
| 结果去哪 | 上屏 | 离屏，进纹理 |
| 能否再当输入采样 | ✗（是 Surface buffer） | ✓（本身是纹理） |

**多级 FBO 原理**（= 你的总结）：

```
帧 → 渲染进 FBO①的纹理A → A 当输入 → 渲染进 FBO②的纹理B → … → 渲染进 FBO0 → 上屏
```

> **本质：把上一次的处理结果存成一张纹理，喂给下一次。** 所以「单层但要采样邻域（高斯模糊）」也得先存进 FBO 纹理再二次采样——判据是「要不要读别处结果」，不是层数。
