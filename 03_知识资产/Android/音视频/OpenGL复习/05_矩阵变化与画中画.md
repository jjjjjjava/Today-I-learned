## 正文内容

四件事，全靠**矩阵**。一句话总纲：**几何变换（摆正/平移/缩放）= 顶点左乘一个矩阵；半透明 = 片元阶段开混合。**

### 一、为什么拉伸 + 正交矩阵摆正

- **拉伸根因**：NDC `[-1,1]` 无脑铺满屏幕，OpenGL 不知道视频原始宽高比。
- **解法**：正交投影矩阵（`Matrix.orthoM`）压缩某一维，空出黑边。正交矩阵本质就是**缩放矩阵**：`m[0]`=X 缩放，`m[5]`=Y 缩放。

**判断压哪一维**（核心，别背反）：

| 比较 | 含义 | 动作 |
|---|---|---|
| videoRatio > screenRatio | 视频更「扁」 | 压**高度**（m[5]<1，上下黑边） |
| videoRatio < screenRatio | 视频更「高」 | 压**宽度**（m[0]<1，左右黑边） |

> videoRatio=视频宽/高，screenRatio=屏幕宽/高。压缩倍数 = 两个 ratio 的比值。

### 二、矩阵怎么从 CPU 到 GPU

```
CPU:  Matrix.orthoM() 算矩阵
   → glGetUniformLocation("uMatrix") 拿位置
   → glUniformMatrix4fv() 上传
GPU:  uniform mat4 uMatrix;
     gl_Position = uMatrix * aPosition;   // 每个顶点并行左乘
```

> 一句话：**矩阵当 uniform 传给顶点着色器，每个顶点左乘它完成变换。**

### 三、半透明 = 开混合

- 不开混合：alpha 无效，上层**完全盖住**下层。
- 开混合：`glEnable(GL_BLEND)` + `glBlendFunc(GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA)`
- 公式：`final = src×srcα + dst×(1−srcα)`
- **绘制顺序 = 层叠顺序**：先 draw 的在底层（画中画底图先加，小窗后加）。

### 四、平移 / 缩放矩阵（画中画交互）

| | 改矩阵哪里 | 怎么做 |
|---|---|---|
| 缩放 scaleM | 对角 `m[0] m[5]` | 在正交矩阵上**累乘**（正交是缩放矩阵，再 ×用户缩放系数） |
| 平移 translateM | 第 4 列 `m[12] m[13]` | 顶点坐标 + 平移量 |

**唯一的坑——平移量为什么要乘投影系数**（掌握项）：

```
手指移动 dx（屏幕占比）
 → 世界坐标移动 sx = dx × ratio × 2
 → 写进 m[12] 时还要 × m[5]（投影系数）
```

> 因为 `m[5]` 把世界坐标 `[-ratio, ratio]` 压进 NDC `[-1,1]`。平移发生在世界坐标，但矩阵第 4 列作用在 NDC 上，**所以平移量必须同步乘上这个压缩系数**，否则视频移动距离和手指对不上。缩放后要同步更新 ratio，正是为了让后续平移量算得准。
