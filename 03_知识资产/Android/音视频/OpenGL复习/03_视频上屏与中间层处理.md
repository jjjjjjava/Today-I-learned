# 视频上屏与中间层处理：FBO 是 GPU 的输出目标

> 前置知识：第①篇（管线）、02（零拷贝把帧变成纹理）
> 难度：进阶（复习）
> 本篇一个纲两个分支：**FBO 才是 GPU 的输出目标**——绑 FBO0 就上屏，绑自定义 FBO 就出纹理（中间结果）。
> 底层机制（EGL/Context/TLS、双三缓冲细节）见 06，本篇只串主线。

---

## 开篇：OpenGL 不止加水印

01、02 把「给视频帧加个水印」走通了。但 GPU 的能力远不止此——你想做的还有：

- **多级滤镜**：磨皮 → 调色 → 锐化，一层叠一层；
- **灵魂出窍 / 鬼影**：把上一帧放大、半透明叠在当前帧上；
- **高斯模糊**：当前像素要看**邻域**一片像素；
- **AI 滤镜**：风格迁移、人像分割换背景（见文末 teaser）。

这些都需要同一件事：**把渲染出的结果再加工一遍**。而像高斯模糊这种「要读邻域」的，**必须先把整张帧渲染完，再对它后处理**——单个片元着色器逐像素并行、每个像素只看自己，拿不到「别处的渲染结果」。

怎么把「渲染结果」变成「下一步能采样的输入」？答案是一个统一的东西：**FBO**。

---

## 立纲：FBO 才是 GPU 的输出目标

OpenGL 的渲染结果**写向「当前绑定的 framebuffer」**——绑谁，就写谁。这是本篇的总纲：**控制 FBO，就控制了 GPU 输出到哪。**

> **FBO 本质 = 一组附件挂载点（attachment points），本身不存像素。** 像素存在挂到它**颜色附件**上的东西里。

按「当前绑的是哪个 framebuffer」，分两个分支：

| 当前绑定 | 谁创建 | 结果落在哪 | 用途 |
|---|---|---|---|
| **FBO0（默认）** | **系统给的**，你挂不了附件 | window EGLSurface 背后的 **GraphicBuffer** | **上屏**（分支 A） |
| **自定义 FBO** | 你 `glGenFramebuffers` | 你挂的那张**纹理**（离屏，留显存） | **中间结果**，多级后处理（分支 B） |

⚠️ **别把 FBO0 说成「颜色附件指向 Surface」**：FBO0 是 window EGLSurface **自带**的默认帧缓冲，你创建不了、也挂不了附件——`eglMakeCurrent` 选中一个窗口 EGLSurface，FBO0 就自动等于那个 Surface 的缓冲。只有**自定义 FBO** 才由你挂纹理附件。

---

## 分支 A：FBO0 → 上屏

绑着 FBO0 渲染，结果进窗口 Surface 的 GraphicBuffer，再走上屏：

```
glDrawArrays 渲染进后缓冲（窗口 Surface 的 GraphicBuffer）
   ↓ eglSwapBuffers
把后缓冲 queueBuffer 进 BufferQueue + Binder 通知 SurfaceFlinger（不是立刻显示！）
   ↓ 等 VSync 信号
SurfaceFlinger 被唤醒 → acquireBuffer 取走这帧
   ↓
HWC（硬件合成器）合成所有 Layer（你的视频层 + 状态栏 + …）
   ↓
扫描输出上屏 → SurfaceFlinger releaseBuffer 还回，循环复用
```

> **一句话：`eglSwapBuffers` 不是「立刻显示」，是「把帧交给 BufferQueue 的消费者 SurfaceFlinger」，由它在 VSync 到来时取走、合成、上屏。**

为什么要双 / 三缓冲 + VSync（此处点到，细节见 06）：

| 机制 | 解决什么 |
|---|---|
| 双缓冲 | 前缓冲显示 + 后缓冲渲染，交换 → 防**画面撕裂** |
| 三缓冲 | 前缓冲没释放、后缓冲已用完时不让 GPU 空等 → 防**阻塞** |
| VSync | 等显示器同步信号再交换 → 进一步防撕裂 |

## 分支 B：自定义 FBO → 纹理 → 多级后处理

### 为什么不能都堆在一个片元着色器里

片元着色器是**逐像素并行**的，每个像素只看自己。只要某一步需要**读到「上一步的整张渲染结果」**——比如：

- 高斯模糊：当前像素要采样**邻域**多个像素；
- 多级串联：先磨皮，再拿磨皮后的整张图去调色；

单个着色器里拿不到「别处 / 上一道工序的输出」，就堆不进去。**判据不是「几层」，是「这一步要不要读别处的渲染结果」。**

### FBO：把「渲染结果」变成「下一道工序的输入纹理」

自定义 FBO 提供一块**离屏画布**：渲染结果不上屏，而是存进 FBO 挂着的那张纹理；这张纹理再当下一次渲染的输入。机制：

```
glGenFramebuffers 建 FBO
  → glFramebufferTexture2D 把一张纹理挂到颜色附件
  → glBindFramebuffer(FBO1)   ← 把输出目标切到 FBO1
  → glDrawArrays              ← 渲染！这一画，像素就写进了那张附件纹理
```

⚠️ **这里最容易记错（专门焊死）**：渲染进 FBO 纹理，靠的是上面那句 **`glDrawArrays`——「画」这个动作本身就把结果写进了附件纹理，不需要、也不能 `eglSwapBuffers`。** `eglSwapBuffers` 是 **EGL 层对窗口**的操作（把窗口后缓冲交给 SurfaceFlinger）；自定义 FBO 没有 BufferQueue 消费者，对它 swap 毫无意义。画完只要 `glBindFramebuffer` 切到下一个目标即可。

多个滤镜就这样**链式串成流水线**：

```
视频帧(OES) → [绑 FBO①渲染：磨皮]        → 纹理A
            → [绑 FBO②渲染：拿纹理A调色] → 纹理B
            → [绑 FBO0渲染：拿纹理B加水印] → eglSwapBuffers → 上屏
```

> 高斯模糊只要一层 FBO：先把帧渲进 FBO 纹理，再在下一 pass 把这张纹理当输入、在片元着色器里采样邻域做加权。

| 要点 | 说清 |
|---|---|
| FBO 本质 | 一组**附件挂载点**，本身不存像素；像素存在挂到颜色附件上的**纹理**里 |
| 中间 pass 收尾 | 输出是 FBO 纹理，**不 `eglSwapBuffers`**——靠 `glDrawArrays` 写进纹理；只有最后切回 FBO0 才 swap 上屏 |
| 代价 | 每多一级 = 多一遍渲染 + 一块显存，层数要克制 |

> ⚠️ **EGL 层 vs GL 层别混**：`glBindFramebuffer` / `glDrawArrays` 是 **GL 层**（选哪个 framebuffer、往里画）；`eglMakeCurrent` / `eglSwapBuffers` 是 **EGL 层**（选哪个窗口、交不交窗口）。「自定义 FBO 不 swap」的根因就在这两层之分——细节见 06。

### AI 滤镜（teaser，本课范围外）

AI 滤镜（风格迁移、人像分割换背景、卡通化……）**只是把链条里某一 pass 的「手写片元着色器」换成「神经网络推理」**——输入还是纹理，输出还是纹理（或一张 mask，再用老办法在片元着色器里混合回去）。FBO 串流水线的职责完全没变。

- 模型跑在 TFLite GPU delegate / NNAPI / MediaPipe 等；
- 和 GL 衔接靠**纹理 interop**（共享同一块 GPU 纹理、零拷贝，和 02 的 OES 同源思路）；走 `glReadPixels` 回 CPU 是慢路、有两次拷贝，能免则免。

> 这块是图形学 + ML 的交叉，不在本课 syllabus 内。记住一句：**AI 滤镜 = 某一 pass 换成 NN，FBO 链路照旧。**

---

### 收束

视频渲染的**输出侧**，统一在一句话下：**FBO 是 GPU 的输出目标，控制 FBO 就控制输出去向。**

1. **上屏**（绑 FBO0）：写进窗口 Surface 的 GraphicBuffer → `eglSwapBuffers` 交给 SurfaceFlinger → VSync 时合成上屏。
2. **中间层处理**（绑自定义 FBO）：要读上一步结果的加工，离屏渲进纹理、链式传递，最后一道才切回 FBO0 上屏。

接上 02：02 把解码帧**零拷贝变成可采样纹理（输入侧）**，本篇把这张纹理**加工 + 送出（输出侧）**，视频渲染主链路闭环。
