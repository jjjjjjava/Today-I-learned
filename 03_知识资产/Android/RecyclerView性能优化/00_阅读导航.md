# RecyclerView 性能优化｜阅读导航

这套笔记只围绕一个总问题展开：

> **一帧为什么没能按时完成？时间具体花在了哪里？**

## 推荐阅读顺序

| 篇目 | 只解决一个核心问题 |
|---|---|
| 01｜整体性能模型 | 一条 Item 从数据到画面经历什么？ |
| 02｜复用与缓存 | 滚动时，ViewHolder 从哪里来？ |
| 03｜布局与滚动 | Holder 已经有了，为什么仍可能卡？ |
| 04｜数据更新与绑定 | 数据变化时，怎样只做必要工作？ |

## 贯穿四篇的总模型

```text
一次列表更新或滚动
        ↓
获取 Holder：缓存命中 / Pool 命中 / 新建
        ↓
绑定数据：完整绑定 / Payload 局部绑定
        ↓
measure → layout → draw
        ↓
在帧截止时间前提交画面
```

遇到卡顿时，不要先问“该开哪个优化开关”，而要依次问：

1. 是创建多，还是绑定重？
2. 是布局、绘制重，还是更新范围过大？
3. 是否存在主线程阻塞、频繁分配或 GC？
4. 证据来自 Trace，还是仅凭猜测？

## 阅读方法

每篇按同一节奏组织：

```text
本篇问题 → 具体场景 → 核心模型 → 优化原则 → 常见误区 → 自测
```

先掌握模型，再记 API。API 会变，成本归因方法更稳定。
