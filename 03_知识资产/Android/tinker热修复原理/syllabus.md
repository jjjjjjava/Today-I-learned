## 背景与衔接

你已经通过课程1梳理清楚了"ANR修复 → 灰度 → Bugly收敛判断 → 全量发布"这条**工程链路**。本课程补的是Tinker框架侧的原理，深度以面试追问层级为界：

- **L1**（补丁为什么重启才生效）：必须真懂 → 模块一
- **L2**（方案对比、7.0前后注入路线为什么分家）：必须真懂 → 模块二
- **L3/L4**（资源so修复细节、diff算法）：只留兜底话术，主动收口 → 模块三

## 核心掌握项

### 模块一：整体架构与补丁生效时机（含前置：类加载器三条规则）
- [x] 能说出类加载三条规则：双亲委派 / dexElements顺序查找先到先得 / 已加载缓存不可逆（01.md，思考题全对）

- [x] 能口述补丁从生成到生效的完整链路，说清"合并"（后台:patch进程，一次性）和"生效"（下次冷启动attachBaseContext）是两个时刻，以及为什么必须冷启动（02.md+对话确认）
