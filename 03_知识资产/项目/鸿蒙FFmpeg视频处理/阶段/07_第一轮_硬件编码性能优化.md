# 07 · 第一轮：硬件编码性能优化

## 现象

2 分钟视频加水印约需 `150s`，处理时间超过视频时长，怀疑仍在 CPU 软件编码。

## 排查链

```text
确认水印必须重新编码
→ 向平台确认h264_ohosavcodec
→ 命令指定输出编码器
→ Native日志提示codec不存在
→ 排除命令位置
→ 当前.so未编入OpenHarmony codec
```

## 处理

获取包含 OpenHarmony 硬件适配的 FFmpeg 源码，修改 `HPKBUILD` 和构建配置，重新交叉编译单一 `.so`，替换产物并回归。

## 结果

公司阶段统一口径：

- `150s → 27s`；
- 耗时降低约 `82%`；
- 速度约提升 `5.6` 倍。

不能笼统称为 GPU/NPU 编码，应表述为接入 OpenHarmony 系统硬件编解码能力。
