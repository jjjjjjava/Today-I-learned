# 04｜两分钟水印耗时 150 秒，硬件编码为何没生效？

## 本篇只解决一个问题

视频水印功能已经跑通，但处理 2 分钟视频需要约 150 秒。性能问题怎样从一个耗时现象，收敛到 Native 构建产物？

## 为什么录像下载快，视频水印却很重？

录像下载在输入编码与 MP4 兼容时，可以直接复制压缩数据包：

```text
RTSP
→ 解复用
→ stream copy
→ MP4 封装
```

图片水印改变了每帧像素，不能只换容器：

```text
输入视频
→ 解码
→ overlay 合成水印
→ H.264 重新编码
→ MP4 封装
```

两条链路的主要差别不是有没有图片，而是是否需要重新编码。编码通常是水印链路中最重的阶段。

## 150 秒能直接证明是软件编码吗？

不能。2 分钟视频处理约 150 秒，只说明性能异常，并提示编码阶段值得优先检查。结合当时的命令和产物能力，团队提出了“仍在使用 CPU 软件编码”的假设。

这个假设需要日志和编码器信息验证，不能仅凭总耗时直接写成根因。

## 怎样确认平台硬件编码入口？

项目向华为确认 OpenHarmony FFmpeg 的 H.264 硬件编码器名称：

```text
h264_ohosavcodec
```

水印命令将它指定为输出视频编码器：

```text
ffmpeg -i input.mp4 \
  -i watermark.png \
  -filter_complex "overlay=main_w-overlay_w-10:main_h-overlay_h-10" \
  -c:v h264_ohosavcodec \
  -c:a copy \
  -y output.mp4
```

`-c:v` 位于输出文件之前，作用于输出视频流。它改变的是重新编码阶段，不影响前面的解码与滤镜合成。

## 命令正确，为什么仍提示 codec 不存在？

Native 日志报告当前 FFmpeg 找不到 `h264_ohosavcodec`。这说明参数已经传到 fftools，但正在运行的 `.so` 没有注册该编码器。

```text
命令指定 h264_ohosavcodec
→ fftools 查找编码器
→ Native 报告 codec 不存在
→ 当前构建产物缺少 OpenHarmony 编码适配
```

此时继续调整 ArkTS 参数没有意义。问题已经从业务命令收敛到 FFmpeg 源码版本和构建配置。

## 怎样让编码器真正进入 `.so`？

项目获取包含 OpenHarmony 硬件编解码适配的 FFmpeg 源码，修改 Lycium 的 `HPKBUILD` 与相关配置，再用 OpenHarmony SDK/NDK 工具链重新交叉编译。

```text
获取平台适配源码
→ 开启所需 codec 与组件
→ 重新交叉编译
→ 生成新的单一 .so
→ 替换 App Native 产物
→ 用同一视频和命令回归
```

Lycium 负责组织源码、配置和构建流程；真正执行编译与链接的是 OpenHarmony 工具链。

## 优化结果怎样表达？

公司项目阶段使用相同口径验证：

| 指标 | 优化前 | 优化后 |
|---|---:|---:|
| 视频时长 | 2 分钟 | 2 分钟 |
| 加水印耗时 | 约 150 秒 | 约 27 秒 |
| 耗时降幅 | - | 约 82% |
| 速度提升 | - | 约 5.6 倍 |

准确表述是“接入 OpenHarmony 系统硬件编码能力”，不要直接写成“GPU/NPU 编码”。具体芯片可能使用独立媒体编解码单元。

开源仓库 README 后来记录过约 `15.68s`。该数据来自不同版本或环境，不能与公司阶段的 `150s → 27s` 拼成同一组对比。

## 三个典型判断

1. 水印耗时很高：先把编码列为重点阶段，还不能仅凭耗时宣布根因。
2. 指定 codec 后报告不存在：优先检查源码适配和构建产物，而不是继续改 ArkTS 命令。
3. 新 `.so` 可以打开编码器：还要验证输出可播放、画面正确、音频正常和耗时下降。

## 常见误区

1. 把重新封装与重新编码当成同一种成本。
2. 认为命令中写了硬件编码器，就代表产物一定包含它。
3. 把平台硬件编码笼统描述成 GPU 编码。
4. 用不同设备、版本或输入文件的耗时直接比较。
5. 只看速度，不验证输出视频是否正确。

## 本篇自测

1. 为什么视频加水印通常不能使用 stream copy？
2. 150 秒耗时为什么只是定位线索，而不是根因证据？
3. `codec not found` 把问题范围缩小到了哪一层？
4. `HPKBUILD` 与 OpenHarmony 编译工具链分别做什么？
5. 为什么 `15.68s` 不能并入 `150s → 27s` 的项目数据？

## 一句话总结

水印性能问题沿“重编码假设 → codec 日志 → 构建产物”收敛，补入 OpenHarmony 硬件编码适配后，公司阶段耗时由约 150 秒降至 27 秒。
