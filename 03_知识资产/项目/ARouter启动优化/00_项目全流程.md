## 2. 项目叙事

### 定性与止损

这是候选版本相对稳定版突然变慢，不是长期存量水位。LOW档P90从约4.5s升到12.8s，相对增加约8.3s。团队暂停灰度。

### 线上与线下证据

线上从`startup.total`下钻到`startup.stage.app_init`，再到`startup.task.arouter.init`。线下固定低端机、构建类型、入口和首次启动场景，用AS Profiler快速定位：

```text
ARouter.init
→ LogisticsCenter.init
→ ClassUtils.getFileNameByPackageName
→ DexFile.openDexFile
→ openDexFileNative
```

`openDexFileNative`聚合耗时约7.6s，说明候选版本进入运行时Dex扫描。

### 第一轮处理

旧`arouter-register`依赖被AGP 8移除的Transform接入方式，编译期注册链失效。`loadRouterMap()`没有完整`register()`，`registerByPlugin=false`，运行时回退Dex扫描。

方案选择恢复兼容新AGP的编译期注册，而不是异步转移成本或替换整个路由框架。接入Artifacts API插件后又修复目标variant命名问题，直到产物真正完成插桩。

### 第二轮处理

升级Java 21后构建报`Unsupported class file major version 65`。旧ASM `ClassReader`无法解析Java 21 Class。修复包括：

- `asm`、`asm-commons`、`asm-tree`统一升级到9.7；
- Visitor API调整为ASM9；
- 确认插件运行时classpath真正加载新版ASM；
- 修复variant匹配；
- 发布自维护插件并回馈上游。

### 验证与防线

本地ARouter初始化从约7.84s降到100ms以内，本地整段冷启动约9.4s降到1.54s；灰度LOW档P90从12.8s恢复到约4.5s。三组数据环境不同，不混用。

最终CI覆盖clean install first launch、upgrade first launch、cache-hit；同时检查Stage/Task预算、目标variant插桩、`loadRouterMap()`产物和Java/AGP/ASM兼容矩阵。

## 4. 全流程评分

每项0～2分：

1. 定性：区分增量劣化与存量优化。
2. 证据：线上、Profiler、Benchmark、产物分层。
3. 因果：两轮触发、根因、结果不混淆。
4. 取舍：能解释为什么恢复插件，而非异步或换框架。
5. 闭环：能讲到首次启动场景、兼容矩阵和上游回馈。

某项失分，只提前对应阶段或知识点卡。
