# ARouter 启动优化笔记｜修改诊断

## 原课程为什么难读？

旧 01 在项目刚开始时就提前总结两轮修复；旧 02 同时讲路由跳转、APT、加载、第一轮根因、方案和验证；旧 03 又把插件实现与 Java 21 故障放在一起。

旧 04 大量复述前三篇，并加入完整面试稿、追问表、证据分层和通用治理步骤。每一段都能单独理解，但项目主线多次中断和重复。

## 本次怎样拆分？

```text
01：灰度异常怎样收敛到 Dex 扫描
→ 02：ARouter 为什么存在插件与 Dex 两条加载路径
→ 03：怎样恢复编译期注册并验证第一轮修复
→ 04：怎样解决 Java 21 兼容并回填防线
```

每篇只回答一个问题，中间章节由案例中的自然追问决定，不再加入处理原则、决策路径、输出模板或证据阶梯。

## 哪些内容被删除？

- 上一篇思考题复盘、标准答案、`???` 和学习反馈；
- 预计阅读时间和课程预告；
- 旧 04 中重复前三篇的长面试稿与追问速查；
- Mock P50 数据；
- 与当前根因无关的通用流程。

## 哪些口径被保留？

- LOW 档 P90：`4.5s → 12.8s`，相对新增约 `8.3s`；
- 本地 `openDexFileNative` 聚合约 `7.603s`，不与线上差值画等号；
- 插件消除运行时发现成本，不删除 `loadInto()`；
- 运行时 Dex 扫描按类名筛选，插件按 Entry 路径和实现接口识别；
- Java 21 对应 major version 65；
- 恢复原基线不等于消除原有启动存量。
