# 机制三 · 路由加载

## 目标

把编译期生成的Root、Provider、Interceptor等索引装入Warehouse。加载有两条发现路径。

## 插件注册路径

```text
Gradle插件扫描生成Class
→ ASM修改LogisticsCenter.loadRouterMap
→ 插入register(类名)
→ 运行时调用loadRouterMap
→ register反射创建生成类
→ loadInto对应Warehouse索引
→ registerByPlugin=true
→ 跳过Dex扫描
```

插件消除的是运行时“发现生成类”的成本；必要的实例化和`loadInto()`仍会执行。

## Dex扫描路径

插件未生效时：

```text
获取APK所有Dex路径
→ 逐个打开Dex
→ DexFile.entries枚举全部类名
→ routes包名前缀过滤
→ Root/Provider/Interceptor类名前缀分类
→ 反射创建并loadInto
```

真正昂贵的是打开多个Dex和遍历全部类名，不是`startsWith()`本身。

## Warehouse与懒加载

- `groupsIndex`：`group → Group Class`。
- `routes`：`path → RouteMeta`。
- Root在初始化期进入`groupsIndex`。
- Group在首次访问该组时进入`routes`。

插件直接注册Root、Provider、Interceptor；不全量注册Group，保留分组懒加载。

## 编译期插件深挖

```text
APT生成Class
→ Artifacts API取得variant的allDirectories/allJars
→ 路径筛选候选Class
→ ASM按实现接口识别Root/Provider/Interceptor
→ 扫描完成后修改LogisticsCenter
→ RETURN前插入LDC + INVOKESTATIC register
→ ClassWriter输出
→ D8生成Dex
```

必须先收集完整类名集合，再统一修改`LogisticsCenter`；遍历顺序不确定，遇到目标Class就立即插桩会漏掉后出现的路由表类。

## 两轮事故

- 第一轮：AGP升级破坏旧插件接入，运行时回退Dex扫描。
- 第二轮：Java 21 Class major 65超出旧ASM解析能力，插件构建失败。
