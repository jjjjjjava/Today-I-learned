# 机制一 · 路由跳转

## 为什么需要路由表

传统Intent直接引用目标Class。ARouter调用方只持有字符串path：

```kotlin
ARouter.getInstance()
    .build("/user/login")
    .navigation()
```

因此运行时必须完成：

```text
/user/login → UserLoginActivity.class
```

## `build(path)`

创建Postcard，保存：

- path；
- group；
- Bundle与flags；
- 动画等配置。

此时Postcard还没有destination和route type。

## `navigation()`

进入：

```text
LogisticsCenter.completion(postcard)
```

`completion()`用path查找RouteMeta，再补全Postcard：

```text
destination
type
priority
extra
```

最后按类型执行：

- Activity：Intent与`startActivity()`；
- Fragment：创建实例并设置arguments；
- Provider：获取或创建服务实例。

## Group未加载时

```text
routes[path]找不到
→ 从path得到group
→ groupsIndex[group]找到Group Class
→ 反射创建并loadInto(routes)
→ 再次completion
```
