# 阶段六 · 防线回填与增量治理闭环

> 回答：怎样避免同类问题再次穿透到灰度。
> 事实源：[[../ARouter启动优化笔记#6.5 回填增量防线]]

## 1. 启动场景

```text
clean install first launch
upgrade first launch
cache-hit cold start
```

首次安装和升级首启必须单独出结果，不能一律当warm-up丢弃。

## 2. 指标预算

```text
startup.stage.app_init
startup.task.arouter.init
```

总启动判断用户影响，ARouter Task判断增量归属。测试没执行风险路径时，预算没有拦截能力。

## 3. 构建产物校验

- 目标variant执行插件任务；
- Root、Provider、Interceptor收集数量合理；
- `loadRouterMap()`存在完整`register()`；
- 缓存失效时`registerByPlugin`路径生效。

## 4. 兼容矩阵

```text
Gradle / AGP
Java Class major version
ASM解析版本
Visitor API
插件运行时classpath
Debug / Release / Benchmark variant
```

## 5. 功能回归

- 普通页面路由；
- Provider注册与获取；
- Interceptor注册与执行；
- 多模块路由完整性；
- Group懒加载。

## 6. 方法论闭环

```text
灰度发现
→ 暂停放量
→ 统一场景
→ 工具归因
→ 源码与构建链定位
→ 治本修复
→ 产物、性能、功能验证
→ 重新灰度
→ 漏网条件回填CI
```
