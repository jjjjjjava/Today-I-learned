# 机制五 · 渲染与首帧上屏

## 主链路

```text
WindowManager.addView
→ 创建 ViewRootImpl
→ requestLayout / scheduleTraversals
→ Choreographer等待VSYNC
→ doFrame / doTraversal
→ performTraversals
→ measure / layout / draw
→ 生成DisplayList
→ RenderThread转为GPU命令
→ GPU写入Buffer
→ SurfaceFlinger合成上屏
```

## 精确点

- `addView`只是建立ViewRootImpl和调度渲染，不等于像素已经可见。
- `performDraw`主要记录DisplayList，不等于CPU直接生成最终屏幕像素。
- `doFrame`是帧调度外层；Wall高、Self低时应继续下钻。
- `onResume`只表示Activity进入可交互生命周期阶段，不是首帧上屏证据。

## 项目关联

业务终点等待下一次draw，避免在数据返回或`addView`后过早打点。Trace中的`traversal`、`RV OnLayout`和`doFrame`都需按嵌套关系解释。
