# 阶段七 · 回归问题处理

> 回答：性能优化暴露隐式依赖后，怎样保住收益并修复根因。
> 事实源：[[../启动优化笔记#6.2 回归问题一：门店页重页面频繁切换]]

## 回归一：门店页频繁切换白屏

恢复懒加载后，重页面更容易 destroy/recreate。生命周期日志与反证表明问题来自页面重建和消费时序。

处理：

```text
冷启动保持低缓存
→ 首次进入门店页后提高局部缓存
→ 运行期减少频繁重建
```

没有恢复启动期全量缓存，避免吃掉 P0 收益。

## 回归二：“我的”页入口状态丢失

一次性 EventBus 事件在 Fragment 未创建、未注册时发出，状态丢失。

根因：

> 状态生产早于 UI 消费 ready。

处理：

- Activity 保存最新 `MineEntryState`；
- API 回调先更新快照；
- Fragment view ready 后主动获取并 replay；
- EventBus 保留实时通知，但不再是唯一状态源。
