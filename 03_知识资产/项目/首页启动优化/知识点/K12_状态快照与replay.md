# K12 · 状态快照与 replay

一次性事件适合通知“发生过什么”，不适合作为latest-wins状态的唯一来源。

本项目中，Fragment未创建时EventBus事件已经发出，入口显隐和红点状态丢失。

方案：

```text
生产方保存最新状态快照
→ 实时事件继续通知已就绪消费者
→ 新消费者view ready后主动读取快照
→ apply统一应用状态
```

这样修复“状态生产早于UI消费ready”，不再依赖启动期提前创建所有Fragment。

2. 为什么低缓存会暴露事件丢失？
3. 快照加replay如何保住启动收益？
