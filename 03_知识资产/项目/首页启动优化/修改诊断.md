# 首页启动优化笔记｜修改诊断

## 原笔记为什么难用？

旧课程分别讲了指标、Perfetto、首屏根因、方案和冷启动机制，但缺少从季度目标进入项目的第一步。读者容易直接抓 Trace，却不知道为什么先查首页构建。

另一个问题是内容成熟度混在一起：ViewPager2 和 WebView 已落地，DAG 只是设计，Baseline Profile 尚未对照验证，Tinker 只是启动机制背景。

## 本次怎样重写？

主线压缩为四个连续问题：

```text
线上目标先查哪一段
→ 线下怎样证明时间花在哪里
→ Trace 热点对应哪段源码
→ 本地收益怎样经过回归和灰度到达线上
```

每篇用一个真实场景展开。中间章节跟随自然追问，不再重复设置“处理原则、决策路径、输出模板、证据阶梯、成本模型、完成标准”等栏目。

附录 A 只保留解释项目所需的冷启动五阶段。附录 B 只区分 Tinker、Provider、DAG 和 Baseline Profile 的机制与项目身份，删除与当前案例无关的通用风险清单。

## 哪些口径被修正？

- 官方 TTFD 与项目 `bindApplication → TTFD_HomeWorkDesk` 区间分开命名。
- 优化前后要求固定 Macrobenchmark 的 `CompilationMode` 和 Profile 状态。
- 不再使用“RelativeLayout 嵌套必然指数级变慢”的绝对说法。
- Tinker 的类加载策略注明版本差异，不写成统一实现。
- DAG 和 Baseline Profile 不计入本次已验证收益。
