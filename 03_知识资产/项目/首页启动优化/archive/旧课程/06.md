## 全课终检清单（逐条自测）

### 一、口径（模块一）
- **为什么先定口径再改代码？** 没口径无法证明体感改善、无法判断改对没。
- **为什么 TTFD 不用 TTID？** TTID 只首帧可见（可能 Splash/壳子），TTFD 才是首页工作台可见。
- **本项目 TTFD 起止？** `bindApplication` → `TTFD_HomeWorkDesk`（权限模块 View add 并**经下一次 draw** 后打 marker）。
- **为什么等下一次 draw？** addView 只到对象层，要等 ViewRootImpl→vsync→performTraversals 出像素才算"看见"。
- **为什么起点选 bindApplication？** 点击→main 是系统调度+Zygote fork，业务不可控；从 bindApplication 进可控链路。

### 二、工具/计算/归因（模块二）
- **工具组合？** Perfetto（看中间哪里慢）+ 业务 marker（定终点）。
- **怎么算 TTFD？** SQL 限定目标进程，找起止 slice 相减，ts 纳秒÷1e6→ms（优化前 ≈2790ms）。
- **Wall/Self/Count 各是什么？** 总耗时 / 自身耗时 / 次数；**不能只看 Wall**。
- **doFrame Wall 高 Self 低说明什么？** 帧调度外层容器，下钻它内部的 traversal/inflate/layout。
- **聚合 Wall 能相加吗？** 不能，嵌套重叠会重复计算、超过总时长。

### 三、瓶颈机制（模块三）
- **inflate 为什么贵？** 每个标签反射 newInstance + 解析 attrs；手写 new 省反射（X2C/AsyncInflater 动机）。
- **RV 和 RelativeLayout 一回事吗？** **不是**。RV=RecyclerView（列表），RelativeLayout 才双重测量（横纵各一遍，嵌套 2ⁿ）。
- **RecyclerView OnLayout 为什么重？** 本该复用，重=首屏一次性铺太多 item/多 RV 实例被布局（根子 ViewPager 全量预加载）。
- **WebView gone 为什么还创建？** gone 只控显示，inflate 仍反射 new WebView → 触发 Chromium 初始化。
- **binder 579 次哪来的？** 生命周期调度/系统服务查询/window-Surface 建立；**渲染计算本身不走 binder**。

### 四、方案/取舍/回归（模块四）
- **P0/P1/P2 怎么分？** 按收益确定性+风险：P0=ViewPager 懒加载+WebView 移出；P1=模块分批+悬浮组件后置；P2=Application 瘦身。
- **为什么 Application 排 P2？** 实测才 220ms；主线程串行链路（Provider/生命周期）砍不动，ROI 低。
- **P0 成效？** TTFD 2790→1774ms，**≈36%**（不是 33%）。
- **门店页白屏怎么判断是时序问题？** 只重建后复现 + 生命周期打点（事件早于 view ready）+ 反证（数据其实回来了、加缓存就好）。
- **两个回归取舍？** 门店页**分阶段缓存**；"我的"页 **状态快照+replay**（治"状态生产早于 UI 消费 ready"，不靠一次性 EventBus）。
- **offscreenPageLimit=5 原本身兼两职？** ① 提前创建 Fragment 掩盖状态时序 bug；② 缓存防重建。

### 五、全流程全景（模块五·附录）
- **5 阶段？** 进程创建→主线程+双向 Binder→Application→Activity+Window 三层→渲染。
- **fork 返回值？** =0 子进程跑 main，>0 父进程拿子 pid 续轮询，<0 失败。
- **三层创建时机？** attach 生 PhoneWindow，setContentView 生 DecorView，addView 生 ViewRootImpl。
- **ContentProvider.onCreate 和 Application.onCreate 谁先？** Provider 先（系统要它能被外部早查询）。
- **Instrumentation 是什么？** ActivityThread 调用用户代码的统一入口（Espresso 拦截生命周期靠它）。
- **启动终点？** WMS 打 `Displayed` 日志（=TTID），`onResume ≠ 启动完成`。
