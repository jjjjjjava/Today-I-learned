# 启动优化方法论 · 课程大纲

> 这份大纲定义了完成本课题后你将掌握的所有能力。
> 学习深度：标准
> 文档数量因人而异，但掌握内容不打折扣。

## 核心掌握项

完成本课题后，你将能够：

### 一、指标与观测口径

- [x] 能够区分冷启动、温启动、热启动以及 TTID、TTFD，并为具体业务选择稳定的起终点。
- [x] 能够解释 P50、P90、超时率、样本量和设备分群各自解决什么问题，并识别样本结构变化造成的假劣化。
- [x] 能够把总启动耗时拆成稳定的 Stage/Task 观测树，并说明线上指标与本地 Trace 的证据边界。

### 二、增量与存量双线治理

- [x] 能够区分存量启动优化与增量劣化治理，并说明两者如何通过新基线和阶段预算衔接。
- [x] 能够完整推导“发现 → 归因 → 治理 → 验证”的共同闭环。
- [x] 能够为存量治理设计从线上分位数、同档位复现到新基线建立的流程。
- [x] 能够为增量治理设计从 MR、CI Benchmark、灰度到线上长尾监控的分层防线。

### 三、归因与治理决策

- [x] 能够沿“版本 → 场景 → 设备档位 → Stage → Task”缩小问题范围，再交接给 Macrobenchmark 与 Perfetto 完成根因解释。
- [ ] 能够从启动阶段和 CPU、调度、IO、锁、Binder、UI 渲染两个维度分析耗时。
- [x] 能够按“删除 → 缩短 → 移出关键路径 → 重排并发 → 降级”选择治理手段，并解释为什么简单异步化可能恶化低端机 P90。

### 四、验证、沉淀与面试表达

- [x] 能够设计本地、灰度和线上三层验证，避免只凭单次耗时或单一指标宣布优化成功。
- [x] 能够把首页冷启动存量治理案例嵌入统一方法论，并解释“关键路径重构 + 有限兼容”的改造边界。
- [x] 能够把 ARouter 增量劣化案例嵌入统一方法论，并准确区分真实实践、模拟演练和行业认知。

## 不在本课题范围内

- 不实现生产级 APM 后端、实时分位数聚合器或海量 Trace 存储系统。
- 不实现灰度发布、动态降级或 A/B 实验平台。
- 不穷举所有 SDK、框架和厂商 ROM 的专项优化技巧。
- 不把广告启动链路作为当前课程的核心实践范围。
- 不将 Synthetic Mock 数据表述为真实生产事故数据。
