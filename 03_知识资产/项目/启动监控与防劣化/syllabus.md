# 启动监控与防劣化 · 课程大纲

> 这份大纲定义了完成本课题后你将掌握的所有能力。
> 学习深度：标准
> 文档数量因人而异，但掌握内容不打折扣。
> 配套素材：用户提供的《线上监控与防劣化》文章（Android 启动优化系列第 5 篇）
> 续接课程：同目录 `首页启动优化/`（已完结）。那门课回答「怎么变快」，本课回答「怎么保持快」——面试中「你们优化完怎么防止回退？」这一追问的完整弹药。
> 推进方式：grill 模式。每篇思考题按「面试官拷问链」设计（主问 + 追问）；你提交反馈后，我会先就薄弱点拷问，再出下一篇。

## 核心掌握项

完成本课题后，你将能够：

### 模块一 · 线上埋点与指标体系
- [x] 能画出启动阶段切分（进程创建 → attachBaseContext → Application.onCreate → Activity.onCreate → TTID → TTFD），并讲清「分阶段埋点」相对「一个总时长」的定位价值
- [x] 能讲清 TTID 与 TTFD 的定义差异、`reportFullyDrawn()` 的作用、「TTID 快但 TTFD 慢」的空壳陷阱，并与首页启动优化项目的 `TTFD_HomeWorkDesk` 口径对上
- [x] 🔧 能解释线上如何取进程创建时刻：API 24+ `Process.getStartElapsedRealtime()` 与 `/proc/self/stat` starttime 换算原理，及为什么全链路统一用 elapsedRealtime 时基
- [x] 🔧 能解释 Looper Printer 慢消息监控的原理、为何开销极低，及它的两个局限（堆栈抓取时机滞后、`setMessageLogging` 唯一槽位冲突）

### 模块二 · CI 卡口：合入前拦截
- [x] 能讲清 Macrobenchmark CI 卡口的设计要点：固定模拟器环境、关闭动画、取 P50 判定、「相对基线容忍度（如 10%）」而非只设绝对阈值的原因
- [x] 能说清 Baseline Profile 的作用机制，及为什么要用 weekly CI job 自动再生成
- [x] 能主动指出 CI 卡口的盲区（模拟器 I/O 与算力失真、覆盖不了厂商 ROM 和低端机），并由此推导「CI 通过 ≠ 线上没事」

### 模块三 · 灰度与线上监控体系
- [x] 能设计一份启动上报结构，并讲清三个关键决策：设备分级（Tier）、环境字段（低内存/低电量/温控）、分层采样率（阶段耗时全量 + 慢消息堆栈 5%-10%）
- [x] 能讲清监控看板五面板的分工，与三类告警规则的设计逻辑（P50 突增百分比、低端机 P90 绝对阈值、TTFD−TTID gap 扩大）
- [x] 能讲清灰度阶段的版本对比分析方法与「涨幅超 15% 暂停扩量」的决策逻辑

### 模块四 · 组织防劣化与完整实战链路
- [x] 能讲清四件组织手段——Owner 机制、CODEOWNERS 强制 Review、启动预算制度、SDK 接入 Checklist——并说清各自拦住哪一类劣化来源
- [x] 能完整复述「告警 → 阶段定位 → 慢消息堆栈 → git 追溯 → 修复 → 防复发」的实战链路，并能替换成自己项目的版本在面试中讲出

## 不在本课题范围内

- Perfetto / Macrobenchmark 工具本身的用法（首页启动优化 02 篇已覆盖，此处只讲它们在 CI 卡口中的角色）
- DAG 异步初始化框架的设计（系列第 3 篇话题，本课只作为修复手段引用）
- APM SDK（Matrix / ArgusAPM 等）的源码级实现
- ANR / 卡顿 / 内存等其他线上监控维度（ANR 已有独立课程）
- 服务端数据管道与存储选型（只讲客户端上报结构与看板消费逻辑）
