# 02 · 共性归因

## 目标

面对一批存量 issue，先找共同边界，再挑代表样本。共性归因回答“优先看哪里”，不直接回答“技术根因是什么”。

## 切片顺序

```text
版本 / 机型 / 系统 / 地区 / 企业 / 页面
→ 公共调用栈
→ 找到集中边界
→ 形成代码排查假设
→ 抽取代表 issue
```

## 两个案例

### Camera 图片保存

页面聚类集中在 `CameraClickActivity`，再由代表 issue 证明主线程经过：

```text
Bitmap.compress → FileOutputStream.write
```

页面集中只负责缩小范围；主线程栈与源码线程边界才证明同步 IO。

### IJK 播放器释放

Activity 和机型分散，但公共栈都经过：

```text
VideoPlayChildView.stopPlay
→ IjkMediaPlayer.release
```

因此页面不是根因，公共播放器组件才是优先排查边界。

## 输出

共性归因必须留下：

1. 使用了哪些维度；
2. 哪个维度明显集中；
3. 排除了什么；
4. 代表 issue 为什么具有代表性；
5. 当前结论只是范围，还是已有单点证据。

## 复习检查

1. 页面集中为什么不能直接证明页面代码有问题？
2. 页面分散时，公共调用栈有什么价值？
3. 共性归因如何决定后续验证人群？
