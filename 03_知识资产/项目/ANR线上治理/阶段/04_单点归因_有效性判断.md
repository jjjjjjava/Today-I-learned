# 04 · 单点归因：有效性判断

## 目标

确认平台展示的主线程栈能否解释 ANR 发生时的阻塞。没有有效现场，后面的状态分析没有意义。

## 前置机制

- [[../../../Android/ANR复习/04_traces分析流程]]
- [[../../../Android/ANR复习/05_线上ANR监控方案原理]]

Bugly 发现异常、采集线程栈、平台聚合之间存在时机差。展示的栈可能是阻塞发生后的快照，而不是最严重时刻。

## 判断路径

```text
确认 issue 属于目标聚类
→ 查看主线程完整栈
→ 主线程栈能否解释长时间无响应？
   ├─ 能：进入状态与调用栈分析
   └─ 不能：判断采样过晚、栈缺失或证据不足
```

### `nativePollOnce`

```text
MessageQueue.nativePollOnce
→ MessageQueue.next
→ Looper.loop
```

它通常只能证明采样这一刻主线程在等新消息。不能单独证明此前没有阻塞，也不能直接证明系统问题。

在本课程只看主线程的边界下：

- 同聚类有其他有效主线程栈：更换代表样本；
- 有系统 trace 或连续采样：补充时序证据；
- 没有更多证据：归入 C 类，不强行归因。

## 有效现场最低条件

1. 样本属于目标聚类与目标时间窗口；
2. 主线程栈完整；
3. 栈中存在可能影响响应的执行或等待路径；
4. 业务调用链可以回到自有代码、三方代码或明确的系统调用；
5. 结论强度没有超过当前快照能证明的范围。

## 复习检查

1. 为什么 `nativePollOnce` 不能直接判定 issue 无效？
2. 单次线程快照能证明什么，不能证明什么？
3. 没有有效主线程现场时应该怎样结束分析？
