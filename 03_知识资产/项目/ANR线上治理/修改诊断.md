# ANR 线上治理笔记｜修改诊断

## 原笔记为什么难用？

原资料能分别解释 ANR 原理、Service 源码、线程状态和线上案例，但阅读顺序偏向“先学知识，再想怎么处理”。面对线上告警时，仍不容易判断先看批量数据还是先看单条堆栈。

系统原理与线上治理又分散在不同目录。读者容易记住超时阈值和线程状态，却没有把“入口—聚类—代表 issue—等待链—验证”连起来。

## 本次怎样重写？

四篇分别回答四个连续问题：

```text
一批 ANR 怎样收敛
→ 系统为什么判定当前样本超时
→ 怎样沿执行链或等待链追到责任方
→ 怎样修复并验证原聚类下降
```

01 保留独立的“共性归因原则”和“爆发归因流程”。前者处理日常存量，后者处理异常上涨和止损，不能被压缩成通用“处理原则”。

03 固定先讲 RUNNABLE、BLOCKED、WAITING、NATIVE，再归并为 A 自己执行、B 等待别人、C 当前证据不足。

## 哪些技术口径被修正？

- Broadcast 超时与 Intent 标志、Android 版本、CPU starvation 和 OEM 有关，不使用“前台固定 5 秒”的统一口诀。
- Provider 发布超时与远程 Provider 查询无响应分开描述。
- Input 区分完整事件生命周期与具体版本采用的超时起点，不统一写成从原始 `eventTime` 起算。
- `NATIVE` 作为线上常见栈形态讲解，不宣称它与 Java 三种 `Thread.State` 完全同维度。
