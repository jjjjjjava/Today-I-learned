# 线上 ANR 归因全流程

> 目标：把一批线上 ANR 收敛为一条可复查的主线程因果链；无法证明时明确停在“证据不足”。

## 一句话主线

```text
发现入口
→ 共性归因
→ 爆发归因（仅指标异常上涨时）
→ 选择代表 issue
→ 判断主线程现场是否有效
→ 结合主线程堆栈与状态提出假设
→ 归并为 A / B / C 三个排查方向
```

## 四类问题

| 层次 | 回答的问题 | 主要产物 |
|---|---|---|
| 发现入口 | 为什么现在开始处理这批 ANR？ | 日常看板任务或机器人告警 |
| 共性归因 | 这批问题共同集中在哪里？ | 人群、页面、版本或公共栈边界 |
| 爆发归因 | 为什么从这个时间点突然增加？ | 拐点、增量贡献、变更与反向验证 |
| 单点归因 | 代表 issue 的主线程为什么无法及时响应？ | A、B 或 C 类证据链 |

## 单点归因

```text
有效性判断
→ 主线程 + 堆栈状态
   ├─ RUNNABLE
   ├─ BLOCKED
   ├─ WAITING
   └─ NATIVE
→ 归并处理
   ├─ A：主线程自己执行太久
   ├─ B：主线程等待其他执行单元
   └─ C：当前主线程样本无法解释超时
```

## 案例锚点

- Camera 图片保存：共性归因 → `RUNNABLE` → A 类。
- 极验 AB-BA 死锁：`BLOCKED` → B 类。
- IJK `pthread_join`：`NATIVE` → B 类。
- “茉莉奶白”企业开关：爆发归因。

## 全流程自检

1. 我是否先说明入口，而不是直接打开一条随机堆栈？
2. 共性切片提供的是范围，还是已被误说成根因？
3. 指标上涨时，是否证明了拐点、增量贡献和变更关系？
4. 主线程栈是否处在有效采样时刻？
5. 最终结论属于 A、B 还是 C？证据缺口是什么？
