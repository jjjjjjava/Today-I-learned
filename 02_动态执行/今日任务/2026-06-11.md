### 7.1 ARouter 路由表生成阶段复述 v1

> 实际耗时：18 分钟  
> 状态：已完成初版复述  
> 评价：主链路清晰，已经能讲出 APT 扫描、RouteMeta 封装、按 group 分组、JavaPoet 生成索引文件这条主线。后续需要补上 Interceptor 表，并统一生成类名写法。

ARouter 路由表生成阶段的目的，是在编译期把用户代码里所有 `@Route` 注解静态收集出来，生成运行时可以加载的路由索引文件，避免运行时去扫描业务类本身。

这个阶段最终主要生成几类文件：

- `ARouter$$Root$$moduleName`
- `ARouter$$Group$$groupName`
- `ARouter$$Providers$$moduleName`
- `ARouter$$Interceptors$$moduleName`

其中：

- `Root` 文件保存的是 `group -> Group Class`，后续初始化时会加载到 `Warehouse.groupsIndex`。
- `Group` 文件保存的是 `path -> RouteMeta`，后续懒加载时加载到 `Warehouse.routes`。
- `Providers` 文件保存 Provider 服务映射。
- `Interceptors` 文件保存拦截器优先级与拦截器类的映射。

从构建流程看，点击构建 APK 后，会先进入编译准备阶段。在这个阶段会注册 `RouteProcessor` 这个注解处理任务；如果使用 ARouter Gradle 插件，也会注册字节码后处理阶段的任务。不过单说路由表生成，核心是 `RouteProcessor` 这条 APT 流程。

到编译开始阶段，Java / Kotlin 编译会触发 javac 的注解处理流程，调用 `RouteProcessor`，并把 `RoundEnvironment` 传给它。`RouteProcessor` 通过 `roundEnv.getElementsAnnotatedWith(Route.class)` 拿到所有被 `@Route` 标注的 `Element`，再从注解里读取 `path` 和 `group`，从 `Element` 中判断目标 Class 和路由类型，然后封装成 `RouteMeta`。

收集完成后，`RouteProcessor` 会按 group 对 `RouteMeta` 分组，再通过 JavaPoet 生成 Java 文件。它会先生成每个 group 对应的 `ARouter$$Group$$groupName`，其中 `loadInto()` 负责写入 `path -> RouteMeta`；再生成 `ARouter$$Root$$moduleName`，其中 `loadInto()` 负责写入 `group -> Group Class`；同时还会生成 `ARouter$$Providers$$moduleName` 保存 Provider 映射，以及 `ARouter$$Interceptors$$moduleName` 保存拦截器映射。

#### 面试精简版

> ARouter 的路由表生成发生在编译期。它通过 `RouteProcessor` 扫描所有 `@Route` 注解，把页面、Provider、Interceptor 等信息封装成 `RouteMeta`，再按 group 分组，通过 JavaPoet 生成 Root、Group、Provider、Interceptor 几类路由索引文件。这样运行时就不需要重新扫描业务类，只需要加载生成好的索引表，再把数据写入 `Warehouse`，后续跳转时通过 path 找到对应的 `RouteMeta`。

### 7.2 ARouter 路由表加载 + 跳转阶段串联复述 v1

> 状态：已完成  
> 薄弱点：插件加载模式的具体流程仍需针对复习。  
> 评价：你已经能把插件模式的主线讲出来：构建期扫描 ARouter 生成类，通过 ASM 修改 `LogisticsCenter.loadRouterMap()`，运行时直接 register，跳过 dex 扫描。后续需要把 AGP 任务注册、class/jar 产物处理、ASM 插桩点这几个细节再压实。

插件模式是在构建配置阶段通过 AGP 给当前构建变体注册字节码后处理任务。等 Java / Kotlin 编译和 APT 生成完成后，字节码后处理阶段会拿到当前 variant 的 class 产物，这些产物可能来自目录，也可能来自 jar。

插件会遍历这些 class 产物，用 ASM 的 `ClassReader` 读取字节码，再通过 `ClassVisitor` 访问类信息。它会先筛选 `com/alibaba/android/arouter/routes/` 包下的 ARouter 生成类，然后根据类实现的接口判断类型：实现 `IRouteRoot` 的是 Root 索引，实现 `IProviderGroup` 的是 Provider 索引，实现 `IInterceptorGroup` 的是 Interceptor 索引。插件会把这些生成类的完整类名收集起来。

同时，插件还会找到 `LogisticsCenter` 这个目标类，然后用 ASM 访问它的 `loadRouterMap()` 方法，在方法 return 前插入一系列 `LogisticsCenter.register("生成类名")` 调用对应的字节码。最后修改后的 class 产物继续交给 D8，打包成 dex 和 APK。

这样运行时初始化时，`LogisticsCenter.init()` 执行 `loadRouterMap()`，就会直接执行这些注册调用，把 `registerByPlugin` 置为 `true`，从而跳过运行时 dex 扫描。

#### 复习提示

下次复习不要只背结论，按这 5 步讲：

1. APT 先生成 ARouter 索引类。
2. Gradle 插件在字节码阶段扫描 class/jar。
3. ASM 找到 Root / Provider / Interceptor 索引类。
4. ASM 修改 `LogisticsCenter.loadRouterMap()`，插入 `register()` 调用。
5. 运行时 `LogisticsCenter.init()` 直接注册索引，跳过 dex 扫描。
