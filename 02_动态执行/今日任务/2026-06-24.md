来源：

目标：不是泛读，而是能把音视频主链路说顺。

### 2.1 主链路口述

- [ ] 用自己的话讲出：

```text
MP4 容器
-> 解封装
-> H264/H265 视频码流 + AAC 音频码流
-> 解码
-> YUV 视频帧 + PCM 音频帧
-> YUV 转 RGB 渲染到屏幕 + PCM 播放
```

### 2.2 四组概念压实

- [ ] 视频：帧率 vs 码率。
- [ ] 图像：RGB vs YUV / YUV420。
- [ ] 音频：PCM、采样率、位深、声道数。
- [ ] 编码压缩：H264 / H265、AAC、I/P/B、GOP、IDR。

### 2.3 Android API 对应关系

- [ ] MediaExtractor：从容器取轨道信息和压缩帧。
- [ ] MediaCodec：压缩帧 -> YUV / PCM。
- [ ] MediaMuxer：压缩帧 + format + pts/flags -> 新容器。
- [ ] Surface：视频解码输出直接进入渲染链路。

完成标准：

## 4. 收口输出：5 分钟

今天只留下两段口述稿，不写长文。

### 4.1 音视频基础 1 分钟口述

```text
MP4 是容器，里面通过 moov 管轨道和索引，通过 mdat 存 H264/AAC 压缩数据。播放时先用 MediaExtractor 解封装，拿到轨道信息、压缩帧和 PTS；再用 MediaCodec 解码，把 H264/AAC 还原成 YUV 视频帧和 PCM 音频帧。YUV 进入渲染链路，最终转成 RGB 上屏；PCM 进入音频播放链路。重封装则是在不改编码内容时，把压缩帧和时间戳重新写进新的 MP4 容器。
```

### 4.2 OpenGL01 1 分钟口述

```text
视频解码后得到的是 YUV 帧，但屏幕最终要显示 RGB 像素，而且每帧都有上百万像素要处理。CPU 擅长复杂控制，不适合对海量像素重复执行同一套计算，所以渲染交给 GPU。CPU 通过 OpenGL ES API 编译 shader、传顶点和纹理数据，GPU 再按渲染管线执行：顶点处理、图元装配、光栅化、片元处理、测试混合、写入帧缓冲。关键是光栅化会把少量顶点覆盖的区域切成片元，并插值出每个片元的纹理坐标，片元着色器再按坐标采样纹理，最终形成屏幕像素。
```
