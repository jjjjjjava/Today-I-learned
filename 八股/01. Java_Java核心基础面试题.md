### 3.1 [Java中提供了抽象类还有接口，开发中如何去选择呢？](https://link.juejin.cn/?target=https%3A%2F%2Fmp.weixin.qq.com%2Fs%3F__biz%3DMzg3ODY2MzU2MQ%3D%3D%26mid%3D2247488726%26idx%3D1%26sn%3D9501f5e7ad24191a4894e4c102f3b14c%26chksm%3Dcf111630f8669f2651ef7256e70a864ac6c7bcf7c7911dbb747a9c54c33aa170a07174cf9977%26token%3D1436311520%26lang%3Dzh_CN%23rd)

速记口诀：接口是"我能做什么"（has-a/can-do），用于行为规范约束。抽象类是表明我是什么"（is-a），用于代码复用。

举例理解：

- 抽象类表示关系，表示族谱基因，比如  Android中实际的View体系。

  - ```java
    // Android 中的实际例子：View 体系
    public abstract class View {
        // 所有 View 都有的共同属性
        protected int mLeft, mTop, mRight, mBottom;
        
        // 所有 View 都能复用的方法
        public void invalidate() {
            // 通知重绘的通用逻辑
        }
        
        // 强制子类实现的方法
        protected abstract void onDraw(Canvas canvas);
    }
    
    // TextView、ImageView 都"是"View
    public class TextView extends View {
        @Override
        protected void onDraw(Canvas canvas) {
            // TextView 特有的绘制逻辑
        }
    }
    ```

  - TextView是一个View，ImageView也是一个View，他们都继承了View的能力和属性

- 接口表示行为规范约束，表示其拥有的一个或一系列的能力

  - ```java
    // Android 中的实际例子：点击能力
    public interface OnClickListener {
        void onClick(View v);
    }
    
    // 任何类都可以"拥有"点击处理能力
    public class MainActivity extends AppCompatActivity implements OnClickListener {
        @Override
        public void onClick(View v) {
            // 处理点击
        }
    }
    
    // Button 本身也可以实现
    public class Button extends View implements OnClickListener {
        // ...
    }
    ```

  - 这个能力不是强制所有人都拥有的。比如：你父母是北京人，拥有四合院。那么你继承了你父母的北京户口和四合院。但是你不一定会开车。反而其他不是你血缘的可能会开车。

- 我们来看一个更为负责的多层次接口 + 抽象类的逻辑

  - ```java
    // 1️⃣ 基础能力：可执行
    interface Runnable {
        fun run()
    }
    
    // 2️⃣ 扩展规范：解码器 = 可执行 + 更多能力
    interface IDecoder: Runnable {
        // 继承了 run()
        fun pause()      // 新增能力
        fun stop()       // 新增能力
        fun goOn()       // 新增能力
        // ... 更多
    }
    
    // 3️⃣ 通用实现：实现接口规范
    abstract class BaseDecoder: IDecoder {
        override fun run() { /* 通用实现 */ }
        override fun pause() { /* 通用实现 */ }
        override fun stop() { /* 通用实现 */ }
        abstract fun render(...)  // 留给子类
    }
    
    // 4️⃣ 具体实现：继承通用实现
    class VideoDecoder: BaseDecoder() {
        override fun render(...) { /* 视频特定 */ }
    }
    ```

### 3.2 重载和重写

重写就是重新写的意思，当父类中的方法对于子类来说不适用或者需要扩展增强时，子类可以对从父类中继承来的方法进行重写。

- 比如：

  - ```
    public class MainActivity extends Activity{
       @Override
       protected void onCreate(Bundle savedInstanceState) {
           super.onCreate(savedInstanceState);
           setContentView(R.layout.activity_main);
      }
    }
    ```

重载则是在同一个类中，允许存在多个同名方法，只要它们的参数列表不同即可。比如在Android开发中，我们会使用LayoutInflater的inflate方法加载布局，inflate方法存在多个定义，其中包括两个参数的，与三个参数的：

- 比如：

  - ```
    public View inflate(@LayoutRes int resource, @Nullable ViewGroup root) {
    	return inflate(resource, root, root != null);
    }
    public View inflate(@LayoutRes int resource, @Nullable ViewGroup root, boolean attachToRoot) {
       //......
    }
    ```

### 3.3 静态内部类和非静态内部类

在定义内部类时，如果内部类被static声明，则该内部类为静态内部类，否则为非静态内部类

- 比如：

  - ```java
    静态内部类
    public class OuterClass{
       static class InnerClass{}
    }
    
    非静态内部类
    public class OuterClass{
       int i;
       public class InnerClass{
           public InnerClass(){
               i = 10;
          }
      }
    }
    ```

- 当内部类被static声明，那么在内部类中就无法直接使用外部类的属性。

我们来通过字节码看看他们的本质差异

- 我们通过反编译后的字节码对比：

- 非静态内部类，注意看啊，这里通过OuterClass var1传递外部类实例引用进来

  - ```
    public OuterClass$InnerClass(OuterClass var1) {
        this.this$0 = var1;  // ⚠️ 隐式持有外部类实例引用
        var1.i = 10;
    }
    ```

- 静态内部类

  - ```
    public OuterClass$InnerClass() {
        // ✅ 没有外部类实例引用
    }
    ```

- 原理解释

  - 静态成员属于类，在类加载时就存在

  - 非静态成员属于实例，只有创建对象后才存在

  - 静态内部类没有外部类实例引用，所以无法访问非静态成员

实例化方式差异

- 如下

  - ```
    // 非静态内部类：必须先有外部类实例
    OuterClass outer = new OuterClass();
    OuterClass.InnerClass inner = outer.new InnerClass();  // 注意这个特殊的语法
    
    // 静态内部类：可以直接创建
    OuterClass.InnerClass staticInner = new OuterClass.InnerClass();
    ```

- 怎么理解呢

  - 非静态内部类：依附于外部类的实例存在，就像"寄生虫"需要宿主

  - 静态内部类：依附于外部类的类本身，是独立的"平等伙伴"

### 3.4 Java中在传参数时是将值进行传递，还是传递引用？

值传递：在方法调用时，传递的参数是这个参数指向值的拷贝；

引用传递：在方法调用时，传递引用的地址

我们来看看这两种方式

- 值传递

  - ```
    1 public class TransferTest {
    2     public static void main(String[] args) {
    3         int num = 1;
    4         System.out.println("changeNum()方法调用之前：num = " + num);
    5         changeNum(num);
    6         System.out.println("changeNum()方法调用之后：num = " + num);
    7     }
    8
    9     public static void changeNum(int x) {
    10         x = 2;
    11     }
    12 }
    ```

### 3.5 equals vs == 

==

- 对于不同的数据类型，使用==进行比较的意义不同：
  - 基本数据类型（也称原始数据类型） ：byte,short,char,int,long,float,double,boolean。用==，比较的是他们的值；
  - 引用数据类型：用（==）进行比较的时候，比较的是地址。

equals

- equals 方法是 Object 中定义的一个方法，源码如下：

  - ```
    public boolean equals(Object obj) {
      return (this == obj);
    }
    ```

- 可以看到实际上就是用的 == 实现的，所以这个原始方法意义不大，一般在类中做比较的时候，都会重写这个方法，如String、Integer、Date等。

  - ```
    //Integer
    public boolean equals(Object obj) {
    if (obj instanceof Integer) {
           //比较Integer中包装的int值
    return value == ((Integer)obj).intValue();
    }
    return false;
    }
    ```

结论

- equals和==的区别，需要分情况讨论：

  - 没有重写 equals ，则 equals 和 == 是一样的。
  - 如果重写了 equals，则需看 equals 的方法实现。以 String 类为例：

  1. - equals 是比较字符串的内容是否一样；
     - == 是比较字符串的堆内存地址是否一样，或者说引用的值是否相等。
