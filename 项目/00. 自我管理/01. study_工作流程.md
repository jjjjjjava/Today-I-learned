### 3.1 git开发流程是什么样的？

- 要基于本地已有分支创建新分支并进行开发，请按以下步骤操作：
  - ![image-20250716134207501](../../_pic_/image-20250716134207501.png)
- 基于远程分支
  - ![image-20250716134254553](../../_pic_/image-20250716134254553.png)
- 注：fetch只是先同步远端的分支信息。
  
- 提交呢
  - git pull origin modulize  （需要拉取别人的修改，防止后续push时把别人的修改覆盖了，毕竟是协同开发的过程）
  -  git push origin FEAT_WDZ_129598-128285-128279-panruiqi:modulize 

> 补充，如果是带子模块的呢？提交流程（含子模块）
>
> 假设父仓库叫 `modulize`，子模块叫 `submoduleA`。
>
> Step 1：更新子模块
>
> ```
> cd submoduleA
> git checkout <你要操作的分支>  # 确保在对的分支
> git pull origin <branch>          # 拉取远端最新修改
> ```
>
> - 这是确保子模块本身的代码和远程同步，避免你修改的内容覆盖别人。
>
> ------
>
> Step 2：处理子模块冲突（如有）
>
> 如果 `git pull` 发现冲突：
>
> ```
> # 在 submoduleA 内部解决冲突
> git add .
> git commit -m "fix merge conflict in submoduleA"
> git push origin <branch>
> ```
>
> - 解决完子模块冲突，再回到父仓库。
>
> ------
>
> Step 3：更新父仓库对子模块的引用
>
> 回到父仓库：
>
> ```
> cd ..
> git add submoduleA   # 父仓库记录子模块新 commit
> git commit -m "update submoduleA commit"
> ```
>
> - 这个操作是关键：父仓库只会提交子模块指向的 commit，而不是子模块内容本身。
>
> ------
>
> Step 4：更新父仓库主分支
>
> ```
> git pull origin modulize  # 父仓库拉取最新代码
> ```
>
> - 如果父仓库有冲突，这里再解决。
> - 注意，父仓库冲突通常不会涉及子模块内部代码，只会涉及父仓库对子模块 commit 的引用。
>
> ------
>
> Step 5：推送父仓库修改
>
> ```
> git push origin FEAT_WDZ_129598-128285-128279-panruiqi:modulize
> ```
>
> ------
>
> 3️⃣ 总结规则
>
> 1. **子模块先拉、先合并、先推送**
>    确保子模块本身没冲突，远端仓库是最新。
> 2. **父仓库记录子模块 commit**
>    修改父仓库时，提交的是子模块新 commit。
> 3. **父仓库再拉取/合并/推送**
>    避免父仓库冲突，顺序和普通仓库类似，但要注意子模块 commit 的变化。

------

### 3.7 新开发模块依赖冲突该如何处理？

- 用如下命令查看依赖树，定位是否有重复依赖：
  - ```
    ./gradlew :lib_graffiti:dependencies > deps.txt
    ```

  - 然后在 deps.txt 里搜索 code-scanner、protobuf、zxing 等，看看是不是有多个版本或 groupId。

- 强制排除冲突依赖

  - ```
    implementation('com.budiyev.android:code-scanner:2.1.0') {
        exclude group: 'com.github.yuriy-budiyev', module: 'code-scanner'
    }
    ```

- 检查依赖树

  - 用如下命令定位是哪个库引入了 com.github.yuriy-budiyev:code-scanner:2.1.0，然后在对应依赖上加 exclude。

  - ```
    ./gradlew :lib_graffiti:dependencies --configuration implementation
    ```

- 如需进一步定位是哪个库引入了 com.github.yuriy-budiyev:code-scanner，可以用如下命令：

  - ```
    ./gradlew :lib_graffiti:dependencies --configuration runtimeClasspath > runtime_deps.txt
    ```

  - 然后在 runtime_deps.txt 里搜索 code-scanner，就能看到是哪个库引入的。

**解决鸿蒙包体积异常增大的问题**

- 最新构建包从 48MB 异常增长至 ~900MB。
- 排查发现 `@ohos/mp4parser@2.0.6` 自带完整 FFmpeg 分离库，并被放置在顶级目录导致所有模块都引用了它。
- 注释掉相关引用后，包体积恢复正常。
- 同时对各模块中对 `redplayer` 的引用进行了优化，避免 hap 自身重复打包播放器相关 so，进一步降低包体积。

**调整 FFmpegUtils 的编译方式**

- 改为：将 FFmpegTools 源码 + FFmpeg 核心 `.a` 文件一起编译为单个 `.so` 的结构，便于后续维护和集成。

/**
     * 解码一帧
     * 此方法会阻塞直到有一帧输出或到达末尾
     * @return true 表示成功解码一帧并渲染到 Surface，false 表示已到达末尾
     */
    fun decodeFrame(): Boolean {
        if (isEndOfStream) {
            return false
        }
        
        val decoder = this.decoder ?: return false
        val extractor = this.extractor ?: return false
        
        // 循环直到获取到一帧输出或到达末尾
        while (true) {
            // 1. 尝试输入数据
            val inputBufferIndex = decoder.dequeueInputBuffer(TIMEOUT_US)
            if (inputBufferIndex >= 0) {
                val inputBuffer = decoder.getInputBuffer(inputBufferIndex)
                if (inputBuffer != null) {
                    val sampleSize = extractor.readSampleData(inputBuffer, 0)
                    if (sampleSize < 0) {
                        // 输入结束
                        if (!inputEOSSent) {
                            Log.d(TAG, "[DEBUG] Input EOS, sending END_OF_STREAM flag")
                            decoder.queueInputBuffer(inputBufferIndex, 0, 0, 0, MediaCodec.BUFFER_FLAG_END_OF_STREAM)
                            inputEOSSent = true
                        }
                    } else {
                        val presentationTimeUs = extractor.sampleTime
                        decoder.queueInputBuffer(inputBufferIndex, 0, sampleSize, presentationTimeUs, 0)
                        extractor.advance()
                    }
                }
            }
            
            // 2. 尝试获取输出
            val bufferInfo = MediaCodec.BufferInfo()
            val outputBufferIndex = decoder.dequeueOutputBuffer(bufferInfo, TIMEOUT_US)
            
            when {
                outputBufferIndex >= 0 -> {
                    currentPositionUs = bufferInfo.presentationTimeUs
                    decodedFrameCount++
                    
                    val isEOS = (bufferInfo.flags and MediaCodec.BUFFER_FLAG_END_OF_STREAM) != 0
                    
                    // 每100帧或前5帧打印日志
                    if (decodedFrameCount % 100 == 0 || decodedFrameCount <= 5 || isEOS) {
                        Log.d(TAG, "[DEBUG] Decoded frame $decodedFrameCount: pts=${bufferInfo.presentationTimeUs}us, size=${bufferInfo.size}, isEOS=$isEOS")
                    }
                    
                    // 渲染到 Surface
                    decoder.releaseOutputBuffer(outputBufferIndex, true)
                    
                    if (isEOS) {
                        Log.d(TAG, "[DEBUG] Output EOS received, total decoded frames: $decodedFrameCount")
                        isEndOfStream = true
                        return false
                    }
                    
                    // 成功获取一帧，返回 true
                    return true
                }
                outputBufferIndex == MediaCodec.INFO_OUTPUT_FORMAT_CHANGED -> {
                    Log.d(TAG, "[DEBUG] Output format changed: ${decoder.outputFormat}")
                    // 继续循环
                }
                outputBufferIndex == MediaCodec.INFO_TRY_AGAIN_LATER -> {
                    // 没有输出可用
                    if (inputEOSSent) {
                        // 已经发送了输入 EOS，继续等待输出 EOS
                        // 继续循环
                    } else {
                        // 还有输入数据，继续循环输入更多数据
                    }
                }
            }
            // 继续循环，直到获取到输出帧或 EOS
        }
    }
