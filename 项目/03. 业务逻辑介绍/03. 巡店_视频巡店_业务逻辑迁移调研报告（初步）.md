## 03.整体统计梳理

- 整体梳理具体如下：

  - ```
    视频巡店业务线 (lib_video + 5个依赖模块)
    │
    ├─【核心模块 lib_video】
    │  ├─ Activity层(6个)：VideoActivity、ReplayActivity、VideoSplitActivity等
    │  ├─ Fragment层(15个)：VideoPlayFragment、VideoDownloadFragment等
    │  ├─ Widget层(35个)：VideoPlayView、IjkPlayView、DragPointView等
    │  ├─ Presenter层(10个)：MVP业务逻辑层
    │  ├─ Adapter层(34个)：RecyclerView适配器
    │  ├─ Manager层(5个)：PlayManager、StorageCheckerManager等
    │  ├─ Utils层(20个)：VideoViewUtils、BuildUrl等
    │  └─ ViewModel层(4个)：LiveData状态管理
    │
    ├─【图片编辑 lib_edit】(8000行)
    ├─【媒体浏览 lib_media_viewer】(3000行)
    ├─【巡店公共 lib_patrol_shop】(12000行)
    └─【第三方SDK】
       ├─ IjkPlayer(FFmpeg)
       ├─ 萤石/乐橙/悠络客SDK
       ├─ VoiceIntercomManager
       └─ timerulerslib
    ```

- 不可压缩的技术风险

  - | 风险项                                        | 影响范围 | 迁移工作量 | 缓解方案                     |
    | :-------------------------------------------- | :------- | :--------- | :--------------------------- |
    | **4种播放器SDK不可用**                        | 12,000行 | 4-5周      | 统一降级RedPlayer (HTTP-FLV) |
    | **语音对讲库重写**                            | 3,000行  | 2-3周      | AVRecorder+G.711编解码重写   |
    | **时间轴组件重写**（很多是Android三方库组件） | 2,000行  | 2-3周      | ArkTS自定义组件              |
    | **VideoActivity重构**                         | 6,089行  | 3-4周      | 拆分为6个Feature模块         |
    | **FFmpeg重新编译**                            | Native层 | 1-2周      | RedPlayer编译脚本            |

  - 鸿蒙上的三方SDK较少，比如：视频播放模块，redplayer不支持rtsp，需要使用鸿蒙工具链重编译libffmpeg，这个很耗时间，因为鸿蒙工具链处理这个的笔记较少，需要自己探索。

  - 代码需要重构，之前的技术债（迫于需求交付压力导致的代码集成）：VideoActivity。6089行。VideoPlayFragment5390行。需要拆分重构架构，修改为MVVM架构。 

  - 需要的基础组件：播放器，libffmpeg,萤石/乐橙/悠络客SDK（尚不清楚他们是否适配鸿蒙）

- 整体工期评估（含架构重构）

  - | 场景              | 功能范围                           | 工期        | 人力  | 说明             |
    | :---------------- | :--------------------------------- | :---------- | :---- | :--------------- |
    | **最低可用P0**    | 播放+回放+设备（不含语音/AI/编辑） | 12-14周     | 2人   | 不重构，功能阉割 |
    | **合理迁移P0+P1** | +语音+云台+截图（不含AI/编辑）     | 18-22周     | 2-3人 | 部分重构         |
    | **完整对等**      | 全功能+架构完全重构                | **26-32周** | 3-4人 | 推荐方案         |

- 完整统计

  - **总代码量：~150,000行Java/Kotlin**
  - **总类数：275+个类**
  - **最低合理工期**：18-22周（4.5-5.5个月）
  - **推荐完整工期**：26-32周（6.5-8个月）

  - **UI组合式**：
    - 使用 Component 创建可复用 UI 组件（如 `DeviceSwitchBar`）。

  - **状态分散式**：
    - `VideoPatrolState` 作为全局状态聚合器。
    - 每个功能模块拥有独立状态：`DeviceState`、`VideoPlaybackState`、`VoiceIntercomState`。
    - 使用 `Observed + Track` 实现响应式，利用 `Provide/Consume` 实现状态共享。
  - **功能模块式**：
    - 按业务域划分目录，如 `feature_video_playback`、`feature_voice_intercom`。
    - 每个模块包含自己的 State、ViewModel、Manager，通过 DI 容器实现解耦。
    - 使用 Orchestrator 统一编排跨模块交互。
