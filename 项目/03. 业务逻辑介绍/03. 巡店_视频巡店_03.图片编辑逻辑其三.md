## 📖 第 1 步：FBO 离屏渲染原理深度解析

### 🎯 什么是 FBO？

**FBO（Framebuffer Object，帧缓冲对象）** 是 OpenGL ES 中用于实现**离屏渲染**的核心机制。

```
传统渲染（直接渲染到屏幕）：
┌──────────────────────────────────┐
│  GPU 渲染                        │
│  ↓                               │
│  默认帧缓冲（屏幕）               │
│  ↓                               │
│  用户看到结果                     │
└──────────────────────────────────┘

FBO 离屏渲染：
┌──────────────────────────────────┐
│  GPU 渲染                        │
│  ↓                               │
│  自定义 FBO（GPU 内存中的纹理）   │
│  ↓                               │
│  可选：读取到 CPU / 保存 / 复用   │
│  ↓                               │
│  将 FBO 作为纹理渲染到屏幕        │
│  ↓                               │
│  用户看到结果                     │
└──────────────────────────────────┘
```

---

### 🔑 核心概念：默认 FBO vs 自定义 FBO

#### ⚠️ 常见误解（已纠正）

```
❌ 错误理解：
"FBO 可以实现离屏渲染，如果不用 FBO 就是直接渲染到屏幕"

✅ 正确理解：
"所有 OpenGL 渲染都使用 FBO！"
├─ 渲染到屏幕 → 使用默认 FBO（FBO ID = 0）
└─ 离屏渲染 → 使用自定义 FBO（FBO ID ≠ 0）
```

---

#### 默认 FBO（FBO ID = 0）

```java
// 绑定默认 FBO（渲染到屏幕）
GLES20.glBindFramebuffer(GLES20.GL_FRAMEBUFFER, 0);
```

---

#### 自定义 FBO（FBO ID ≠ 0）

```java
// 创建自定义 FBO
int[] fbos = new int[1];
GLES20.glGenFramebuffers(1, fbos, 0);
int fboId = fbos[0];

// 绑定自定义 FBO（渲染到 GPU 内存）
GLES20.glBindFramebuffer(GLES20.GL_FRAMEBUFFER, fboId);
```

---

OpenGL线程控制GPU自动渲染到FBO，默认FBO则是屏幕，自定义FBO则是FBO绑定的颜色纹理对象的缓冲区。

### 🛠️ FBO 的组成部分

```
一个完整的 FBO 包含：

┌────────────────────────────────────┐
│  FBO (Framebuffer Object)         │
│                                    │
│  ┌──────────────────────────────┐ │
│  │  颜色附件（Color Attachment）│ │
│  │  ↓                           │ │
│  │  纹理（Texture）              │ │
│  │  ├─ 存储渲染的颜色数据       │ │
│  │  └─ 可以作为纹理复用         │ │
│  └──────────────────────────────┘ │
│                                    │
│  ┌──────────────────────────────┐ │
│  │  深度附件（Depth Attachment）│ │  ← 可选
│  │  ↓                           │ │
│  │  Renderbuffer                │ │
│  │  └─ 存储深度信息             │ │
│  └──────────────────────────────┘ │
│                                    │
│  ┌──────────────────────────────┐ │
│  │  模板附件（Stencil Attach.） │ │  ← 可选
│  │  ↓                           │ │
│  │  Renderbuffer                │ │
│  │  └─ 存储模板信息             │ │
│  └──────────────────────────────┘ │
└────────────────────────────────────┘
```

### 📝 FBO 创建流程（代码详解）

```java
// FBOManager.java - createFBO()

public FBO createFBO(int width, int height) {
    FBO fbo = new FBO(); //这是我们自定义的FBO封装类
    fbo.width = width;
    fbo.height = height;
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // Step 1: 创建纹理（用于存储渲染结果）
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    int[] textures = new int[1];
    GLES20.glGenTextures(1, textures, 0);
    fbo.textureId = textures[0];
    
    // 绑定纹理，默认纹理单元不用激活，可以直接绑定
    GLES20.glBindTexture(GLES20.GL_TEXTURE_2D, fbo.textureId);
    
    // 配置纹理参数
    GLES20.glTexParameteri(GLES20.GL_TEXTURE_2D, 
            GLES20.GL_TEXTURE_MIN_FILTER, GLES20.GL_LINEAR);
    GLES20.glTexParameteri(GLES20.GL_TEXTURE_2D, 
            GLES20.GL_TEXTURE_MAG_FILTER, GLES20.GL_LINEAR);
    GLES20.glTexParameteri(GLES20.GL_TEXTURE_2D, 
            GLES20.GL_TEXTURE_WRAP_S, GLES20.GL_CLAMP_TO_EDGE);
    GLES20.glTexParameteri(GLES20.GL_TEXTURE_2D, 
            GLES20.GL_TEXTURE_WRAP_T, GLES20.GL_CLAMP_TO_EDGE);
    
    // 分配纹理存储空间（注意：最后一个参数为 null），此时纹理对象终于拥有了自身的纹理存储空间了。
    GLES20.glTexImage2D(
            GLES20.GL_TEXTURE_2D,    // 目标类型
            0,                        // mipmap 级别
            GLES20.GL_RGBA,          // 内部格式
            width, height,           // 尺寸
            0,                        // 边框（必须为0）
            GLES20.GL_RGBA,          // 像素格式
            GLES20.GL_UNSIGNED_BYTE, // 数据类型
            null                      // ← 关键：不传入数据，只分配空间
    );
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // Step 2: 创建 FBO
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    int[] fbos = new int[1];
    GLES20.glGenFramebuffers(1, fbos, 0);
    fbo.fboId = fbos[0];
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // Step 3: 绑定 FBO 并附加纹理，告知OpenGL线程，当前渲染的对象是这个FBO，最终会渲染到这个FBO的颜色附着点上
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    GLES20.glBindFramebuffer(GLES20.GL_FRAMEBUFFER, fbo.fboId);
    
    // 将纹理附加到 FBO 的颜色附件 0
    GLES20.glFramebufferTexture2D(
            GLES20.GL_FRAMEBUFFER,           // FBO 目标
            GLES20.GL_COLOR_ATTACHMENT0,     // 附件点（颜色附件0）
            GLES20.GL_TEXTURE_2D,            // 纹理目标
            fbo.textureId,                   // 纹理 ID
            0                                 // mipmap 级别
    );
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // Step 4: 检查 FBO 完整性
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    int status = GLES20.glCheckFramebufferStatus(GLES20.GL_FRAMEBUFFER);
    if (status != GLES20.GL_FRAMEBUFFER_COMPLETE) {
        Log.e(TAG, "FBO not complete: " + status);
        return null;
    }
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // Step 5: 解绑（恢复到默认 FBO）
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    GLES20.glBindFramebuffer(GLES20.GL_FRAMEBUFFER, 0);
    GLES20.glBindTexture(GLES20.GL_TEXTURE_2D, 0);
    
    return fbo;
}
```

### 🎨 FBO 使用流程

```java
// onDrawFrame() - 每帧渲染

@Override
public void onDrawFrame(GL10 gl) {
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // Step 1: 渲染到 FBO（离屏渲染）
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    mFBOManager.bindFBO(mRenderFBO);  // 绑定自定义 FBO
    
    GLES20.glClear(GLES20.GL_COLOR_BUFFER_BIT);
    
    // 渲染场景内容，就调用OpenGL进行绘制就好了，他会自动会知道这上面的。
    renderScene();  // 绘制底图 + 箭头等
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // Step 2: 切换到默认 FBO（屏幕）
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    mFBOManager.unbindFBO(mSurfaceWidth, mSurfaceHeight);
    // ↑ 实际上是：glBindFramebuffer(GL_FRAMEBUFFER, 0)
    
    GLES20.glClear(GLES20.GL_COLOR_BUFFER_BIT);
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // Step 3: 将 FBO 内容作为纹理绘制到屏幕，其实本质是FBO绑定的纹理对象的纹理存储空间中的内容，绘制到默认FBO上
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    blitFBOToSurface();  // 纹理采样，非常快！
}
```

**关键理解**：

```
为什么是两步渲染，但性能不差？
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

误区：
"两步渲染 = 渲染两次 = 性能降低 50%"❌

真相：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Step 1: renderScene()
├─ 绘制底图纹理（1 次纹理采样）
├─ 绘制箭头（N 个三角形）
└─ 总成本：复杂场景渲染

Step 2: blitFBOToSurface()
├─ 绘制一个全屏四边形（2 个三角形）
├─ 纹理采样 FBO 的纹理（GPU 硬件优化）
└─ 总成本：≈ 0.5ms（极快！）
```

### 📖 FBO 像素读取

```java
// FBOManager.java - readBitmapFromFBO()

public Bitmap readBitmapFromFBO(FBO fbo) {
    if (fbo == null || !fbo.isValid()) {
        return null;
    }
    
    int width = fbo.width;
    int height = fbo.height;
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // Step 1: 绑定 FBO
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    GLES20.glBindFramebuffer(GLES20.GL_FRAMEBUFFER, fbo.fboId);
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // Step 2: 分配缓冲区
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    ByteBuffer buffer = ByteBuffer.allocateDirect(width * height * 4);
    buffer.order(ByteOrder.nativeOrder());
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // Step 3: 读取像素（❗ 性能关键点）
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    GLES20.glReadPixels(
            0, 0,                            // 起始位置
            width, height,                   // 尺寸
            GLES20.GL_RGBA,                  // 格式
            GLES20.GL_UNSIGNED_BYTE,         // 类型
            buffer                            // 目标缓冲区
    );
    // ↑ 耗时：10-15ms（1080×607 图片）
    // ↑ 原因：GPU → CPU 数据传输
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // Step 4: Y 轴翻转（OpenGL → Android 坐标系）
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    buffer = flipBufferVertically(buffer, width, height);
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // Step 5: 创建 Bitmap
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    Bitmap bitmap = Bitmap.createBitmap(width, height, Bitmap.Config.ARGB_8888);
    bitmap.copyPixelsFromBuffer(buffer);
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // Step 6: 解绑 FBO
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    GLES20.glBindFramebuffer(GLES20.GL_FRAMEBUFFER, 0);
    
    return bitmap;
}
```

### 🎯 为什么需要 FBO？

有没有疑惑：为什么要用FBO，对比原本的输出到GLSurfaceView的有哪些优点？因为使用FBO中间多加了一层中转，我们为什么要多加这一层中转呢？

默认FBO存在的问题

- 不好实现保存/OpenGL切换到默认工具的逻辑：无法读取像素直接保存为bitmap

  - ```java
    
    // 用户点击保存
    public void saveImage() {
        // ❌ 问题：无法高效读取默认 FBO 的像素
        glBindFramebuffer(GL_FRAMEBUFFER, 0);
        
        ByteBuffer buffer = ByteBuffer.allocateDirect(width * height * 4);
        glReadPixels(0, 0, width, height, GL_RGBA, GL_UNSIGNED_BYTE, buffer);
        // ↑ 可能失败，或性能极差（100-200ms）
        // ↑ Android 系统的默认 FBO 通常不支持高效读取
    }
    
    // 方案 B：渲染到自定义 FBO
    glBindFramebuffer(GL_FRAMEBUFFER, fboId);  // 自定义 FBO
    drawArrows();  // 绘制箭头到 FBO
    
    // 用户点击保存
    public void saveImage() {
        // ✅ 可以高效读取自定义 FBO
        glBindFramebuffer(GL_FRAMEBUFFER, fboId);
        
        ByteBuffer buffer = ByteBuffer.allocateDirect(width * height * 4);
        glReadPixels(0, 0, width, height, GL_RGBA, GL_UNSIGNED_BYTE, buffer);
        // ↑ 成功，性能稳定（10-15ms）
    }
    
    默认 FBO 的像素数据在哪里？
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    默认 FBO：
    ├─ 后备缓冲（backbuffer）由系统管理
    ├─ 通常存储在专用的显示缓冲区
    ├─ Android 系统可能使用双缓冲/三缓冲机制
    ├─ 缓冲区与显示器硬件直接关联
    └─ ❌ 应用程序无法保证高效访问
    
    自定义 FBO：
    ├─ 像素数据存储在我们创建的纹理中
    ├─ 纹理在 GPU 的通用内存区域
    ├─ 应用程序完全控制
    └─ ✅ 可以随时高效读取
    
    结论：
    没有 FBO，你根本无法可靠地保存用户的编辑结果！

### 🔬 FBO 底层机制深度理解

#### 核心认知（简洁版）

```
FBO = 索引容器（不存储数据）
纹理 = 数据存储（存储像素）

FBO 只存"指向数据的索引"
GPU 渲染时：查 FBO → 找索引 → 找数据 → 写入
```

FBO相关创建过程

```
1. FBO = 索引容器 ✅
   └─ 不存储数据，只存储指向数据的索引

2. glGenFramebuffers = 分配 ID ✅
   └─ 生成唯一标识符

3. glBindFramebuffer（第一次）= 创建对象 + 关联 ID ✅
   └─ 创建 FBO 对象，将 fboId 与对象绑定

4. glFramebufferTexture2D = 将纹理对象绑定到FBO对象的颜色附着点索引上，后续可以通过这个颜色附着点访问到对应的纹理对象 
   └─ FBO.colorAttachment0 = textureId

5. 绘制到 FBO = 写入纹理对象的纹理存储空间的 GPU 内存 ✅
   └─ GPU 查找 FBO → 找到 textureId → 写入纹理内存

6. 渲染到屏幕 = 采样上面自定义FBO的纹理对象的纹理存储空间 + 渲染到默认 FBO ✅
   └─ 将 textureId 作为输入纹理，绘制到默认 FBO
```



#### FBO vs 纹理的本质区别

```
纹理对象：
┌────────────────────────────────┐
│  纹理 ID: 1                    │
│  ├─ GPU 内存地址: 0x12345678   │
│  ├─ 宽度: 768                  │
│  ├─ 高度: 432                  │
│  ├─ 格式: RGBA                 │
│  └─ 数据: [像素数据 1.3MB]     │ ← 实际存储像素
└────────────────────────────────┘

FBO 对象：
┌────────────────────────────────┐
│  FBO ID: 2                     │
│  ├─ colorAttachment0: 纹理ID=1 │ ← 索引，指向纹理
│  ├─ depthAttachment: null      │
│  └─ stencilAttachment: null    │
└────────────────────────────────┘
      │
      └─ 不存储像素数据
      └─ 只存储"指向数据的索引"
```

#### 完整渲染流程（底层视角）

```

// 准备阶段
// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
int textureId = 1;  // 已创建的纹理（存储像素数据）
int fboId = 2;      // 已创建的 FBO（存储索引）

// FBO 内部结构：
FBO_Object_2 = {
  colorAttachment0: textureId = 1,  // 指向纹理
  depthAttachment: null,
  stencilAttachment: null
};

// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
// 渲染到 FBO（离屏渲染）
// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
glBindFramebuffer(GL_FRAMEBUFFER, fboId);
// OpenGL 状态机：currentFramebuffer = 2

glDrawArrays(GL_TRIANGLES, 0, 9);
// GPU 执行流程：
// 1. 读取全局状态：currentFramebuffer = 2
// 2. 查找映射表：fboId=2 → FBO_Object_2
// 3. 读取 FBO_Object_2.colorAttachment0 = 1
// 4. 查找映射表：textureId=1 → Texture_Object_1
// 5. 获取 Texture_Object_1 的 GPU 内存地址
// 6. 将渲染的像素写入该内存地址

// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
// 渲染到屏幕（使用 FBO 内容作为纹理）
// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
glBindFramebuffer(GL_FRAMEBUFFER, 0);
// OpenGL 状态机：currentFramebuffer = 0（默认 FBO）

glActiveTexture(GL_TEXTURE0);
glBindTexture(GL_TEXTURE_2D, textureId);  // textureId = 1
// 将 FBO 渲染的结果作为输入纹理

drawQuad();  // 绘制全屏四边形
// GPU 执行流程：
// 1. 读取全局状态：currentFramebuffer = 0（默认 FBO）
// 2. Fragment Shader 采样 textureId=1 的像素数据
// 3. 将像素写入默认 FBO（屏幕缓冲）
```

### 2️⃣ 双 FBO 的角色定义

```
┌────────────────────────────────────────────────────┐
│  FBO_A：已固化层（Settled Layer）                  │

│  FBO_B：工作层（Working Layer）                    │
├────────────────────────────────────────────────────┤

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

✅ FBO_A 是"历史快照"，固化后就不再改变
✅ 双层架构：类似 Photoshop 的图层系统

### 4️⃣ 绘制完成（Up 阶段 → 固化机制）

#### 什么是"固化"？

```
固化（Commit）的含义：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
将 FBO_B（当前箭头）的内容合并到 FBO_A（历史层）

不是"数据拷贝"，而是"GPU 渲染"：
├─ 将 FBO_B 的纹理作为输入
├─ 渲染到 FBO_A（Alpha 混合）
└─ 完全在 GPU 内存，无 CPU 参与
```

#### 核心动作：GPU 端纹理更新

```java
// 用户松开手指（Up）
@Override
public void onTouchUp(float x, float y) {
        mShapeList.add(mCurrentShape);
        mCurrentShape = null;
        
    // 固化到 FBO_A
        commitToSettledLayer();
}

private void commitToSettledLayer() {
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // GPU 端零拷贝固化（最优方案）
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    glBindFramebuffer(GL_FRAMEBUFFER, fboA.fboId);
    glEnable(GL_BLEND);
    glBlendFunc(GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA);
    
    // 将 FBO_B 渲染到 FBO_A（GPU 渲染操作）
    drawTexture(fboB.textureId);  // 0.3ms ✅
    
    // FBO_A 纹理已更新：底图 + 历史箭头 + 新箭头
}
```

#### 固化过程的底层原理

```
GPU 执行流程：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Fragment Shader 采样 FBO_B 的纹理
   └─ 读取 textureB[x][y]（GPU 内存）

2. Alpha 混合（GPU 硬件自动）
   └─ finalColor = srcColor × alpha + dstColor × (1-alpha)
   └─ srcColor：textureB 的像素（当前箭头）
   └─ dstColor：textureA 的像素（底图+历史）

3. 写回 FBO_A 的纹理
   └─ textureA[x][y] = finalColor

特点：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
✅ 完全在 GPU 内存（显存）
✅ 无 GPU → CPU 数据传输
✅ 无 CPU → GPU 数据传输
✅ 利用 GPU 纹理采样和混合硬件
✅ 耗时：0.3ms（极快）
```

#### 为什么只在 Up 阶段执行？

```
触发时机：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Down：开始绘制，无需固化
Move：实时绘制中，无需固化（FBO_B 动态变化）
Up：绘制完成，固化到 FBO_A ✅

原因：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. Move 阶段不固化
   └─ 用户还在画，箭头在变化
   └─ 固化没有意义（内容不确定）

2. Up 阶段固化
   └─ 箭头已完成，形状确定
   └─ 固化后变成"历史层"
   └─ 下次绘制只需采样（不重绘）

3. 固化成本可接受
   └─ 0.3ms（GPU 端）或 15ms（CPU 端）
   └─ 只在 Up 触发（低频）
   └─ 用户松手时触发，感知不明显
```

### 5️⃣ Undo / Redo 的代价模型

#### Undo 的必要成本

```java
public void undo() {
    // 移除最后一个箭头
    mShapeList.remove(mShapeList.size() - 1);
    
    // 重建 FBO_A（无法避免）
    rebuildSettledLayer();

private void rebuildSettledLayer() {
    glBindFramebuffer(GL_FRAMEBUFFER, fboA.fboId);
    glClear(GL_COLOR_BUFFER_BIT);
    
    // 重绘底图
    drawBaseImage();  // 5ms
    
    // 重绘所有剩余箭头
    for (Shape shape : mShapeList) {
        drawArrow(shape);  // N × 0.5ms
    }
    
    // 固化到纹理
    // ...
}

#### 为什么 Undo 不需要持续优化？

```
性能对比：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

场景：画了 100 个箭头，Undo 最后 1 个

双 FBO（当前方案）：
├─ Undo 一次：重建 FBO_A，耗时 50-70ms（一次性）
├─ 后续绘制：1.1ms/帧（恒定，流畅）✅
└─ Undo 是低频操作（用户偶尔触发）

单 FBO（无优化）：
├─ Undo 一次：移除数组元素，耗时 0.1ms（快）
├─ 后续绘制：50ms/帧（卡顿）❌
└─ 每帧都慢，用户持续感知卡顿

结论：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
✅ 宁可 Undo 慢一次（70ms，低频，用户不敏感）
✅ 也不能让每帧都慢（50ms，高频，用户非常敏感）
```

```
交换模型：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

频率对比：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

用户感知：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
绘制卡顿：非常明显，影响体验 ❌
Undo 延迟：不明显，可接受 ✅

设计哲学：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
优化高频操作（绘制）> 优化低频操作（Undo）
```

#### 特别强调：高频帧渲染 vs 低频 Undo

```
┌─────────────────────────────────────────────────┐

结论：

## ⚙️ GPU 渲染管线深度理解

### 🎯 什么是 GPU 渲染管线？

**GPU 渲染管线（Graphics Pipeline）** 是将 3D 几何数据转换为屏幕上像素的一系列固定步骤。

```
输入：顶点数据（位置、颜色等）
       ↓
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
       GPU 渲染管线（7 个主要阶段）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
       ↓
输出：屏幕像素（最终图像）
```

---

### 📊 渲染管线的 7 个主要阶段

```
┌────────────────────────────────────────────────────────┐
│  1. 顶点着色器（Vertex Shader）                       │
│     ├─ 输入：顶点属性（位置、颜色、纹理坐标等）       │
│     ├─ 处理：应用 MVP 矩阵变换                        │
│     └─ 输出：gl_Position（裁剪空间坐标）              │
├────────────────────────────────────────────────────────┤
│  2. 图元装配（Primitive Assembly）                    │
│     ├─ 输入：变换后的顶点                             │
│     ├─ 处理：将顶点组装成图元（三角形、线段等）       │
│     └─ 输出：完整的图元                               │
├────────────────────────────────────────────────────────┤
│  3. 裁剪（Clipping）                                  │
│     ├─ 输入：裁剪空间中的图元                         │
│     ├─ 处理：裁剪或丢弃视锥体外的图元                 │
│     └─ 输出：可见的图元                               │
├────────────────────────────────────────────────────────┤
│  4. 屏幕映射（Screen Mapping / Viewport Transform）   │
│     ├─ 输入：NDC 坐标（[-1, 1] 范围）                │
│     ├─ 处理：映射到屏幕坐标（像素坐标）               │
│     └─ 输出：屏幕空间坐标                             │
├────────────────────────────────────────────────────────┤
│  5. 光栅化（Rasterization）                           │
│     ├─ 输入：屏幕空间的图元                           │
│     ├─ 处理：确定图元覆盖哪些像素（片段生成）         │
│     └─ 输出：片段（Fragment，潜在的像素）            │
├────────────────────────────────────────────────────────┤
│  6. 片段着色器（Fragment Shader）                     │
│     ├─ 输入：片段（包含插值后的属性）                 │
│     ├─ 处理：计算片段颜色（纹理采样、光照计算等）     │
│     └─ 输出：gl_FragColor（片段颜色）                 │
├────────────────────────────────────────────────────────┤
│  7. 像素操作（Per-Fragment Operations）               │
│     ├─ 深度测试（Depth Test）                        │
│     ├─ 模板测试（Stencil Test）                      │
│     ├─ Alpha 混合（Blending）                        │
│     └─ 输出：最终像素颜色 → 帧缓冲                   │
└────────────────────────────────────────────────────────┘
```

---

### 🔍 各阶段详解

#### 阶段 1：顶点着色器（Vertex Shader）

```glsl
// vertex_shader.glsl

attribute vec4 vPosition;  // 顶点位置（输入）
uniform mat4 uMVPMatrix;   // MVP 矩阵（输入）

void main() {
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // 将顶点从模型空间变换到裁剪空间
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    gl_Position = uMVPMatrix * vPosition;
    // ↑ 输出：裁剪空间坐标（Clip Space）
}
```

**职责**：

```
1. 坐标变换
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
模型空间（Model Space）
    ↓ Model Matrix
世界空间（World Space）
    ↓ View Matrix
摄像机空间（View Space / Eye Space）
    ↓ Projection Matrix
裁剪空间（Clip Space）← gl_Position 的坐标系
    ↓ 透视除法（自动）
NDC（Normalized Device Coordinates，[-1, 1]³）

2. 顶点属性传递
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
✅ 可以将顶点属性（如颜色、纹理坐标）传递给片段着色器
✅ 使用 varying 变量（插值）
```

---

#### 阶段 2：图元装配（Primitive Assembly）

```
输入：变换后的顶点

处理：
┌────────────────────────────────────────┐
│  glDrawArrays(GL_TRIANGLES, 0, 6)      │
│                                        │
│  顶点序列：v0, v1, v2, v3, v4, v5      │
│                                        │
│  装配结果：                            │
│  ├─ 三角形 1：(v0, v1, v2)            │
│  └─ 三角形 2：(v3, v4, v5)            │
└────────────────────────────────────────┘

图元类型：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
GL_TRIANGLES      ← 每3个顶点组成一个三角形
GL_TRIANGLE_STRIP ← 共享边的三角形序列
GL_LINES          ← 每2个顶点组成一条线段
GL_POINTS         ← 每个顶点是一个点
```

#### 阶段 3：裁剪（Clipping）⭐ 关键阶段

```
输入：裁剪空间中的图元（gl_Position）

裁剪判断：

    // 顶点在视锥体外 → 裁剪或丢弃

透视除法（自动）：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

#### 阶段 7：像素操作（Per-Fragment Operations）

```
输入：片段颜色（gl_FragColor）

操作序列：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. 所有权测试（Ownership Test）
   └─ 检查片段是否属于当前窗口

2. 剪刀测试（Scissor Test）
   └─ glScissor() 定义的矩形区域外的片段被丢弃

3. 模板测试（Stencil Test）
   └─ 根据模板缓冲的值决定是否保留片段

4. 深度测试（Depth Test）
   └─ 比较片段的深度值，决定是否保留
   
   glEnable(GL_DEPTH_TEST);
   glDepthFunc(GL_LESS);  // 深度小的片段保留
   
   if (fragment.z < depthBuffer[x][y]) {
       // 更近，保留此片段
       depthBuffer[x][y] = fragment.z;
   } else {
       // 更远，丢弃此片段
       discard;
   }

5. Alpha 混合（Blending）
   └─ 将片段颜色与帧缓冲中的颜色混合
   
   glEnable(GL_BLEND);
   glBlendFunc(GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA);
   
   finalColor = srcColor * srcAlpha + dstColor * (1 - srcAlpha);
   
   示例：
   ├─ srcColor = red (1.0, 0.0, 0.0, 0.5)  ← 新片段
   ├─ dstColor = blue (0.0, 0.0, 1.0, 1.0) ← 帧缓冲
   └─ finalColor = (0.5, 0.0, 0.5, 1.0)    ← 紫色

6. 抖动（Dithering）
   └─ 用于减少颜色量化误差（通常禁用）

7. 写入帧缓冲
   └─ frameBuffer[x][y] = finalColor
```

### 🔍 观察到的现象

```
场景 A：手指按着不松，一直绘画
├─ 第 1 秒：绘制流畅（16ms/帧）✅

└─ 立即恢复：流畅（16ms/帧）✅

### 💡 根本原因：Path 的 O(N) 复杂度

#### 问题代码

```java
// 典型的绘制代码
private Path mPath = new Path();

@Override
public boolean onTouchMove(MotionEvent event) {
    float x = event.getX();
    float y = event.getY();
    
    mPath.lineTo(x, y);  // ← 持续累积点
    invalidate();
    return true;
}

@Override
protected void onDraw(Canvas canvas) {
    // ❌ 每次都绘制整条路径（包括所有历史点）
    canvas.drawPath(mPath, this.eraser ? mEraserPaint : mPaint);
}
```

#### Path 对象的累积效应

```
mPath 是一个累积的路径对象：

手指移动时：
├─ onTouchMove 第 1 次：mPath.lineTo(x1, y1)  → 1 个线段
├─ onTouchMove 第 2 次：mPath.lineTo(x2, y2)  → 2 个线段
├─ onTouchMove 第 3 次：mPath.lineTo(x3, y3)  → 3 个线段
├─ ...
└─ onTouchMove 第 N 次：mPath.lineTo(xN, yN)  → N 个线段

每一帧绘制时：
drawPath(mPath) → 重新绘制所有 N 个线段！❌

性能劣化曲线：
├─ N = 30（0.5秒）：   2ms   ✅
├─ N = 60（1秒）：     4ms   ✅
├─ N = 120（2秒）：    8ms   ✅
├─ N = 300（5秒）：    20ms  ⚠️ 开始卡顿
├─ N = 600（10秒）：   40ms  ❌ 明显卡顿
├─ N = 1200（20秒）：  80ms  ❌ 严重卡顿
└─ 时间复杂度：O(N)，线性增长
```

### 🎯 Canvas.drawPath() 内部机制

#### 简化的内部实现

```java
// Canvas.drawPath() 的简化逻辑
public void drawPath(Path path, Paint paint) {
    // 1. 获取路径的所有点
    float[] points = path.getPoints();  // 获取所有 N 个点
    byte[] verbs = path.getVerbs();     // 获取所有操作类型
    
    // 2. 遍历所有操作（❌ 关键问题：遍历所有历史点）
    for (int i = 0; i < path.getPointCount(); i++) {
        switch (verbs[i]) {
            case VERB_MOVE_TO:
                moveTo(points[i*2], points[i*2+1]);
                break;
                
            case VERB_LINE_TO:
                // 3. 绘制线段（需要计算抗锯齿、线宽、混合等）
                drawLine(
                    prevX, prevY,              // 上一个点
                    points[i*2], points[i*2+1], // 当前点
                    paint
                );
                // ← 每条线段都要重新计算！
                break;
        }
    }
}
```

**关键问题**：
- ❌ 每次 `drawPath()` 都要遍历**所有**历史点
- ❌ 每个点都要重新计算绘制（抗锯齿、线宽、Alpha 混合等）
- ❌ 即使这些点之前已经画过，Canvas 也无法识别
- ❌ 时间复杂度：O(N)，N 是路径中的点数

#### 为什么会劣化？

```
根本原因：
Canvas.drawPath() 每次都遍历所有历史点

劣化机制：
├─ 点数 N = 30：    遍历 30 次   → 2ms
├─ 点数 N = 300：   遍历 300 次  → 20ms
├─ 点数 N = 1200：  遍历 1200 次 → 80ms
└─ 时间复杂度：O(N)，线性增长

重复计算率：
├─ 1 秒后：50% 重复
├─ 5 秒后：90% 重复
├─ 20 秒后：98% 重复
└─ 极度浪费计算资源 ❌
```

#### 为什么松开后恢复？

```
松开时：
├─ 固化到 Bitmap（drawPath 一次）
├─ mPath.reset()（清空路径）
└─ 点数 N 回到 0

下次绘制：
├─ 只画新的线段（N 很小）
├─ 性能恢复到初始状态
└─ 但会再次累积，再次劣化 ⚠️
```

#### Canvas vs OpenGL

```
Canvas 方案：
├─ 每次都重绘所有内容
├─ 时间复杂度：O(N)
├─ 适合：静态图形、少量元素
└─ 不适合：实时绘制、大量累积 ❌

OpenGL 方案（双 FBO）：
├─ 历史内容：纹理采样（O(1)）
├─ 新增内容：增量渲染（O(k)，k=新增点数）
├─ 时间复杂度：O(1)，恒定！
└─ 适合：实时绘制、无限累积 ✅

性能差距：
├─ 5 秒：   20ms vs 1.2ms（16.7倍）
├─ 20 秒：  80ms vs 1.2ms（66.7倍）
└─ 差距随时间增大
```

### 📊 Y 轴转换详解（带翻转）

```
公式：y_ndc = -((y_screen / height) * 2.0 - 1.0)

关键：最外层的负号！

步骤分解：

1. y_screen / height
   → 归一化到 [0, 1]
   
2. 结果 * 2.0
   → 缩放到 [0, 2]
   
3. 结果 - 1.0
   → 平移到 [-1, 1]
   
4. 取负号（关键！）
   → 翻转 Y 轴方向

示例：屏幕高度 2340px
├─ 顶部：  -((0 / 2340) * 2.0 - 1.0) = -(-1.0) = 1.0 ✅
├─ 中心：  -((1170 / 2340) * 2.0 - 1.0) = -(0.0) = 0.0 ✅
└─ 底部：  -((2340 / 2340) * 2.0 - 1.0) = -(1.0) = -1.0 ✅

为什么需要负号？
Android 坐标系：Y↓（向下增长）
OpenGL 坐标系：Y↑（向上增长）

如果不取负号：
Android Y=0（顶部）→ OpenGL -1（底部）❌ 颠倒了
Android Y=height（底部）→ OpenGL 1（顶部）❌ 颠倒了

取负号后：
Android Y=0（顶部）→ OpenGL 1（顶部）✅ 正确
Android Y=height（底部）→ OpenGL -1（底部）✅ 正确

转换过程可视化：
Android：[0, 2340] (Y↓)
    0                 1170                2340
    ├───────────────────┼───────────────────┤
    ↓ 除以 height
[0, 1]
    0                  0.5                  1
    ├───────────────────┼───────────────────┤
    ↓ 乘以 2.0
[0, 2]
    0                  1.0                  2
    ├───────────────────┼───────────────────┤
    ↓ 减去 1.0
[-1, 1]
   -1                  0                    1
    ├───────────────────┼───────────────────┤
    ↓ 取负号（翻转）
NDC：[-1, 1] (Y↑)
    1                  0                   -1
    ├───────────────────┼───────────────────┤
```

### 💡 核心认知总结

#### 为什么需要转换？

```
OpenGL 的设计哲学：
├─ 归一化设备坐标（NDC）
├─ 与设备分辨率无关
├─ 统一的坐标系统（-1 到 1）
└─ 便于跨平台、跨设备

如果不转换：
├─ 1080×2340 设备上的坐标
├─ 在 2160×4680 设备上完全错误
└─ 需要为每个设备适配 ❌

使用 NDC 后：
├─ (-1, -1) 永远是左下角
├─ (1, 1) 永远是右上角
└─ 所有设备统一 ✅
```

#### Y 轴翻转的深层原因

```
历史原因：
├─ OpenGL 起源于 SGI 工作站
├─ 数学坐标系传统：Y 轴向上
└─ 与屏幕显示相反

Android/UI 系统：
├─ 基于屏幕扫描顺序
├─ 从上到下扫描
└─ Y 轴向下

因此必须翻转：
Android Y=0（顶部）→ OpenGL Y=1（顶部）
Android Y=max（底部）→ OpenGL Y=-1（底部）
```

#### 转换公式的数学本质

```
线性映射（Linear Mapping）：

输入域 [a, b] → 输出域 [c, d]

公式：
output = (input - a) / (b - a) * (d - c) + c

应用到 X 轴：
[0, width] → [-1, 1]

展开：
x_ndc = (x_screen - 0) / (width - 0) * (1 - (-1)) + (-1)
      = x_screen / width * 2 - 1

应用到 Y 轴（带翻转）：
[0, height] → [1, -1]  ← 注意：输出域翻转

展开：
y_ndc = (y_screen - 0) / (height - 0) * (-1 - 1) + 1
      = y_screen / height * (-2) + 1
      = -(y_screen / height * 2 - 1)  ← 与代码一致！
```

// 📍 GLEditRenderer.java 第 565-606 行
private void calculateImageTransform() {
    // 1. 计算宽高比
    float surfaceRatio = (float) mSurfaceWidth / mSurfaceHeight;
    float imageRatio = (float) mImageWidth / mImageHeight;
    
    float scaleX = 1.0f;
    float scaleY = 1.0f;
    
    // 2. 选择缩放策略
    if (imageRatio > surfaceRatio) {
        // 图片更宽：以宽度为准，高度缩小
        scaleY = surfaceRatio / imageRatio;
    } else {
        // 图片更高：以高度为准，宽度缩小
        scaleX = imageRatio / surfaceRatio;
    }
    
    // 3. 应用缩放
    Matrix.setIdentityM(mModelMatrix, 0);
    Matrix.scaleM(mModelMatrix, 0, scaleX, scaleY, 1.0f);
    
    // 4. 保存缩放因子（用于后续坐标补偿）
    mImageScaleX = scaleX;
    mImageScaleY = scaleY;
}
```

Matrix.multiplyMM(mFBOShapeMVPMatrix, 0, mProjectionMatrix, 0, tempMatrix, 0);

[0        0      1  0]   [0      0      1  0]

#### GPU 渲染管线（简化）

  ├─ 应用 MVP 矩阵变换

  ↓
② 裁剪阶段（Clipping）← 关键！
  ├─ GPU 硬件自动执行
  ├─ 裁剪超出 [-1, 1]³ 范围的图元
  └─ 输出：可见的图元
  ↓
③ 透视除法 → ④ 视口变换 → ⑤ 光栅化
  ↓
⑥ 片元着色器（Fragment Shader）
  ↓
⑦ 混合 → 帧缓冲（Framebuffer）

关键：
✅ 裁剪阶段完全由 GPU 硬件自动执行
✅ 不需要 CPU 参与
✅ 性能极高（专用硬件电路）
```

#### 裁剪空间（Clip Space）

```
顶点着色器输出的 gl_Position 在"裁剪空间"：

有效范围（正交投影，w=1.0）：
x ∈ [-1, 1]
y ∈ [-1, 1]
z ∈ [-1, 1]

GPU 自动裁剪规则：
├─ x < -1 或 x > 1 → 裁剪
├─ y < -1 或 y > 1 → 裁剪
└─ z < -1 或 z > 1 → 裁剪

超出范围的顶点：
├─ 完全不可见的图元 → 直接丢弃
├─ 部分可见的图元 → 裁剪后保留可见部分
└─ 完全在硬件层面处理，无需 CPU 干预
```

### 🔑 投影矩阵 vs 补偿矩阵（核心区别）

#### 投影矩阵（Projection Matrix）

```
标准功能：
├─ 定义裁剪空间（视锥体）
├─ 相机坐标 → 裁剪空间
└─ 标准范围：[-1, 1]³

我们的项目（2D 图片编辑）：
P = Identity（正交投影）

作用：
定义裁剪空间为 [-1, 1]³
GPU 会裁剪超出这个范围的顶点

这是 GPU 管线的标准步骤 ✅
```

---

#### 补偿矩阵（Compensation Matrix）

```
我们额外添加的：
C = scale(1.0, 3.852, 1.0)

作用：
❗ 不是定义裁剪空间
❗ 而是控制哪些顶点会超出裁剪空间

原理：
├─ 将屏幕 NDC 坐标映射到 FBO 空间
├─ 图片区域：映射到 [-1, 1]（可见）✅
└─ 黑边区域：映射到超出范围（不可见）❌

公式：
y_fbo = y_screen × 3.852

示例：
├─ 图片顶部：y = 0.26 → 0.26 × 3.852 = 1.0 ✅ 在范围内
├─ 图片中心：y = 0.0 → 0.0 × 3.852 = 0.0 ✅ 在范围内
├─ 黑边区域：y = 0.914 → 0.914 × 3.852 = 3.52 ❌ 超出范围

结果：
GPU 自动裁剪黑边区域的顶点 ✅

这是我们利用 GPU 裁剪机制的技巧 🎯
```

---

#### 完整 MVP 变换

```
标准 MVP：
MVP = Projection × View × Model

我们的 FBO Shape MVP（带补偿）：
MVP = Projection × View × Compensation × Model
    = P × V × C × M

具体值：
├─ P = Identity（正交投影，定义裁剪空间 [-1,1]³）
├─ V = Identity（无相机变换）
├─ C = scale(1.0, 3.852, 1.0)（补偿矩阵，关键！）
└─ M = Identity（无模型变换，简化）

最终：
MVP = scale(1.0, 3.852, 1.0)

关键认知：
✅ 投影矩阵 P：定义裁剪空间（标准功能）
✅ 补偿矩阵 C：控制顶点是否进入裁剪空间（技巧）
✅ GPU 裁剪：自动丢弃超出范围的顶点（硬件）
```

### 🎨 箭头顶点生成算法

#### generateVertices 详解

核心是利用 **方向向量** 和 **垂直向量** 构造图形顶点。

```java
// 📍 ArrowTool.java 第 137-214 行

@Override
protected float[] generateVertices(Shape shape) {
    float x1 = shape.startX;  // 起点 X
    float y1 = shape.startY;  // 起点 Y
    float x2 = shape.endX;    // 终点 X
    float y2 = shape.endY;    // 终点 Y
    float width = shape.strokeWidth;  // 线宽
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // 步骤 1：计算线段方向向量
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    float dx = x2 - x1;
    float dy = y2 - y1;
    float length = (float) Math.sqrt(dx * dx + dy * dy);
    
    // 如果线段太短，不绘制
    if (length < 0.001f) {
        return new float[0];
    }
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // 步骤 2：归一化方向向量
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    float dirX = dx / length;  // 单位方向向量 X
    float dirY = dy / length;  // 单位方向向量 Y
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // 步骤 3：计算垂直方向向量（用于线宽）
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    float perpX = -dirY;  // 垂直向量 X（逆时针旋转 90°）
    float perpY = dirX;   // 垂直向量 Y
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // 步骤 4：根据宽高比调整线宽（可选）
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    float adjustedWidth = width;
    if (Math.abs(perpY) > Math.abs(perpX)) {
        adjustedWidth = width * mAspectRatio;
    }
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // 步骤 5：计算线段矩形的四个顶点
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    float halfWidth = adjustedWidth / 2.0f;
    
    // 起点两侧
    float lineX1 = x1 + perpX * halfWidth;
    float lineY1 = y1 + perpY * halfWidth;
    float lineX2 = x1 - perpX * halfWidth;
    float lineY2 = y1 - perpY * halfWidth;
    
    // 箭头尾部（线段末端往回一点）
    float arrowLength = width * ARROW_LENGTH_FACTOR;  // 15 倍线宽
    float arrowTailX = x2 - dirX * arrowLength;
    float arrowTailY = y2 - dirY * arrowLength;
    
    // 箭头尾部两侧
    float lineX3 = arrowTailX + perpX * halfWidth;
    float lineY3 = arrowTailY + perpY * halfWidth;
    float lineX4 = arrowTailX - perpX * halfWidth;
    float lineY4 = arrowTailY - perpY * halfWidth;
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // 步骤 6：计算箭头三角形的顶点
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    float arrowWidth = width * ARROW_WIDTH_FACTOR;  // 8 倍线宽
    
    // 箭头左侧顶点
    float arrowX1 = arrowTailX + perpX * arrowWidth / 2.0f;
    float arrowY1 = arrowTailY + perpY * arrowWidth / 2.0f;
    
    // 箭头右侧顶点
    float arrowX2 = arrowTailX - perpX * arrowWidth / 2.0f;
    float arrowY2 = arrowTailY - perpY * arrowWidth / 2.0f;
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // 步骤 7：返回顶点数组（3个三角形 = 9个顶点）
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    return new float[]{
        // 线段矩形（2个三角形）
        lineX1, lineY1,     // 三角形 1 - 顶点 1
        lineX2, lineY2,     // 三角形 1 - 顶点 2
        lineX3, lineY3,     // 三角形 1 - 顶点 3
        
        lineX2, lineY2,     // 三角形 2 - 顶点 1
        lineX3, lineY3,     // 三角形 2 - 顶点 2
        lineX4, lineY4,     // 三角形 2 - 顶点 3
        
        // 箭头三角形
        arrowX1, arrowY1,   // 箭头左侧
        arrowX2, arrowY2,   // 箭头右侧
        x2, y2              // 箭头尖端
    };
}
```

##### 步骤 1-2：方向向量计算与归一化

```java
float dx = x2 - x1;
float dy = y2 - y1;
float length = (float) Math.sqrt(dx * dx + dy * dy);

float dirX = dx / length;  // 单位方向向量
float dirY = dy / length;
```

**目的**：得到从起点指向终点的**单位向量**

```
起点 (x1, y1) ──────────> 终点 (x2, y2)
        ↖
         方向向量 (dx, dy)
         长度 = √(dx² + dy²)
         
归一化后：(dirX, dirY)
长度 = 1（单位向量）
```

**为什么需要归一化？**
- 后续计算线宽时，需要沿垂直方向偏移**固定距离**（halfWidth）
- 单位向量 × 距离 = 精确的偏移量

---

##### 步骤 3：计算垂直向量（关键！）

```java
float perpX = -dirY;  // 垂直向量 X
float perpY = dirX;   // 垂直向量 Y
```

**几何原理**：将向量 **(x, y)** 逆时针旋转 90° 得到 **(-y, x)**

```
原向量：(dirX, dirY)  →
垂直向量：(-dirY, dirX) ↑

示例：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
如果方向向量是 (1, 0)（水平向右）
垂直向量就是 (0, 1)（垂直向上）

如果方向向量是 (0, 1)（垂直向上）
垂直向量就是 (-1, 0)（水平向左）
```

**作用**：
- 垂直向量用于确定**线宽方向**
- 沿着垂直方向偏移 `halfWidth`，形成线段的**两条边**

---

##### 步骤 4：宽高比补偿（可选）

```java
float adjustedWidth = width;
if (Math.abs(perpY) > Math.abs(perpX)) {
    adjustedWidth = width * mAspectRatio;
}
```

**目的**：补偿屏幕宽高比导致的视觉变形

**原理**：
```
垂直方向占主导（|perpY| > |perpX|）
→ 线段主要是竖直方向
→ 需要用 mAspectRatio 补偿 Y 轴的拉伸

例如：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
屏幕 1080×2340，图片 768×432
mAspectRatio = 432/768 = 0.5625

如果线段是竖直的：
adjustedWidth = width × 0.5625
```

**为什么只在 Y 方向占主导时补偿？**
- 如果线段是水平的，X 方向已经填满屏幕，不需要补偿
- 如果线段是竖直的，Y 方向有黑边，需要补偿以保持视觉线宽一致

##### 步骤 5：计算线段矩形的 4 个顶点

```java
float halfWidth = adjustedWidth / 2.0f;

// 起点两侧
float lineX1 = x1 + perpX * halfWidth;  // 起点左侧
float lineY1 = y1 + perpY * halfWidth;
float lineX2 = x1 - perpX * halfWidth;  // 起点右侧
float lineY2 = y1 - perpY * halfWidth;

// 箭头尾部（线段末端往回一点）
float arrowLength = width * ARROW_LENGTH_FACTOR;  // 15 倍线宽
float arrowTailX = x2 - dirX * arrowLength;
float arrowTailY = y2 - dirY * arrowLength;

// 箭头尾部两侧
float lineX3 = arrowTailX + perpX * halfWidth;  // 尾部左侧
float lineY3 = arrowTailY + perpY * halfWidth;
float lineX4 = arrowTailX - perpX * halfWidth;  // 尾部右侧
float lineY4 = arrowTailY - perpY * halfWidth;
```

**几何示意图**：

```
                箭头尾部
               /        \
      (lineX3, lineY3)  (lineX4, lineY4)
              │          │
              │  线段主体 │
              │          │
      (lineX1, lineY1)  (lineX2, lineY2)
               \        /
                起点 (x1, y1)

关键点：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. 起点两侧：沿垂直方向 ± halfWidth
2. 箭头尾部：从终点往回退 arrowLength
3. 尾部两侧：沿垂直方向 ± halfWidth
4. 形成矩形的 4 个顶点
```

**计算细节**：

```
起点左侧：
  (x1, y1) + perpVector × halfWidth
= (x1 + perpX * halfWidth, y1 + perpY * halfWidth)

起点右侧：
  (x1, y1) - perpVector × halfWidth
= (x1 - perpX * halfWidth, y1 - perpY * halfWidth)

箭头尾部位置：
  终点 - dirVector × arrowLength
= (x2 - dirX * arrowLength, y2 - dirY * arrowLength)

尾部左侧和右侧：
  同样沿垂直方向 ± halfWidth
```

float arrowX2 = arrowTailX - perpX * arrowWidth / 2.0f;

```

           |                  |

箭头三角形的 3 个顶点：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. 箭头尖端：(x2, y2)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
✅ arrowWidth = 8 × width（箭头宽度是线宽的 8 倍）

##### 🔑 关键要点总结

**1. 垂直向量计算**
```
向量 (x, y) 逆时针旋转 90° → (-y, x)
用途：确定线宽方向
```

**2. 线段矩形构造**
```
起点 + 垂直向量 × halfWidth → 左边缘
起点 - 垂直向量 × halfWidth → 右边缘
箭头尾部 = 终点 - 方向向量 × arrowLength
```

**3. 箭头三角形构造**
```
箭头宽度 = 8 × 线宽
箭头长度 = 15 × 线宽
3 个顶点：尖端 + 左侧 + 右侧
```

**4. 顶点组装**
```
3 个三角形 = 9 个顶点
矩形 = 2 个三角形（6 个顶点）
箭头 = 1 个三角形（3 个顶点）
```

**5. 坐标系统**
```
输入坐标：FBO NDC 坐标 [-1, 1]
输出顶点：直接用于 OpenGL 绘制
无需 MVP 变换（已在 NDC 空间）
```

##### 💡 设计亮点

```
1. 数学精确
   └─ 使用单位向量确保偏移距离准确

2. 宽高比补偿
   └─ 自动适配不同屏幕比例

3. 无缝连接
   └─ 线段和箭头完美衔接（共享箭头尾部）

4. 参数化设计
   └─ 箭头宽度和长度可调
      ├─ ARROW_WIDTH_FACTOR = 8.0
      └─ ARROW_LENGTH_FACTOR = 15.0

5. 顶点复用
   └─ 三角形 1 和 2 共享边，减少顶点数量
```

这是一个非常经典的 **2D 向量几何** 应用，核心是利用 **方向向量** 和 **垂直向量** 构造图形顶点。

### 💾 FloatBuffer 详解

#### 为什么需要 FloatBuffer？

```
CPU 内存 vs GPU 内存：

❌ 错误方式：
float[] vertices = {0.0f, 0.0f, 1.0f, 1.0f, ...};
// GPU 无法直接访问 Java 数组（在 JVM 堆中）

✅ 正确方式：
FloatBuffer buffer = ByteBuffer.allocateDirect(...)
    .order(ByteOrder.nativeOrder())  // 本地字节序
    .asFloatBuffer()
    .put(vertices);
// GPU 可以访问 Direct Buffer（在本地内存中）

关键：
├─ allocateDirect：在本地内存分配（不在 JVM 堆）
├─ nativeOrder：使用本地字节序（Big Endian / Little Endian）
└─ asFloatBuffer：转换为 Float 视图
```

#### ByteBuffer 创建流程

// 在本地内存（非 JVM 堆）分配 72 字节

FloatBuffer floatBuffer = byteBuffer.asFloatBuffer();
// 将字节视图转换为浮点数视图

// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
// 步骤 5：填充数据

floatBuffer.put(vertices);
// 将 Java 数组拷贝到 Buffer

// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

// GPU 从位置 0 开始读取

### 🎮 Shader 传参详解

#### Attribute vs Uniform

```
┌──────────────────────────────────────────────────┐
│  Attribute（顶点属性）                           │
├──────────────────────────────────────────────────┤
│  特点：                                          │
│  ├─ 每个顶点一个值                               │
│  ├─ 由 Vertex Shader 读取                        │
│  └─ 通过 glVertexAttribPointer 传递              │
│                                                  │
│  示例：aPosition                                 │
│  ├─ 顶点 1：(0.0, 0.0)                           │
│  ├─ 顶点 2：(1.0, 0.0)                           │
│  └─ 顶点 3：(0.5, 1.0)                           │
└──────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────┐
│  Uniform（统一变量）                             │
├──────────────────────────────────────────────────┤
│  特点：                                          │
│  ├─ 所有顶点共享一个值                           │
│  ├─ 由 Vertex / Fragment Shader 读取             │
│  └─ 通过 glUniform* 传递                         │
│                                                  │
│  示例：uMVPMatrix、uColor                        │
│  ├─ 所有顶点使用同一个 MVP 矩阵                  │
│  └─ 所有片元使用同一个颜色                       │
└──────────────────────────────────────────────────┘
```

#### 传参流程

```java
// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
// 步骤 1：获取 Shader 变量位置
// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
int program = mShaderManager.getProgram(ShaderManager.ShaderType.SHAPE);

// Attribute 位置
int positionHandle = GLES20.glGetAttribLocation(program, "aPosition");

// Uniform 位置
int colorHandle = GLES20.glGetUniformLocation(program, "uColor");
int mvpHandle = GLES20.glGetUniformLocation(program, "uMVPMatrix");

// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
// 步骤 2：传递 Attribute（顶点属性）
// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
// 2.1 启用 Attribute
GLES20.glEnableVertexAttribArray(positionHandle);

// 2.2 设置 Attribute 数据
GLES20.glVertexAttribPointer(
    positionHandle,      // Attribute 位置
    2,                   // 每个顶点的分量数（x, y）
    GLES20.GL_FLOAT,     // 数据类型
    false,               // 是否归一化
    0,                   // stride（0 = 紧密排列）
    vertexBuffer         // 数据源
);

// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
// 步骤 3：传递 Uniform（统一变量）
// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
// 3.1 传递颜色（vec4）
float[] color = {1.0f, 0.0f, 0.0f, 1.0f};  // 红色
GLES20.glUniform4fv(colorHandle, 1, color, 0);

// 3.2 传递 MVP 矩阵（mat4）
float[] mvpMatrix = {...};  // 4×4 矩阵（16个浮点数）
GLES20.glUniformMatrix4fv(mvpHandle, 1, false, mvpMatrix, 0);

// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
// 步骤 4：绘制
// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
GLES20.glDrawArrays(GLES20.GL_TRIANGLES, 0, vertexCount);

// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
// 步骤 5：禁用 Attribute
// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
GLES20.glDisableVertexAttribArray(positionHandle);

### ⚡ 渲染流程优化：批量渲染

#### 🔍 当前实现的性能瓶颈

**当前方式：每个箭头单独绘制**

```java
// ArrowTool.render()
for (Shape shape : mShapeList) {
    renderArrow(shape, mvpMatrix);  // 每个箭头调用一次 glDrawArrays
}
```

**每个箭头的渲染开销**：
```
1. generateVertices()         // CPU 计算顶点
2. 创建 FloatBuffer            // CPU 内存分配
3. glVertexAttribPointer()     // CPU→GPU 数据传输
4. glUniform4fv(color)         // CPU→GPU 参数传递
5. glDrawArrays(...)           // CPU→GPU 绘制调用 ← 主要瓶颈
   └─ CPU-GPU 通信开销（约 0.01-0.05ms）
```

**性能问题**：
```
场景：100 个箭头

当前实现：
├─ 100 次 glDrawArrays 调用
├─ 每次调用开销：0.02ms（CPU-GPU 通信）
├─ 累计浪费：100 × 0.02ms = 2ms
└─ 总耗时：50ms（计算）+ 2ms（绘制）= 52ms ❌

关键认知：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
CPU-GPU 通信的每次调用都有固定开销
多次小调用 > 一次大调用（批量渲染）
```

#### ✅ 优化方案 1：批量渲染（推荐）

**核心思想：合并所有顶点，一次性绘制**

```java
public void renderBatch(List<Shape> shapes, float[] mvpMatrix) {
    if (shapes.isEmpty()) return;
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // 步骤 1：合并所有箭头的顶点
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    List<Float> allVertices = new ArrayList<>();
    for (Shape shape : shapes) {
        float[] vertices = generateVertices(shape);
        for (float v : vertices) {
            allVertices.add(v);
        }
    }
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // 步骤 2：创建大的 FloatBuffer
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    FloatBuffer buffer = ByteBuffer.allocateDirect(allVertices.size() * 4)
            .order(ByteOrder.nativeOrder())
            .asFloatBuffer();
    for (float v : allVertices) {
        buffer.put(v);
    }
    buffer.position(0);
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // 步骤 3：设置顶点数据
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    GLES20.glEnableVertexAttribArray(mPositionHandle);
    GLES20.glVertexAttribPointer(mPositionHandle, 2, GLES20.GL_FLOAT, 
                                  false, 0, buffer);
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // 步骤 4：设置颜色和 MVP（假设所有箭头颜色相同）
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    GLES20.glUniform4fv(mColorHandle, 1, shapes.get(0).color, 0);
    GLES20.glUniformMatrix4fv(mMVPMatrixHandle, 1, false, mvpMatrix, 0);
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // 步骤 5：一次性绘制所有箭头！✅
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    GLES20.glDrawArrays(GLES20.GL_TRIANGLES, 0, allVertices.size() / 2);
    
    GLES20.glDisableVertexAttribArray(mPositionHandle);
}
```

**问题：所有箭头必须共享 Uniform**

```java
public void renderAllArrows(List<Shape> shapes, float[] mvpMatrix) {
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // 步骤 1：按颜色分组
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    Map<Integer, List<Shape>> groupedByColor = new HashMap<>();
    for (Shape shape : shapes) {
        int colorKey = Arrays.hashCode(shape.color);
        groupedByColor.computeIfAbsent(colorKey, k -> new ArrayList<>())
                      .add(shape);
    }
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // 步骤 2：每种颜色批量渲染一次
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    for (Map.Entry<Integer, List<Shape>> entry : groupedByColor.entrySet()) {
        List<Shape> sameColorShapes = entry.getValue();
        
        // 合并顶点
        List<Float> vertices = new ArrayList<>();
        for (Shape shape : sameColorShapes) {
            float[] v = generateVertices(shape);
            for (float f : v) vertices.add(f);
        }
        
        // 创建 Buffer
        FloatBuffer buffer = createFloatBuffer(vertices);
        
        // 设置顶点
        GLES20.glEnableVertexAttribArray(mPositionHandle);
        GLES20.glVertexAttribPointer(mPositionHandle, 2, 
                                      GLES20.GL_FLOAT, false, 0, buffer);
        
        // 设置颜色（每种颜色一次）
        GLES20.glUniform4fv(mColorHandle, 1, sameColorShapes.get(0).color, 0);
        GLES20.glUniformMatrix4fv(mMVPMatrixHandle, 1, false, mvpMatrix, 0);
        
        // 一次性绘制所有相同颜色的箭头
        GLES20.glDrawArrays(GLES20.GL_TRIANGLES, 0, vertices.size() / 2);
        
        GLES20.glDisableVertexAttribArray(mPositionHandle);
    }
}

#### 🚀 终极优化方案：顶点缓存 + VBO

**核心思想：缓存已固化箭头的顶点，避免重复计算**

```java
class ArrowTool {
    // 顶点缓存
    private FloatBuffer mSettledVerticesBuffer = null;
    private int mSettledVertexCount = 0;
    private Map<Integer, ColorBatch> mColorBatches = new HashMap<>();
    
    // 颜色批次
    static class ColorBatch {
        float[] color;
        FloatBuffer vertexBuffer;
        int vertexCount;
    }
    
    // 固化时更新缓存
    private void commitToSettledLayer() {
        // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        // 步骤 1：按颜色分组并生成顶点
        // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        Map<Integer, List<Float>> groupedVertices = new HashMap<>();
        Map<Integer, float[]> colorMap = new HashMap<>();
        
        for (Shape shape : mShapeList) {
            int colorKey = Arrays.hashCode(shape.color);
            
            // 生成顶点
            float[] vertices = generateVertices(shape);
            List<Float> list = groupedVertices.computeIfAbsent(
                colorKey, k -> new ArrayList<>()
            );
            for (float v : vertices) list.add(v);
            
            // 保存颜色
            colorMap.put(colorKey, shape.color);
        }
        
        // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        // 步骤 2：创建 ColorBatch 缓存
        // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        mColorBatches.clear();
        for (Map.Entry<Integer, List<Float>> entry : groupedVertices.entrySet()) {
            int colorKey = entry.getKey();
            List<Float> vertices = entry.getValue();
            
            ColorBatch batch = new ColorBatch();
            batch.color = colorMap.get(colorKey);
            batch.vertexBuffer = createFloatBuffer(vertices);
            batch.vertexCount = vertices.size() / 2;
            
            mColorBatches.put(colorKey, batch);
        }
        
        // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        // 步骤 3：GPU 渲染到 FBO_A
        // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        glBindFramebuffer(GL_FRAMEBUFFER, fboA.fboId);
        glClear(GL_COLOR_BUFFER_BIT);
        drawBaseImage();
        renderFromCache();  // 使用缓存渲染
        glBindFramebuffer(GL_FRAMEBUFFER, 0);
    }
    
    // 使用缓存渲染
    private void renderFromCache() {
        GLES20.glEnableVertexAttribArray(mPositionHandle);
        
        for (ColorBatch batch : mColorBatches.values()) {
            // 设置顶点
            GLES20.glVertexAttribPointer(mPositionHandle, 2, 
                                          GLES20.GL_FLOAT, false, 0, 
                                          batch.vertexBuffer);
            
            // 设置颜色
            GLES20.glUniform4fv(mColorHandle, 1, batch.color, 0);
            GLES20.glUniformMatrix4fv(mMVPMatrixHandle, 1, false, 
                                       mFBOShapeMVPMatrix, 0);
            
            // 绘制
            GLES20.glDrawArrays(GLES20.GL_TRIANGLES, 0, batch.vertexCount);
        }
        
        GLES20.glDisableVertexAttribArray(mPositionHandle);
    }
    
    // Undo 时直接使用缓存

        updateCache();
        renderFromCache();
        
        glBindFramebuffer(GL_FRAMEBUFFER, 0);
    }

    }
}

#### 1. commitCurrentTool（固化当前工具）

```java
// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
// GLEditView.java 第 425-468 行
// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

/**
 * 固化当前工具的内容到底部纹理（异步）
 * 用于工具切换时保留之前的绘制内容
 */
public void commitCurrentTool() {
    if (mCurrentTool == null) {
        return;
    }
    
    if (!(mCurrentTool instanceof BaseDrawingTool)) {
        return;
    }
    
    BaseDrawingTool drawingTool = (BaseDrawingTool) mCurrentTool;
    
    if (drawingTool.getShapeList() == null || 
        drawingTool.getShapeList().isEmpty()) {
        //Log.d(TAG, "commitCurrentTool: No shapes to commit");
        return;
    }
    
    Log.d(TAG, "Committing current tool to texture (async)");
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // 异步执行，不阻塞主线程
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    queueEvent(new Runnable() {
        @Override
        public void run() {
            try {
                // 在 GL 线程中执行固化
                mRenderer.commitToTexture();
                Log.d(TAG, "commitToTexture completed");
                
                // 固化完成后清空当前工具（回到主线程）
                post(new Runnable() {
                    @Override
                    public void run() {
                        if (mCurrentTool instanceof BaseDrawingTool) {
                            ((BaseDrawingTool) mCurrentTool).reset();
                        }
                        requestRender();
                    }
                });
            } catch (Exception e) {
                Log.e(TAG, "Failed to commit to texture", e);
            }
        }
    });
}

#### 2. commitToTexture（GPU 端固化）

```java
// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
// GLEditRenderer.java 第 980-1091 行
// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

/**
 * 将当前所有内容固化为底部纹理（优化版：GPU 直接拷贝）
 * 用于在工具切换时保留所有已绘制的内容
 * 
 * 注意：此方法必须在 GL 线程中调用
 */
public void commitToTexture() {
    Log.d(TAG, "========== commitToTexture START ==========");
    
    if (mRenderFBO == null || !mRenderFBO.isValid()) {
        Log.w(TAG, "FBO not available, cannot commit");
        return;
    }
    
    Log.d(TAG, "Source: FBO (Size=" + mRenderFBO.width + "x" + mRenderFBO.height + ")");
    Log.d(TAG, "Target: Base Texture (Size=" + mImageWidth + "x" + mImageHeight + ")");
    
    try {
        long startTime = System.currentTimeMillis();
        
        // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        // 步骤 1：绑定 FBO 读取像素
        // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        mFBOManager.bindFBO(mRenderFBO);
        Log.d(TAG, "FBO bound for reading");
        
        // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        // 步骤 2：读取像素到 ByteBuffer
        // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        int pixelCount = mImageWidth * mImageHeight;
        ByteBuffer pixelBuffer = ByteBuffer.allocateDirect(pixelCount * 4);
        pixelBuffer.order(ByteOrder.nativeOrder());
        
        GLES20.glReadPixels(
            0, 0,                           // 起始位置
            mImageWidth, mImageHeight,      // 尺寸
            GLES20.GL_RGBA,                 // 格式
            GLES20.GL_UNSIGNED_BYTE,        // 类型
            pixelBuffer
        );
        
        int readError = GLES20.glGetError();
        if (readError != GLES20.GL_NO_ERROR) {
            Log.e(TAG, "❌ glReadPixels error: " + readError);
            mFBOManager.unbindFBO(mSurfaceWidth, mSurfaceHeight);
            return;
        }
        Log.d(TAG, "✅ Pixels read successfully (" + (pixelCount * 4) + " bytes)");
        
        // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        // 步骤 3：Y 轴翻转（FBO 坐标系 → Bitmap 坐标系）
        // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        ByteBuffer flippedBuffer = ByteBuffer.allocateDirect(pixelCount * 4);
        flippedBuffer.order(ByteOrder.nativeOrder());
        
        int rowBytes = mImageWidth * 4;
        byte[] rowData = new byte[rowBytes];
        
        for (int y = 0; y < mImageHeight; y++) {
            // 从底部读取
            pixelBuffer.position(y * rowBytes);
            pixelBuffer.get(rowData);
            
            // 写入到顶部
            flippedBuffer.position((mImageHeight - 1 - y) * rowBytes);
            flippedBuffer.put(rowData);
        }
        
        Log.d(TAG, "✅ Y-axis flipped");
        
        // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        // 步骤 4：更新底图纹理
        // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        GLES20.glBindTexture(GLES20.GL_TEXTURE_2D, mBaseTextureId);
        
        flippedBuffer.position(0);
        GLES20.glTexImage2D(
            GLES20.GL_TEXTURE_2D,
            0,                              // mipmap level
            GLES20.GL_RGBA,                 // 内部格式
            mImageWidth, mImageHeight,      // 尺寸
            0,                              // border
            GLES20.GL_RGBA,                 // 格式
            GLES20.GL_UNSIGNED_BYTE,        // 类型
            flippedBuffer                   // 数据
        );
        
        int texError = GLES20.glGetError();
        if (texError != GLES20.GL_NO_ERROR) {
            Log.e(TAG, "❌ glTexImage2D error: " + texError);
        } else {
            Log.d(TAG, "✅ Base texture updated");
        }

 *

 * @param overlayBitmap 覆盖图片（上层）
 * @return 合并后的 Bitmap
 */
private Bitmap mergeBitmaps(Bitmap baseBitmap, Bitmap overlayBitmap) {
    if (baseBitmap == null) {
        Log.e(TAG, "Base bitmap is null");
        return overlayBitmap != null ? 
               overlayBitmap.copy(Bitmap.Config.ARGB_8888, true) : null;
    }
    
    if (overlayBitmap == null) {
        Log.w(TAG, "Overlay bitmap is null, returning base bitmap");
        return baseBitmap.copy(Bitmap.Config.ARGB_8888, true);
    }
    
    try {
        // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

        // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        Bitmap result = baseBitmap.copy(Bitmap.Config.ARGB_8888, true);
        
        // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        // 步骤 2：创建画布并绘制覆盖层
        // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        Canvas canvas = new Canvas(result);
        Paint paint = new Paint(Paint.ANTI_ALIAS_FLAG);
        canvas.drawBitmap(overlayBitmap, 0, 0, paint);
        
        Log.d(TAG, "Bitmaps merged successfully: " + 
              result.getWidth() + "x" + result.getHeight());
        return result;
    } catch (Exception e) {
        Log.e(TAG, "Failed to merge bitmaps: " + e.getMessage(), e);
        return null;
    }
}

### 🚀 优化建议：跳过冗余的 commitCurrentTool

#### 问题发现

```
当前实现的冗余：
在 OpenGL → Canvas 切换时，执行了两次 FBO 读取

步骤 1：commitCurrentTool()
├─ glReadPixels（FBO → ByteBuffer）← 第一次读取
├─ Y 轴翻转
└─ glTexImage2D（更新底图纹理）

步骤 2：captureResult()
├─ glReadPixels（FBO → ByteBuffer）← 第二次读取（重复！）
├─ Y 轴翻转
└─ Bitmap.copyPixelsFromBuffer()

步骤 3：clearAll()
└─ 清空 OpenGL（步骤 1 固化的底图纹理被丢弃）

问题：
❌ 两次 glReadPixels（重复读取 1.3MB 数据）
❌ 两次 Y 轴翻转（重复计算）
❌ 固化到底图纹理后被 clearAll() 丢弃（白做了）

```java
// GLArrowFragment.java

public void applyArrowImage(final SaveCallback callback) {
    Log.d(TAG, "applyArrowImage: Starting to capture arrow drawing result");
    
    if (mGLEditView == null) {
        Log.e(TAG, "applyArrowImage: GLEditView is null");
        if (callback != null) {
            callback.onSaveComplete(false);
        }
        return;
    }
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // 捕获 OpenGL 渲染结果（底图 + 所有箭头）
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    mGLEditView.captureResult(new GLEditView.CaptureResultCallback() {
        @Override
        public void onCaptureSuccess(Bitmap bitmap) {
            Log.d(TAG, "applyArrowImage: Capture success - " + 
                    bitmap.getWidth() + "x" + bitmap.getHeight());
            
            // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
            // 更新 mainBitmap（替换为 OpenGL 渲染结果）
            // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
            activity.changeMainBitmap(bitmap);
            
            Log.d(TAG, "applyArrowImage: mainBitmap updated successfully");
            
            // 回调通知完成
            if (callback != null) {
                callback.onSaveComplete(true);
            }
        }
        
        @Override
        public void onCaptureError(String error) {
            Log.e(TAG, "applyArrowImage: Capture failed - " + error);
            
            // 静默失败
            if (callback != null) {
                callback.onSaveComplete(false);
            }
        }
    });
}
```

**核心逻辑：**

```
1. 调用 mGLEditView.captureResult()
   ├─ GL 线程：queueEvent()
   ├─ 调用 mRenderer.captureResult()
   ├─ 调用 mFBOManager.readBitmapFromFBO(mRenderFBO)
   │  ├─ glBindFramebuffer(FBO)
   │  ├─ glReadPixels() → ByteBuffer
   │  ├─ Y 轴翻转（OpenGL → Android 坐标系）
   │  └─ Bitmap.copyPixelsFromBuffer()
   └─ UI 线程：post() → callback.onCaptureSuccess(bitmap)

2. changeMainBitmap(bitmap)
   ├─ 回收旧的 mainBitmap
   ├─ mainBitmap = bitmap（新的 OpenGL 渲染结果）
   ├─ mainImage.setImageBitmap(mainBitmap)
   └─ increaseOpTimes()

3. callback.onSaveComplete(true)
   └─ 触发 doSaveImage()
```

private final class SaveImageTask extends AsyncTask<Bitmap, Void, Boolean> {
    private Dialog dialog;
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // 预执行：显示加载对话框（UI 线程）
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    @Override
    protected void onPreExecute() {
        super.onPreExecute();
        this.dialog = EditImageActivity.this.getLoadingDialog(
                EditImageActivity.this.mContext, 
                R.string.saving_image,  // "正在保存..."
                false);
        this.dialog.show();
    }
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // 后台执行：保存 Bitmap 到文件（后台线程）
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    @Override
    protected Boolean doInBackground(Bitmap... params) {
        return TextUtils.isEmpty(EditImageActivity.this.saveFilePath) 
            ? false 
            : BitmapUtils.saveBitmap(params[0], EditImageActivity.this.saveFilePath);
    }
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // 后执行：处理保存结果（UI 线程）
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    @Override
    protected void onPostExecute(Boolean result) {
        super.onPostExecute(result);
        this.dialog.dismiss();
        
        if (result) {
            // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
            // 保存成功
            // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
            EditImageActivity.this.resetOpTimes();  // isBeenSaved = true
            
            try {
                EditImageActivity.this.previewWidth = EditImageActivity.this.mainBitmap.getWidth();
                EditImageActivity.this.previewHeight = EditImageActivity.this.mainBitmap.getHeight();
                EditImageActivity.this.onSaveTaskDone(true);
            } catch (Exception e) {
                e.printStackTrace();
            }
        } else {
            // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
            // 保存失败
            // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
            Toast toast = Toast.makeText(mContext, R.string.save_error, Toast.LENGTH_SHORT);
            toast.setText(R.string.save_error);
            toast.show();
        }
    }
    
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // 取消处理：关闭对话框（避免内存泄漏）
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

#### 3️⃣ `BitmapUtils.saveBitmap()` - 核心保存方法

```java
// BitmapUtils.java

public static boolean saveBitmap(Bitmap bm, String filePath) {
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    // Step 1: 删除旧文件（如果存在）
    // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    File f = new File(filePath);
    if (f.exists()) {
        f.delete();
    }
    
    try {
        // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        // Step 2: 创建文件输出流
        // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        FileOutputStream out = new FileOutputStream(f);
        
        // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        // Step 3: 压缩并写入文件
        // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        // 格式：PNG（无损压缩，支持透明度）
        // 质量：90（平衡质量和文件大小）
        bm.compress(CompressFormat.PNG, 90, out);
        
        // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        // Step 4: 刷新并关闭流
        // ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
        out.flush();
        out.close();
        
        return true;
    } catch (FileNotFoundException e) {
        e.printStackTrace();
        return false;
    } catch (IOException e) {
        e.printStackTrace();
        return false;
    }
}
```

**关键参数：**

```
格式选择：CompressFormat.PNG
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
PNG：
✅ 无损压缩
✅ 支持透明度（ALPHA 通道）
✅ 适合图形、截图、带透明度的图像
❌ 文件较大（相比 JPEG）

JPEG：
✅ 有损压缩
✅ 文件较小
✅ 适合照片、复杂图像
❌ 不支持透明度
❌ 会丢失细节

质量参数：90
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
0-100：
├─ 0：最低质量，最小文件
├─ 50：中等质量
├─ 90：高质量（推荐）✅
└─ 100：最高质量（文件巨大，与 90 视觉差异极小）

注意：
对于 PNG，quality 参数实际上影响的是压缩算法的复杂度，
而不是图像质量（PNG 总是无损的）。
90 是一个平衡点，兼顾压缩速度和文件大小。
```

✅ UI 操作必须在 UI 线程（post）

✅ 回调通知在 UI 线程（AsyncTask.onPostExecute）

### ⚠️ 错误处理

```java
// 1. GLEditView 为空
if (mGLEditView == null) {
    Log.e(TAG, "applyArrowImage: GLEditView is null");
    if (callback != null) {
        callback.onSaveComplete(false);
    }
    return;
}

// 2. FBO 读取失败
@Override
public void onCaptureError(String error) {
    Log.e(TAG, "applyArrowImage: Capture failed - " + error);
    if (callback != null) {
        callback.onSaveComplete(false);
    }
}

// 3. 保存文件失败
protected Boolean doInBackground(Bitmap... params) {
    return TextUtils.isEmpty(EditImageActivity.this.saveFilePath) 
        ? false  // 文件路径为空
        : BitmapUtils.saveBitmap(params[0], EditImageActivity.this.saveFilePath);
}

// 4. AsyncTask 被取消
@Override
protected void onCancelled() {
    super.onCancelled();
    if (dialog != null && dialog.isShowing()) {
        if (!EditImageActivity.this.isFinishing() && !EditImageActivity.this.isDestroyed()) {
            dialog.dismiss();  // 防止 Activity 销毁后操作对话框
        }
    }
}

// 5. 文件写入异常
try {
    FileOutputStream out = new FileOutputStream(f);
    bm.compress(CompressFormat.PNG, 90, out);
    out.flush();
    out.close();
    return true;
} catch (FileNotFoundException e) {
    e.printStackTrace();
    return false;
} catch (IOException e) {
    e.printStackTrace();
    return false;
}
