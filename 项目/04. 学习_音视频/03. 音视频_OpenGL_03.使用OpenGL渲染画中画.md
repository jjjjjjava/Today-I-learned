## 03.原理机制

### 3.1 需求分析

核心需求：实现视频画中画效果

- 类似下面的

  - ```
    ┌─────────────────────────────────────┐
    │                                     │
    │   📹 底层视频（全屏播放）            │
    │                                     │
    │         ┌──────────┐                │
    │         │  📹 上层  │ ← 半透明       │
    │         │  小视频  │ ← 可移动       │
    │         └──────────┘ ← 可缩放       │
    │                                     │
    └─────────────────────────────────────┘
    ```

拆解一下需求

- 阶段一：渲染多个视频
  - 预期效果：同时播放2+个视频
  - 实现思路：多SurfaceTexture接收多个解码器数据 + 多Drawer进行在同一个Surface上进行多级编辑
- 阶段二：半透明混合
  - 预期效果：透过上层看到下层。我们上面的编辑会覆盖下层编辑的结果，我们现在让其也显示出来。
  - 实现思路：着色器传递alpha + Blend模式，就是色彩混合
- 阶段三：交互编辑
  - 预期效果：拖动、缩放视频
  - 实现思路：矩阵变换（平移 /　缩放）

第一步：SimpleRender改造

- 改造前，只支持一个drawer

  - ```
    class SimpleRender(private val mDrawer: IDrawer): GLSurfaceView.Renderer {
        
        override fun onSurfaceCreated(gl: GL10?, config: EGLConfig?) {
            GLES20.glClearColor(0f, 0f, 0f, 0f)
            GLES20.glClear(GLES20.GL_COLOR_BUFFER_BIT)
            mDrawer.setTextureID(OpenGLTools.createTextureIds(1)[0])
        }
    
        override fun onSurfaceChanged(gl: GL10?, width: Int, height: Int) {
            GLES20.glViewport(0, 0, width, height)
            mDrawer.setWorldSize(width, height)
        }
    
        override fun onDrawFrame(gl: GL10?) {
            mDrawer.draw()  // 只能绘制一个
        }
    }
    ```

- 改造后：支持多Drawer列表

  - ```
    class SimpleRender: GLSurfaceView.Renderer {
    
        // 🔑 关键改造1：使用列表管理多个Drawer
        private val drawers = mutableListOf<IDrawer>()
    
        override fun onSurfaceCreated(gl: GL10?, config: EGLConfig?) {
            GLES20.glClearColor(0f, 0f, 0f, 0f)
            
            // 🔑 关键改造2：开启混合模式（实现半透明的前提）
            GLES20.glEnable(GLES20.GL_BLEND)
            GLES20.glBlendFunc(GLES20.GL_SRC_ALPHA, GLES20.GL_ONE_MINUS_SRC_ALPHA)
            
            // 🔑 关键改造3：批量创建纹理ID
            val textureIds = OpenGLTools.createTextureIds(drawers.size)
            for ((idx, drawer) in drawers.withIndex()) {
                drawer.setTextureID(textureIds[idx])
            }
        }
    
        override fun onSurfaceChanged(gl: GL10?, width: Int, height: Int) {
            GLES20.glViewport(0, 0, width, height)
            // 🔑 关键改造4：通知所有Drawer
            for (drawer in drawers) {
                drawer.setWorldSize(width, height)
            }
        }
    
        override fun onDrawFrame(gl: GL10?) {
            // 🔑 关键改造5：每帧清屏（避免残留）
            GLES20.glClear(GLES20.GL_COLOR_BUFFER_BIT or GLES20.GL_DEPTH_BUFFER_BIT)
            // 🔑 关键改造6：遍历绘制所有Drawer
            drawers.forEach { it.draw() }
        }
    
        // 🔑 关键改造7：提供动态添加能力
        fun addDrawer(drawer: IDrawer) {
            drawers.add(drawer)
        }
    }
    ```

- 我们来看看核心点：

- 要点1：OpenGL混合模式 - 核心原理

  - 这是代码

  - ```
    GLES20.glEnable(GLES20.GL_BLEND)  // 开启混合
    GLES20.glBlendFunc(GLES20.GL_SRC_ALPHA, GLES20.GL_ONE_MINUS_SRC_ALPHA)
    ```

  - 这是混合公式 `finalColor = srcColor * srcFactor + dstColor * dstFactor`

    - `srcColor`：当前要绘制上层视频的颜色
    - `dstColor`：帧缓冲中已有底层视频的颜色
    - `GL_SRC_ALPHA`：srcFactor = srcColor.alpha
    - `GL_ONE_MINUS_SRC_ALPHA`：dstFactor = 1 - srcColor.alpha

  - 来看一下

  - ```
    假设：
    - 底层视频颜色：dstColor = (1.0, 0.0, 0.0, 1.0)  // 纯红色
    - 上层视频颜色：srcColor = (0.0, 0.0, 1.0, 0.5)  // 蓝色，alpha=0.5
    
    计算过程：
    srcFactor = srcAlpha = 0.5
    dstFactor = 1 - srcAlpha = 0.5
    
    finalColor.r = 0.0 * 0.5 + 1.0 * 0.5 = 0.5
    finalColor.g = 0.0 * 0.5 + 0.0 * 0.5 = 0.0
    finalColor.b = 1.0 * 0.5 + 0.0 * 0.5 = 0.5
    finalColor.a = 0.5 * 0.5 + 1.0 * 0.5 = 0.75
    
    最终颜色：(0.5, 0.0, 0.5, 0.75)  // 紫色（红+蓝混合）
    ```

  - 如果不开启，那么即使alpha=0.5，上层视频仍完全不透明，看不到底层

第二步：VideoDrawer中实现半透明

- 步骤一：修改着色器代码

  - 顶点着色器

  - ```
    attribute vec4 aPosition;      // 顶点坐标（Java传入）
    attribute vec2 aCoordinate;    // 纹理坐标（Java传入）
    attribute float alpha;         // 🆕 新增：接收alpha值（Java传入）
    
    uniform mat4 uMatrix;          // 变换矩阵（Java传入）
    
    varying vec2 vCoordinate;      // 传给片元着色器
    varying float inAlpha;         // 🆕 新增：传递alpha给片元着色器
    
    void main() {
        gl_Position = uMatrix * aPosition;
        vCoordinate = aCoordinate;
        inAlpha = alpha;           // 🔑 关键：将alpha传递出去
    }
    ```

  - 片元着色器

  - ```
    #extension GL_OES_EGL_image_external : require
    precision mediump float;
    
    varying vec2 vCoordinate;      // 从顶点着色器接收纹理坐标
    varying float inAlpha;         // 🆕 从顶点着色器接收alpha值
    
    uniform samplerExternalOES uTexture;  // 视频纹理
    
    void main() {
        // 从纹理中采样颜色
        vec4 color = texture2D(uTexture, vCoordinate);
        
        // 🔑 关键：使用inAlpha修改颜色的alpha通道
        gl_FragColor = vec4(color.r, color.g, color.b, inAlpha);
    }
    ```

- 步骤二：传递alpha值

  - ```
    private fun doDraw() {
        // 启用顶点属性数组
        GLES20.glEnableVertexAttribArray(mVertexPosHandler)
        GLES20.glEnableVertexAttribArray(mTexturePosHandler)
        
        // 传递变换矩阵
        GLES20.glUniformMatrix4fv(mVertexMatrixHandler, 1, false, mMatrix, 0)
        
        // 传递顶点坐标和纹理坐标（数组）
        GLES20.glVertexAttribPointer(mVertexPosHandler, 2, GLES20.GL_FLOAT, false, 0, mVertexBuffer)
        GLES20.glVertexAttribPointer(mTexturePosHandler, 2, GLES20.GL_FLOAT, false, 0, mTextureBuffer)
        
        // 🔑 关键：传递alpha值到顶点着色器（单个float）
        GLES20.glVertexAttrib1f(mAlphaHandler, mAlpha)
        
        // 执行绘制（4个顶点，TRIANGLE_STRIP模式）
        GLES20.glDrawArrays(GLES20.GL_TRIANGLE_STRIP, 0, 4)
    }
    ```

  - 注意：这里有两种传值方式

  - ```
    // 方式1：传递数组数据（如顶点坐标）
    glVertexAttribPointer(
        index,    // 变量位置
        size,     // 每个顶点的分量数（2=xy, 3=xyz）
        type,     // 数据类型（GL_FLOAT）
        normalized, // 是否归一化
        stride,   // 步长
        buffer    // 数据缓冲
    )
    
    // 方式2：传递常量值（如alpha）
    glVertexAttrib1f(
        index,    // 变量位置
        value     // float值
    )
    ```

  - Alpha是常量，对所有顶点都一样，因此不需要为每个顶点单独指定，直接传一个值即可

- 步骤三：Activity中使用

  - ```
    class MultiOpenGLPlayerActivity: AppCompatActivity() {
        private val path = "/sdcard/mvtest.mp4"
        private val path2 = "/sdcard/mvtest_2.mp4"
        
        private val render = SimpleRender()
        private val threadPool = Executors.newFixedThreadPool(10)
        
        override fun onCreate(savedInstanceState: Bundle?) {
            super.onCreate(savedInstanceState)
            setContentView(R.layout.activity_opengl_player)
            
            initFirstVideo()   // 底层视频
            initSecondVideo()  // 上层视频
            initRender()
        }
        
        // 底层视频：全屏，不透明，带音频
        private fun initFirstVideo() {
            val drawer = VideoDrawer()
            drawer.setVideoSize(1920, 1080)
            drawer.getSurfaceTexture {
                initPlayer(path, Surface(it), true)
            }
            render.addDrawer(drawer)  // 🔑 先添加，在底层
        }
        
        // 上层视频：全屏，半透明，无音频
        private fun initSecondVideo() {
            val drawer = VideoDrawer()
            drawer.setAlpha(0.5f)  // 🔑 关键：设置50%透明度
            drawer.setVideoSize(1920, 1080)
            drawer.getSurfaceTexture {
                initPlayer(path2, Surface(it), false)
            }
            render.addDrawer(drawer)  // 🔑 后添加，在上层
        }
        
        private fun initPlayer(path: String, sf: Surface, withSound: Boolean) {
            val videoDecoder = VideoDecoder(path, null, sf)
            threadPool.execute(videoDecoder)
            videoDecoder.goOn()
            
            if (withSound) {
                val audioDecoder = AudioDecoder(path)
                threadPool.execute(audioDecoder)
                audioDecoder.goOn()
            }
        }
        
        private fun initRender() {
            gl_surface.setEGLContextClientVersion(2)
            gl_surface.setRenderer(render)
        }
    }
    ```

  - 那么他们的层叠关系是这样的

  - ```
    addDrawer顺序 → 绘制顺序 → 层叠关系
    
    drawer1（先添加）→ 先绘制 → 在底层
    drawer2（后添加）→ 后绘制 → 在上层（叠加在drawer1上）
    ```

### 3.4 上层视频平移

当前状态：两个视频完全重叠，都是全屏显示（虽然经过正交投影矫正了比例）  ，我们期望可以让上层视频可以通过触摸拖动到任意位置

- 这是我们期望的效果

  - ```
    初始状态：                拖动后：
    ┌────────────────┐      ┌────────────────┐
    │  黑边区域       │      │  黑边区域       │
    ├────────────────┤      ├────────────────┤
    │  📹 视频1       │      │  📹 视频1       │
    │  📹 视频2       │  →   │                │
    │  (完全重叠)     │      │        📹 视频2 │
    ├────────────────┤      ├────────────────┤
    │  黑边区域       │      │  黑边区域       │
    └────────────────┘      └────────────────┘
    ```

好，我们的实现是通过平移矩阵实现的。

第一步：平移矩阵原理

- 看看标准的平移矩阵

  - 前3列是单位矩阵（不改变方向和缩放），第4列存储平移距

  - ```
    平移矩阵：
    ┌              ┐
    │ 1  0  0  Tx  │  ← Tx: X方向平移距离
    │ 0  1  0  Ty  │  ← Ty: Y方向平移距离
    │ 0  0  1  Tz  │  ← Tz: Z方向平移距离
    │ 0  0  0  1   │
    └              ┘
    ```

- 平移矩阵乘法运算

  - ```
    原始顶点        平移矩阵           结果
    ┌   ┐          ┌              ┐   ┌        ┐
    │ x │          │ 1  0  0  Tx  │   │ x + Tx │
    │ y │    ×     │ 0  1  0  Ty  │ = │ y + Ty │
    │ z │          │ 0  0  1  Tz  │   │ z + Tz │
    │ 1 │          │ 0  0  0  1   │   │   1    │
    └   ┘          └              ┘   └        ┘
    
    计算过程（你学过的矩阵乘法）：
    第1行：x' = 1*x + 0*y + 0*z + Tx*1 = x + Tx
    第2行：y' = 0*x + 1*y + 0*z + Ty*1 = y + Ty
    第3行：z' = 0*x + 0*y + 1*z + Tz*1 = z + Tz
    第4行：w' = 0*x + 0*y + 0*z + 1*1  = 1
    ```

  - 很简单呢，平移矩阵就是简单的加法！顶点坐标直接加上平移距离。

第二步：项目中的平移逻辑

- 步骤1：计算正交投影的ratio

  - ```
    屏幕尺寸：1080 × 1920（竖屏）
    视频尺寸：1000 × 500（横向视频）
    
    videoRatio = 1000 / 500 = 2.0
    screenRatio = 1080 / 1920 = 0.5625
    
    videoRatio (2.0) > screenRatio (0.5625)
    → 视频更扁（横向），需要缩放高度
    
    mHeightRatio = videoRatio / screenRatio
                 = 2.0 / 0.5625
                 = 3.5556
    
    mWidthRatio = 1.0（不缩放）
    ```

  - 那么其执行正交矩阵生成方法：`Matrix.orthoM(prjMatrix, 0, -1.0f, 1.0f, -3.5556f, 3.5556f, 3f, 5f)` ，这是生成的正交矩阵

  - ```
    ┌                           ┐
    │ 1.0     0       0      0  │  ← m[0] = 1.0
    │ 0     0.2813    0      0  │  ← m[5] = 2/(2×3.5556) = 0.2813
    │ 0       0       *      *  │
    │ 0       0       0      1  │
    └                           ┘
    ```

  - 那么世界坐标范围如下

  - ```
    X轴：[-1.0, 1.0]     总宽度 = 2.0
    Y轴：[-3.5556, 3.5556]  总高度 = 7.1112
    ```

- 步骤二：用户触摸事件

  - 场景：手指从屏幕中心向右下移动

  - ```
    起点：(540, 960)   // 屏幕中心
    终点：(640, 1060)  // 向右100px，向下100px
    
    像素距离：
    deltaX = 640 - 540 = 100px
    deltaY = 1060 - 960 = 100px
    
    归一化距离（除以屏幕尺寸）：
    dx = 100 / 1080 = 0.0926
    dy = 100 / 1920 = 0.0521
    ```

  - dx = 0.0926 表示手指向右移动了屏幕宽度的 9.26%

  - dy = 0.0521 表示手指向下移动了屏幕高度的 5.21%

- 步骤三：调用translate方法 `translate(dx = 0.0926, dy = 0.0521)`

  - 计算传入translateM的值：

  - ```
    sx = dx × mWidthRatio × 2
       = 0.0926 × 1.0 × 2
       = 0.1852  // 世界坐标X方向移动距离
    
    sy = -dy × mHeightRatio × 2
       = -0.0521 × 3.5556 × 2
       = -0.3704  // 世界坐标Y方向移动距离（负号表示向上）
       
    世界坐标总宽度 = 2.0
    手指移动了9.26%
    世界坐标应该移动：2.0 × 0.0926 = 0.1852 ✓
    
    世界坐标总高度 = 7.1112
    手指移动了5.21%
    世界坐标应该移动：7.1112 × 0.0521 = 0.3704 ✓
    （加负号是因为Android向下，OpenGL向上）
    ```

- 步骤四：调用translateM方法

  - ```
    /**
     * Translates matrix m by x, y, and z in place.
     */
    public static void translateM(
            float[] m, int mOffset,
            float x, float y, float z) {
        for (int i=0 ; i<4 ; i++) {
            int mi = mOffset + i;
            // 🔑 关键：修改矩阵的第4列（索引12、13、14）
            m[12 + mi] += m[mi] * x + m[4 + mi] * y + m[8 + mi] * z;
        }
    }
    ```

  - 这是调用逻辑，传递的mMatrix是我们的正交矩阵，所以就是直接修改正交矩阵

  - ```
    Matrix.translateM(mMatrix, 0, 0.1852f, -0.3704f, 0f)
    
    // 源码执行（展开）：
    m[12] += m[0] × 0.1852 + m[4] × (-0.3704) + m[8] × 0
    m[13] += m[1] × 0.1852 + m[5] × (-0.3704) + m[9] × 0
    
    //  最终计算出来的值
    m[12] += 1.0 × 0.1852 + 0 × (-0.3704) + 0 × 0
          += 0.1852
    
    m[13] += 0 × 0.1852 + 0.2813 × (-0.3704) + 0 × 0
          += -0.1042
    ```

  - 现在矩阵变成

  - ```
    ┌                               ┐
    │ 1.0     0       0     0.1852  │  ← 第4列存储平移
    │ 0     0.2813    0    -0.1042  │
    │ 0       0       *       *     │
    │ 0       0       0       1     │
    └                               ┘
    ```

  - 现在有一个关键的问题：为什么 m[13] = -0.3704 *0.2813 =  -0.1042 而不是直接 -0.3704？

    - 因为这个传入的 -0.3704 是世界坐标的移动距离，我们期望视图相对自身移动
    - 以 m[5] = 0.2813（投影矩阵的Y轴系数）
    - 得到投影空间的平移：-0.3704 × 0.2813 = -0.1042

- 步骤五：GPU顶点变化

  - 以右上角顶点 (1, 1) 为例

  - 变换前（世界坐标）： `顶点：(x=1, y=1, z=0, w=1)`

  - GPU执行矩阵乘法： `gl_Position = uMatrix × aPosition`

  - 计算X坐标

  - ```
    x' = m[0]×1 + m[4]×1 + m[8]×0 + m[12]×1
       = 1.0×1 + 0×1 + 0 + 0.1852
       = 1.1852
    ```

  - 计算Y坐标：

  - ```
    y' = m[1]×1 + m[5]×1 + m[9]×0 + m[13]×1
       = 0×1 + 0.2813×1 + 0 + (-0.1042)
       = 0.2813 - 0.1042
       = 0.1771
    ```

  - 变换后的顶点：(1.1852, 0.1771)

- 步骤六：**理解最终效果**

  - 原始顶点（未移动）：

  - ```
    右上角：(1.0, 1.0 × 0.2813) = (1.0, 0.2813)
                  ↑ 被投影矩阵压缩
    ```

  - 移动后的顶点：

  - ```
    右上角：(1.1852, 0.1771)
    
    向右移动：1.1852 - 1.0 = 0.1852
    向下移动：0.1771 - 0.2813 = -0.1042（负数表示向下）
    ```

  - NDC坐标系中的移动比例

  - ```
    X方向：
    NDC总宽度 = 2.0（-1到1）
    移动了0.1852
    比例 = 0.1852 / 2.0 = 9.26% ✓ 正好等于dx！
    
    Y方向：
    NDC总高度 = 2.0
    移动了0.1042
    比例 = 0.1042 / 2.0 = 5.21% ✓ 正好等于dy！
    ```

  - 完美匹配！ 手指在屏幕上移动9.26%，视频在NDC中也移动9.26%！

- 数据流如下

  - ```
    触摸事件
      │
      ├─ 起点：(540, 960)
      ├─ 终点：(640, 1060)
      ├─ 像素距离：(100, 100)
      │
      ↓ 归一化
      
    归一化距离
      │
      ├─ dx = 100/1080 = 0.0926 (9.26%)
      ├─ dy = 100/1920 = 0.0521 (5.21%)
      │
      ↓ translate(dx, dy)
      
    计算世界坐标移动距离
      │
      ├─ sx = 0.0926 × 1.0 × 2 = 0.1852
      ├─ sy = -0.0521 × 3.5556 × 2 = -0.3704
      │     为什么乘以3.5556？因为世界坐标Y轴范围是[-3.5556, 3.5556]
      │     为什么乘以2？因为总高度 = 3.5556 - (-3.5556) = 7.1112 = 2×3.5556
      │
      ↓ Matrix.translateM(m, 0, 0.1852, -0.3704, 0)
      
    矩阵运算
      │
      ├─ m[12] += 1.0 × 0.1852 = 0.1852
      ├─ m[13] += 0.2813 × (-0.3704) = -0.1042
      │     为什么乘以0.2813？因为这是投影矩阵的Y轴缩放系数
      │     这个系数会把世界坐标[-3.5556, 3.5556]压缩到NDC[-1, 1]
      │
      ↓ GPU渲染
      
    顶点变换
      │
      ├─ 右上角：(1, 1) → (1.1852, 0.1771)
      ├─ X移动：0.1852 = NDC宽度的9.26%
      ├─ Y移动：0.1042 = NDC高度的5.21%
      │
      └─ 完美对应手指移动的比例！
    ```

### 3.5 上层视频缩放

当前状态：视频可以拖动，但尺寸固定（经过正交投影矫正的尺寸），我们期望可以让上层视频可以通过双指捏合手势任意缩放大小

- 这是我们期望的效果

  - ```
    初始状态：                缩放后：
    ┌────────────────┐      ┌────────────────┐
    │  黑边区域       │      │  黑边区域       │
    ├────────────────┤      ├────────────────┤
    │  📹 视频1       │      │  📹 视频1       │
    │  📹 视频2       │  →   │    ┌─────┐     │
    │  (完全重叠)     │      │    │视频2│     │ ← 缩小到50%
    ├────────────────┤      │    └─────┘     │
    │  黑边区域       │      ├────────────────┤
    └────────────────┘      │  黑边区域       │
                            └────────────────┘
    ```

原理：我们的实现是通过在正交矩阵基础上再次缩放实现的。

第一步：理解正交矩阵就是缩放矩阵

- 回顾学过的正交投影矩阵

  - ```
    Matrix.orthoM(prjMatrix, 0, -1f, 1f, -3.5556f, 3.5556f, 3f, 5f)
    
    生成的矩阵：
    ┌                      ┐
    │ 1.0    0     0    0  │  ← X轴缩放系数 = 2/(1-(-1)) = 1.0
    │ 0    0.2813  0    0  │  ← Y轴缩放系数 = 2/(3.5556-(-3.5556)) = 0.2813
    │ 0      0     *    *  │
    │ 0      0     0    1  │
    └                      ┘
    
    m[0] = 1.0    → X方向不缩放（1倍）
    m[5] = 0.2813 → Y方向缩放到28.13%
    这就是为什么视频高度被压缩了！
    ```

  - 正交矩阵本质就是缩放矩

- 现在用户想再次缩放视频，本质上就是**在现有缩放基础上再缩放一次**

  - ```
    原始缩放：Y轴 × 0.2813（正交投影）
    用户缩放：再 × 0.5（双指捏合到50%）
    最终缩放：Y轴 × (0.2813 × 0.5) = Y轴 × 0.1407
    ```

第二步：用户触摸事件 - 双指捏合

- 步骤1：Android的ScaleGestureDetector

  - ```
    // 监听双指捏合手势
    class DefGLSurfaceView : GLSurfaceView {
        private val scaleDetector = ScaleGestureDetector(
            context, 
            object : ScaleGestureDetector.SimpleOnScaleGestureListener() {
                override fun onScale(detector: ScaleGestureDetector): Boolean {
                    // 获取缩放系数
                    val scaleFactor = detector.scaleFactor
                    mDrawer?.scale(scaleFactor, scaleFactor)
                    return true
                }
            }
        )
        
        override fun onTouchEvent(event: MotionEvent): Boolean {
            scaleDetector.onTouchEvent(event)  // 交给缩放检测器处理
            // ... 拖动逻辑
            return true
        }
    }
    ```

  - 原理：scaleFactor 是相对于上一帧的缩放比例：

  - ```
    双指距离增大：scaleFactor > 1.0（如1.05表示放大5%）
    双指距离缩小：scaleFactor < 1.0（如0.95表示缩小5%）
    双指不动：  scaleFactor = 1.0（不缩放）
    
    示例：
    帧1：两指距离100px
    帧2：两指距离150px
    scaleFactor = 150/100 = 1.5（放大50%）
    ```

- 步骤二：用户双指捏合，产生触摸事件

  - 场景：用户双指从距离400px捏合到200px

  - ```
    起始距离：400px
    结束距离：200px
    
    scaleFactor = 200 / 400 = 0.5
    
    → 用户想把视频缩小到原来的50%
    ```

第三步：在正交矩阵基础上再次缩放

- 步骤1：当前矩阵状态（经过正交投影的矩阵）

  - ```
    屏幕尺寸：1080 × 1920（竖屏）
    视频尺寸：1000 × 500（横向视频）
    
    mHeightRatio = 3.5556（你学过的）
    mWidthRatio = 1.0
    
    当前矩阵（正交投影矩阵）：
    ┌                      ┐
    │ 1.0    0     0    0  │  ← m[0] = 1.0（X轴缩放系数）
    │ 0    0.2813  0    0  │  ← m[5] = 0.2813（Y轴缩放系数）
    │ 0      0     *    *  │
    │ 0      0     0    1  │
    └                      ┘
    
    物理含义：
    m[0] = 1.0    → X轴保持原始大小
    m[5] = 0.2813 → Y轴缩放到28.13%（矫正视频比例）
    ```

- 步骤2：调用scale方法

  - ```
    用户触发：scaleFactor = 0.5
    调用：scale(sx = 0.5f, sy = 0.5f)
    ```

- 步骤3：执行scaleM（在现有矩阵上再次缩放）

  - 这是Android Matrix的scaleM源码

  - ```
    /**
     * Scales matrix m in place by sx, sy, and sz.
     * 关键：直接修改现有矩阵的缩放系数
     */
    public static void scaleM(float[] m, int mOffset,
            float x, float y, float z) {
        for (int i=0 ; i<4 ; i++) {
            int mi = mOffset + i;
            m[     mi] *= x;  // 第1列所有元素 × sx
            m[ 4 + mi] *= y;  // 第2列所有元素 × sy
            m[ 8 + mi] *= z;  // 第3列所有元素 × sz
        }
    }
    ```

  - 好，这是处理结果

  - ```
    ┌                      ┐
    │ 0.5    0     0    0  │  ← m[0] = 0.5（X轴缩小到50%）
    │ 0    0.1407  0    0  │  ← m[5] = 0.1407（Y轴缩小到14.07%）
    │ 0      0     *    *  │
    │ 0      0     0    1  │
    └                      ┘
                        ↑
                    平移保持不变！
    ```

- 步骤4：更新ratio

  - 代码中的scale方法

  - ```
    fun scale(sx: Float, sy: Float) {
        Matrix.scaleM(mMatrix, 0, sx, sy, 1f)
        
        // 🔑 关键：更新ratio
        mWidthRatio /= sx
        mHeightRatio /= sy
    }
    ```

  - 执行更新

  - ```
    缩放前：
    mWidthRatio = 1.0
    mHeightRatio = 3.5556
    
    执行：
    mWidthRatio /= 0.5   // 1.0 / 0.5 = 2.0
    mHeightRatio /= 0.5  // 3.5556 / 0.5 = 7.1112
    
    缩放后：
    mWidthRatio = 2.0
    mHeightRatio = 7.1112
    ```

  - 更新ratio的目的：保证后续平移正确

- 步骤5：GPU顶点变换

  - 以右上角顶点 (1, 1) 为例

  - 缩放前（只有正交投影）：

  - ```
    顶点：(x=1, y=1, z=0, w=1)
    矩阵：m[0]=1.0, m[5]=0.2813
    
    x' = 1.0 × 1 = 1.0
    y' = 0.2813 × 1 = 0.2813
    
    结果：(1.0, 0.2813)
    ```

  - 缩放后（正交投影 + 用户缩放）：

  - ```
    顶点：(x=1, y=1, z=0, w=1)
    矩阵：m[0]=0.5, m[5]=0.1407
    
    x' = 0.5 × 1 = 0.5
    y' = 0.1407 × 1 = 0.1407
    
    结果：(0.5, 0.1407)
    ```

  - 对比变化：顶点坐标缩小到原来的50%！

第四步：完整的数据流（从触摸事件到GPU渲染）

- 完整数据流

  - ```
    用户双指捏合
      │
      ├─ 起始距离：400px
      ├─ 结束距离：200px
      │
      ↓ ScaleGestureDetector计算
      
    计算缩放系数
      │
      ├─ scaleFactor = 200 / 400 = 0.5
      │     表示缩小到原来的50%
      │
      ↓ scale(0.5, 0.5)
      
    修改矩阵（在正交矩阵基础上累积缩放）
      │
      ├─ m[0] = 1.0 × 0.5 = 0.5
      ├─ m[5] = 0.2813 × 0.5 = 0.1407
      │     关键理解：正交矩阵就是缩放矩阵
      │               m[5]本身就是Y轴缩放系数
      │               现在再乘以0.5，就是累积缩放
      │
      ↓ 更新ratio
      
    ratio更新（保持m[5] × ratio = 1）
      │
      ├─ mWidthRatio = 1.0 / 0.5 = 2.0
      ├─ mHeightRatio = 3.5556 / 0.5 = 7.1112
      │     为什么除以0.5？
      │     因为m[5]缩小了（× 0.5），ratio必须增大（/ 0.5）
      │     才能保持 m[5] × ratio = 1
      │
      ↓ GPU渲染
      
    顶点变换
      │
      ├─ 右上角：(1, 1) → (0.5, 0.1407)
      ├─ NDC范围：X从[-1,1]→[-0.5,0.5]，Y从[-0.28,0.28]→[-0.14,0.14]
      ├─ 宽度和高度都缩小50%
      │
      └─ 视频缩小到原来的50%！
    ```

         * 缩放视频画面
         *

- GLSurfaceView中监听手势

  - ```
    class DefGLSurfaceView : GLSurfaceView {
        private var mDrawer: VideoDrawer? = null
        
        // 缩放手势检测器
        private val scaleDetector = ScaleGestureDetector(
            context,
            object : ScaleGestureDetector.SimpleOnScaleGestureListener() {
                override fun onScale(detector: ScaleGestureDetector): Boolean {
                    // 获取相对于上一帧的缩放系数
                    val scaleFactor = detector.scaleFactor
                    
                    // 应用缩放
                    mDrawer?.scale(scaleFactor, scaleFactor)
                    
                    return true
                }
            }
        )
        
        override fun onTouchEvent(event: MotionEvent): Boolean {
            // 交给缩放检测器处理
            scaleDetector.onTouchEvent(event)
            
            // 处理拖动（阶段二的逻辑）
            when (event.action) {
                MotionEvent.ACTION_MOVE -> {
                    val dx = (event.x - mPrePoint.x) / width
                    val dy = (event.y - mPrePoint.y) / height
                    mDrawer?.translate(dx, dy)
                    mPrePoint.x = event.x
                    mPrePoint.y = event.y
                }
            }
            
            return true
        }
    }
    ```
