### 3.1 声明式 UI vs 命令式 UI

#### 1.命令式UI

状态变化 → 你手动找到控件 → 你手动修改控件属性

```java
// Android：你需要主动操作每一步
bt.setOnClickListener {
    visible = !visible
    if(visible) {
        tv.visibility = View.VISIBLE  // 手动设置
        bt.text = "隐藏文本"           // 手动设置
    } else {
        tv.visibility = View.GONE     // 手动设置
        bt.text = "显示文本"           // 手动设置
    }
}

```

#### 2.声明式UI

状态变化 → 你只修改状态 → 框架自动更新 UI

代码

```java
// Flutter：你只描述 UI 应该是什么样子
@override
Widget build(BuildContext context) {
  return Column(
    children: [
      Visibility(visible: visible, child: const Text("文本")),  // UI = f(状态)
      ElevatedButton(
        onPressed: _switchVisible,
        child: Text(visible ? '隐藏文本' : '显示文本'),  // UI = f(状态)
      ),
    ]
  );
}

void _switchVisible() {
  setState(() {
    visible = !visible;  // 只改状态，UI 自动更新
  });
}

```

执行框架

```java
┌─────────────────────────────────────────────────────────┐
│                                                         │
│   状态 (visible)                                        │
│        │                                                │
│        │ setState() 通知框架                            │
│        ▼                                                │
│   Flutter 框架                                          │
│        │                                                │
│        │ 自动调用 build()                               │
│        ▼                                                │
│   Widget 树 (根据状态生成)                               │
│        │                                                │
│        │ 框架自动 diff 和更新                           │
│        ▼                                                │
│   屏幕显示                                               │
│                                                         │
│   优点：UI = f(状态)，状态变了 UI 自动变                 │
└─────────────────────────────────────────────────────────┘
```

### 3.2 三棵树渲染机制

#### 1. 问题场景

假如只有Widget和Render，在状态频繁变化时。

- Widget 需要频繁重建，其重建那么对应Render不能复用，因为一一对应。
- 这导致实际渲染很昂贵（布局、绘制、GPU），Renderer也要完全重建
- 如果每次都完全重建渲染树，性能会很差

解决方案：

- 用 Element 作为中间层
- Element 负责对比新旧 Widget，决定是否需要更新 RenderObject
- 只更新真正变化的部分

#### 2. 代码

Element复用判断：复用条件：类型相同 + key 相同

- ```java
  // Element 判断是否可以复用
  static bool canUpdate(Widget oldWidget, Widget newWidget) {
    return oldWidget.runtimeType == newWidget.runtimeType
        && oldWidget.key == newWidget.key;
  }
  ```

UI更新流程：按需创建，只创建更新的部分

- ```java
  // Element.updateChild() 简化版
  Element? updateChild(Element? child, Widget? newWidget, Object? newSlot) {
    
    // 情况1：新 Widget 为空，删除旧 Element
    if (newWidget == null) {
      if (child != null) {
        deactivateChild(child);  // 移除
      }
      return null;
    }
    
    // 情况2：有旧 Element
    if (child != null) {
      // 情况2a：可以复用（类型和 key 相同）
      if (canUpdate(child.widget, newWidget)) {
        child.update(newWidget);  // 只更新配置，复用 Element
        return child;
      }
      // 情况2b：不能复用（类型或 key 不同）
      deactivateChild(child);  // 移除旧的
    }
    
    // 情况3：创建新 Element
    return inflateWidget(newWidget, newSlot);  // 新建
  }
  
  ```

渲染流程

- ```java
  1. Widget 树变化（setState 触发）
          │
          ▼
  2. Element 对比新旧 Widget
          │
          ├── canUpdate() == true → 复用 Element，更新属性
          │                              │
          │                              └── RenderObject.属性更新
          │
          └── canUpdate() == false → 销毁旧 Element，创建新 Element
          │                              │
          │                              └── 创建新 RenderObject
          │
          ▼
  3. RenderObject 树更新完成
          │
          ▼
  4. 布局 (layout)
          │
          ▼
  5. 绘制 (paint)
          │
          ▼
  6. Skia 合成 → GPU 渲染 → 屏幕
  ```

Element的作用：Widget 变了 → Element 对比 → 只更新变化的 RenderObject

### 3.3 StatelessWidget & StatefulWidget

StatelessWidget用于不可变UI，StatefulWidget用于可变UI，可变UI依赖的状态存在State 对象里，State 是跨帧持久的。

#### 1.代码

```java
// StatelessWidget：build 在 Widget 里
class MyStateless extends StatelessWidget {
  @override
  Widget build(BuildContext context) { ... }
}

// StatefulWidget：build 在 State 里
class MyStateful extends StatefulWidget {
  @override
  State<MyStateful> createState() => _MyStatefulState();
}

class _MyStatefulState extends State<MyStateful> {
  int _counter = 0;  // 状态数据在 State 里
  
  @override
  Widget build(BuildContext context) { ... }  // build 也在 State 里
}

```

#### 2.原理

生命周期对比

- ```java
  StatelessWidget:
  ┌─────────────────────────────────────────┐
  │  createElement() → mount() → build()   │
  │                                         │
  │  （没有 State，生命周期简单）            │
  └─────────────────────────────────────────┘
  
  StatefulWidget:
  ┌─────────────────────────────────────────────────────────────────┐
  │                                                                 │
  │  createElement()                                                │
  │       │                                                         │
  │       ▼                                                         │
  │  createState() ← 创建 State 对象                                │
  │       │                                                         │
  │       ▼                                                         │
  │  initState() ← 初始化状态（只调用一次）                          │
  │       │                                                         │
  │       ▼                                                         │
  │  didChangeDependencies() ← 依赖变化时调用                        │
  │       │                                                         │
  │       ▼                                                         │
  │  build() ← 构建 UI                                              │
  │       │                                                         │
  │       │ ←──────────────────────────────┐                        │
  │       │                                │                        │
  │       ▼                                │                        │
  │  [运行中]                              │                        │
  │       │                                │                        │
  │       │ setState() 被调用              │                        │
  │       │                                │                        │
  │       ▼                                │                        │
  │  didUpdateWidget() ← Widget 配置更新   │                        │
  │       │                                │                        │
  │       └────────────────────────────────┘                        │
  │                                                                 │
  │       │ 销毁时                                                  │
  │       ▼                                                         │
  │  dispose() ← 释放资源                                           │
  │                                                                 │
  └─────────────────────────────────────────────────────────────────┘
  ```

setState会置其为脏，当下一个vsync信号到来时，会触发脏Element的rebuild，进而调用state.build返回新的Widget树。并通过Element.updateChild() 对比更新，判断是否要新建redner。

#### 3.建议

1. 开发的时候应该尽可能把状态下沉到最小范围，同时使用状态管理方案（Provider、Riverpod 等）

2. 不要在state.build中做耗时任务。

### 3.4  如何在布局中添加或删除一个组件

#### 1.思路

Flutter 中没有"增删"组件的概念

只有：
1. 修改状态
2. build() 根据状态返回不同的 Widget 树
3. 框架自动对比差异，更新 UI

#### 2.代码

```dart
class _SampleAppPageState extends State<SampleAppPage> {
  // 1️⃣ 定义状态（标志位）
  bool toggle = true;
  
  // 2️⃣ 修改状态的方法
  void _toggle() {
    setState(() {
      toggle = !toggle;  // 切换状态
    });
    // setState 通知框架：状态变了，请重新 build
  }

  // 3️⃣ 根据状态返回不同 Widget 的方法
  Widget _getToggleChild() {
    if (toggle) {
      return const Text('Toggle One');
    } else {
      return ElevatedButton(
        onPressed: () {},
        child: const Text('Toggle Two'),
      );
    }
  }

  // 4️⃣ build 方法中使用
  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: Center(
        child: _getToggleChild(),  // 调用方法，返回不同 Widget
      ),
      floatingActionButton: FloatingActionButton(
        onPressed: _toggle,  // 点击切换状态
        child: const Icon(Icons.update),
      ),
    );
  }
}
```

### 3.5 flutter中实现动画

#### 1.问题点

Android 的做法：

- ```dart
  // 命令式：直接操作 View 的属性
  view.animate()
      .alpha(0f)
      .setDuration(2000)
      .start()
  ```

Flutter 的问题：

- Widget 是不可变的
- 不能直接修改 Widget 的属性
- 那怎么实现动画？

我们来考虑一下什么是动画？不知道有没有看过连续翻动的小人书，动画本质就是连续的画面，这里的每个画面看作一帧即可。所以很简单，我们只用每帧改变动画widget的state，让其往前推一点，构成差异性的一帧。然后连续变动的帧就构成了动画。

#### 2.代码

看看代码吧

- ```dart
  /// with TickerProviderStateMixin：提供 Ticker 能力
  class _MyFadeTest extends State<MyFadeTest> with TickerProviderStateMixin {
    // 1️⃣ 声明 AnimationController
    late AnimationController controller;
  
    @override
    void initState() {
      super.initState();
      
      // 2️⃣ 初始化 AnimationController
      controller = AnimationController(
        duration: const Duration(milliseconds: 2000),  // 动画时长 2 秒
        vsync: this,  // this = TickerProviderStateMixin，提供 Ticker
      );
      
      // AnimationController 的值会从 0.0 线性变化到 1.0
    }
  
    @override
    void dispose() {
      // 4️⃣ 释放资源（重要！）
      controller.dispose();
      super.dispose();
    }
  
    @override
    Widget build(BuildContext context) {
      return Scaffold(
        body: Center(
          // 3️⃣ 使用动画 Widget
          child: FadeTransition(
            opacity: controller,  // 把 controller 传给 FadeTransition
            child: const FlutterLogo(size: 100),
          ),
        ),
        floatingActionButton: FloatingActionButton(
          onPressed: () {
            controller.forward();  // 点击时开始动画
          },
          child: const Icon(Icons.brush),
        ),
      );
    }
  }
  ```

这是原理，AnimationController自动更新值，触发FadeTransition动画Widget的新建

- ```javascript
  ┌─────────────────────────────────────────────────────────────────┐
  │                                                                 │
  │  1. 初始化                                                      │
  │     AnimationController(duration: 2000ms, vsync: this)          │
  │                                                                 │
  │  2. 用户点击按钮                                                 │
  │     controller.forward()  ← 开始动画                            │
  │                                                                 │
  │  3. 每帧执行（约 16.67ms 一次）                                  │
  │     ┌─────────────────────────────────────────────────────┐     │
  │     │                                                     │     │
  │     │  Ticker 发出信号（vsync）                           │     │
  │     │       │                                             │     │
  │     │       ▼                                             │     │
  │     │  AnimationController 更新值（0.0 → 0.01 → ...）     │     │
  │     │       │                                             │     │
  │     │       ▼                                             │     │
  │     │  通知监听者（FadeTransition）                       │     │
  │     │       │                                             │     │
  │     │       ▼                                             │     │
  │     │  FadeTransition 重建，应用新的 opacity 值           │     │
  │     │       │                                             │     │
  │     │       ▼                                             │     │
  │     │  屏幕显示更新后的 UI                                │     │
  │     │                                                     │     │
  │     └─────────────────────────────────────────────────────┘     │
  │                                                                 │
  │  4. 动画结束（值到达 1.0）                                       │
  │     Ticker 停止                                                 │
  │                                                                 │
  └─────────────────────────────────────────────────────────────────┘
  ```

### 3.6. 如何创建自定义Widget

#### 1.思路

Android 的做法：

- ```java
  // 继承 View 或其子类，重写方法
  class CustomView : View {
      override fun onDraw(canvas: Canvas) { ... }
      override fun onMeasure(widthSpec: Int, heightSpec: Int) { ... }
  }
  
  ```

Flutter 自定义 Widget 的核心思想：

- 不是"我要画一个新东西"，而是"我要把现有的东西组合成新东西"

- 也就是把现有 Widget 组合成新的 Widget

- 比如:

  - ```java
    // ✅ 好的做法
    class MyWidget extends StatelessWidget {
      // 1. 用 final 声明属性
      final String title;
      
      // 2. 用 const 构造函数
      const MyWidget({super.key, required this.title});
      
      // 3. 在 build 中组合
      @override
      Widget build(BuildContext context) {
        return Text(title);
      }
    }
    
    // ❌ 不推荐的做法
    class MyWidget extends Text {  // 直接继承具体 Widget
      // 复杂且不灵活
    }
    
    ```

### 3.7 场景View对应Widget

#### 1.Android → Flutter 对照表

| Android View              | Flutter Widget                     | 说明                                                         |
| ------------------------- | ---------------------------------- | ------------------------------------------------------------ |
| LinearLayout (horizontal) | Row                                | 水平方向排列子组件，Android 通过`orientation="horizontal"`实现，Flutter 直接用 Row 组件，支持主轴 / 交叉轴对齐方式 |
| LinearLayout (vertical)   | Column                             | 垂直方向排列子组件，Android 通过`orientation="vertical"`实现，Flutter 直接用 Column 组件，支持灵活对齐配置 |
| RelativeLayout            | Stack + Positioned / LayoutBuilder | 基于相对位置布局子组件：Flutter 中用 Stack 实现层叠，结合 Positioned 控制子组件相对 Stack 的位置；复杂场景可搭配 LayoutBuilder 获取父组件约束 |
| FrameLayout               | Stack                              | 层叠显示子组件，Android 默认子组件居中，Flutter 默认子组件左上角对齐（可通过`alignment`属性修改），均支持子组件覆盖显示 |
| ListView                  | ListView (直接子组件)              | 简单列表展示，Android 需配合 Adapter，Flutter 可直接在 ListView 中添加子组件（适用于少量静态数据） |
| ScrollView                | SingleChildScrollView / ListView   | 滚动容器：Android ScrollView 仅支持单个子组件，Flutter 对应 SingleChildScrollView；ListView 既支持列表也可作为通用滚动容器（适用于动态数据） |
| RecyclerView              | ListView.builder / SliverList      | 高性能可复用列表：Android 通过 RecyclerView + ViewHolder 实现 item 复用，Flutter 用 ListView.builder（懒加载 + 复用）或 SliverList（配合 CustomScrollView），均优化大量数据渲染性能 |

### 3.9 如何使用 Canvas 进行绘制

#### 1.需求场景

画一些自定义图形（线条、圆形、签名等），

Android 的做法：

- ```java
  class MyView : View {
      override fun onDraw(canvas: Canvas) {
          val paint = Paint()
          paint.color = Color.RED
          canvas.drawCircle(100f, 100f, 50f, paint)  // 画一个圆
      }
  }
  
  ```

Flutter 的做法： 使用 CustomPaint（Widget） + CustomPainter（画笔）

#### 2.代码

画一个红色圆形

- ```java
  // 第一步：创建一个 CustomPainter
  class MyPainter extends CustomPainter {
    @override
    void paint(Canvas canvas, Size size) {
      // 1. 创建画笔
      final paint = Paint()
        ..color = Colors.red
        ..style = PaintingStyle.fill;  // 填充
      
      // 2. 画一个圆
      canvas.drawCircle(
        Offset(100, 100),  // 圆心坐标
        50,                 // 半径
        paint,              // 画笔
      );
    }
  
    @override
    bool shouldRepaint(covariant CustomPainter oldDelegate) {
      return false;  // 不需要重绘（静态图形）
    }
  }
  
  // 第二步：在 Widget 树中使用
  class MyWidget extends StatelessWidget {
    @override
    Widget build(BuildContext context) {
      return CustomPaint(
        painter: MyPainter(),  // 传入你的 Painter

      );
    }
  }

签名功能

- 目标：用户手指在屏幕上滑动，画出签名轨迹。

- 思路：监听手指滑动事件；记录手指经过的所有点；把这些点连成线

- 代码

  - ```java
    class Signature extends StatefulWidget {
      @override
      State<Signature> createState() => SignatureState();
    }
    
    class SignatureState extends State<Signature> {
      // 存储所有触摸点
      // null 表示"抬起手指"，用于分隔不同的笔画
      List<Offset?> _points = [];
    
      @override
      Widget build(BuildContext context) {
        return GestureDetector(
          // 监听手指滑动
          onPanUpdate: (details) {
            setState(() {
              // 获取触摸点的坐标（相对于这个 Widget）
              RenderBox box = context.findRenderObject() as RenderBox;
              Offset localPosition = box.globalToLocal(details.globalPosition);
              
              // 添加到点列表
              _points.add(localPosition);
            });
          },
          
          // 手指抬起时，添加 null 表示一笔结束
          onPanEnd: (details) {
            _points.add(null);
          },
          
          // 使用 CustomPaint 绘制
          child: CustomPaint(
            painter: SignaturePainter(_points),  // 传入点列表
            size: Size.infinite,  // 占满整个空间
          ),
        );
      }
    }
    
    class SignaturePainter extends CustomPainter {
      final List<Offset?> points;
      
      SignaturePainter(this.points);
    
      @override
      void paint(Canvas canvas, Size size) {
        // 创建画笔
        final paint = Paint()
          ..color = Colors.black
          ..strokeCap = StrokeCap.round  // 线条端点圆润
          ..strokeWidth = 5;             // 线条宽度
        
        // 遍历所有点，把相邻的点连成线
        for (int i = 0; i < points.length - 1; i++) {
          // 如果当前点和下一个点都不是 null，就画一条线
          if (points[i] != null && points[i + 1] != null) {
            canvas.drawLine(points[i]!, points[i + 1]!, paint);
          }
          // 如果遇到 null，说明是一笔的结束，跳过不画
        }
      }
    
      @override
      bool shouldRepaint(SignaturePainter oldDelegate) {
        // 如果点列表变了，就需要重绘
        return oldDelegate.points != points;
      }
    }
    
    ```

流程

- ```java
  用户手指按下并滑动
          │
          ▼
  GestureDetector.onPanUpdate 触发
          │
          ▼
  获取触摸坐标，添加到 _points 列表
          │
          ▼
  setState() 触发 Widget 重建（CustomPaint观测_points这个状态）
          │
          ▼
  CustomPaint 重建，调用 SignaturePainter.paint()
          │
          ▼
  遍历 _points，用 canvas.drawLine() 连接相邻的点
          │
          ▼
  屏幕显示签名轨迹
  
  ────────────────────────────────────
  
  用户手指抬起
          │
          ▼
  onPanEnd 触发，添加 null 到 _points
          │
          ▼
  下次画线时遇到 null 会跳过，实现"断笔"效果
  
  ```

#### 3.问题

当前存在如下问题：

- ```java
  每次 setState() 触发重绘时：
  
  第 1 次：画点 1
  第 2 次：画点 1 → 点 2
  第 3 次：画点 1 → 点 2 → 点 3
  第 4 次：画点 1 → 点 2 → 点 3 → 点 4
  ...
  
  确实是每次都从头画一遍，不是增量绘制。
  ```

### 4.2 如何处理外部 Intent

#### 1.问题点

其他 App 通过 Intent 分享数据给你的 Flutter 应用，Flutter 如何接收？

#### 2.原理

-  借助MethodChannel 实现 Flutter 和原生的通信

  - ```java
    ┌─────────────────────────────────────────────────────────────┐
    │                    Android 原生层                            │
    │                                                             │
    │   FlutterActivity                                           │
    │       │                                                     │
    │       ├── onCreate(): 接收 Intent 数据                      │
    │       │                                                     │
    │       └── configureFlutterEngine():                         │
    │               │                                             │
    │               └── 创建 MethodChannel                        │
    │                       │                                     │
    │                       │ "app.channel.shared.data"           │
    │                       │                                     │
    └───────────────────────│─────────────────────────────────────┘
                            │
                            │ 通信
                            │
    ┌───────────────────────│─────────────────────────────────────┐
    │                       ▼                                     │
    │                    Flutter 层                               │
    │                                                             │
    │   MethodChannel('app.channel.shared.data')                  │
    │       │                                                     │
    │       └── invokeMethod('getSharedText')                     │
    │               │                                             │
    │               └── 获取原生传递的数据                         │
    │                                                             │
    └─────────────────────────────────────────────────────────────┘
    
    ```

#### 3.代码

- Android侧

  - ```java
    public class MainActivity extends FlutterActivity {
        private String sharedText;
        private static final String CHANNEL = "app.channel.shared.data";
        
        @Override
        protected void onCreate(Bundle savedInstanceState) {
            super.onCreate(savedInstanceState);
            
            // 接收 Intent 数据
            Intent intent = getIntent();
            if (Intent.ACTION_SEND.equals(intent.getAction())) {
                sharedText = intent.getStringExtra(Intent.EXTRA_TEXT);
            }
        }
    
        @Override
        public void configureFlutterEngine(@NonNull FlutterEngine flutterEngine) {
            super.configureFlutterEngine(flutterEngine);
            
            // 创建 MethodChannel
            new MethodChannel(
                flutterEngine.getDartExecutor().getBinaryMessenger(),
                CHANNEL
            ).setMethodCallHandler((call, result) -> {
                // 处理 Flutter 的调用
                if (call.method.equals("getSharedText")) {
                    result.success(sharedText);
                    sharedText = null;
                }
            });
        }
    }
    ```

- Flutter端

  - ```java
    class _SampleAppPageState extends State<SampleAppPage> {
      // 创建通道（名称必须和 Android 端一致）
      static const platform = MethodChannel('app.channel.shared.data');
      String dataShared = 'No data';
    
      @override
      void initState() {
        super.initState();
        getSharedText();
      }
    
      Future<void> getSharedText() async {
        // 调用原生方法
        var sharedData = await platform.invokeMethod('getSharedText');
        if (sharedData != null) {
          setState(() {
            dataShared = sharedData;
          });
        }
      }
    
      @override
      Widget build(BuildContext context) {
        return Scaffold(body: Center(child: Text(dataShared)));
      }
    }
    
    ```

### 4.3 如何监听 Activity 生命周期

#### 1.需求

Flutter 如何知道 App 进入后台、回到前台？

#### 2.原理

- 本质仍然是方法通道，不过是通过 Flutter Engine 内置的 LifecycleChannel 通信，不是你自己创建的 MethodChannel。
  - ```java
    Android Activity 生命周期变化
            │
            ▼
    FlutterActivity 捕获生命周期事件
            │
            ▼
    通过 SystemChannels.lifecycle 发送消息给 Dart
            │
            ▼
    WidgetsBinding 接收消息
            │
            ▼
    通知所有 WidgetsBindingObserver
            │
            ▼
    你的 didChangeAppLifecycleState() 被调用
    
    ```

#### 3.代码

- 应用层订阅

  - ```java
    class _MyAppState extends State<MyApp> with WidgetsBindingObserver {
      @override
      void initState() {
        super.initState();
        // 注册观察者
        WidgetsBinding.instance.addObserver(this);
      }
    
      @override
      void dispose() {
        // 移除观察者
        WidgetsBinding.instance.removeObserver(this);
        super.dispose();
      }
    
      @override
      void didChangeAppLifecycleState(AppLifecycleState state) {
        switch (state) {
          case AppLifecycleState.resumed:
            print('App 回到前台');
            break;
          case AppLifecycleState.inactive:
            print('App 不活跃（如来电）');
            break;
          case AppLifecycleState.paused:
            print('App 进入后台');
            break;
          case AppLifecycleState.detached:
            print('App 被销毁');
            break;
        }
      }
    
      @override
      Widget build(BuildContext context) {
        return Container();
      }
    }
    
    ```

- 系统层处理，进行分发给所有flutter层的观察者

  - ```java
    // FlutterActivity.java
    @Override
    protected void onResume() {
        super.onResume();
        // 通知 Flutter 引擎：App 回到前台
        flutterEngine.getLifecycleChannel().appIsResumed();
    }
    
    @Override
    protected void onPause() {
        super.onPause();
        flutterEngine.getLifecycleChannel().appIsInactive();
    }
    
    
    // WidgetsBinding (Dart 端)
    void handleAppLifecycleStateChanged(AppLifecycleState state) {
      // 通知所有观察者
      for (final WidgetsBindingObserver observer in _observers) {
        observer.didChangeAppLifecycleState(state);
      }
    }
    ```

### 4.5 混合页面模式下路由和启动栈管理

#### 1.问题点

- 问题点

  - ```java
    Flutter 页面 = Widget（在 FlutterActivity 内部）
    原生页面 = Activity
    
    两者的"栈"是不同的东西：
    - Activity 栈：由 Android 系统管理
    - Widget 栈：由 Flutter Navigator 管理
    
    问题：如何让这两个栈"协同工作"？
    ```

#### 2.场景演示

- 假设有这样的跳转序列：

  - ```java
    1. 启动 App，显示 Flutter 页面 A (WidgetA)
    2. 从 WidgetA 跳转到原生 ActivityB
    3. 从 ActivityB 跳转到 Flutter 页面 C (WidgetC)
    4. 用户按返回键...
    5. 用户按返回键...
    6. 用户按返回键...
    
    期望：C → B → A（正确返回）
    
    ```

#### 3.原理：flutter_boost 

- 原理：从Android启动的不同Flutter页就用不同的FlutterActivity区分。而每个FlutterActivity都有自己的BoostNavigator 栈来管理自己内部的widget跳转。

  - Flutter 内部跳转（同一个 FlutterActivity）

  - ```java
    // 在 Flutter 内部跳转，不创建新 Activity
    Navigator.push(context, MaterialPageRoute(builder: (_) => PageB()));
    
    FlutterActivity A
        │
        └── Navigator 栈：[WidgetA, WidgetB, WidgetC]
                                  │
                                  └── 都在同一个 Activity 内
    ```

  - 跨原生跳转（创建新 FlutterActivity）

  - ```java
    // 跳转到原生，再跳回 Flutter，会创建新 Activity
    BoostNavigator.instance.push('/nativePage');  // 跳原生
    // 原生再跳 Flutter 时，创建新的 FlutterActivity
    
    Android 栈：[FlutterActivity A, NativeActivity, FlutterActivity B]
                        │                               │
                        └── WidgetA                     └── WidgetD
    
    ```

  - 完整示例

  - ```java
    操作序列：
    1. App 启动，显示 WidgetA
    2. WidgetA 内部跳转到 WidgetB（Flutter 内部）
    3. WidgetB 跳转到 NativeActivity
    4. NativeActivity 跳转到 WidgetC
    
    结果：
    
    Android Activity 栈：
    ┌─────────────────────────────────────────┐
    │  FlutterActivity 2                      │  ← 栈顶
    │      └── Navigator: [WidgetC]           │
    ├─────────────────────────────────────────┤
    │  NativeActivity                         │
    ├─────────────────────────────────────────┤
    │  FlutterActivity 1                      │  ← 栈底
    │      └── Navigator: [WidgetA, WidgetB]  │
    └─────────────────────────────────────────┘
    
    返回顺序：
      返回 → WidgetC 消失，NativeActivity 显示
      返回 → NativeActivity 消失，WidgetB 显示
      返回 → WidgetB 消失，WidgetA 显示
      返回 → App 退出
    
    ```

- 问题点：flutter渲染时是渲染到对应Activity的Surface上。多个FlutterActivity，如何切换其Surface？

  - 解决方案： FlutterEngine 的 attach/detach

  - ```java
    // 当 FlutterActivity 进入前台
    FlutterActivity.onResume()
        │
        └──→ flutterEngine.attachToActivity(this)
                  │
                  └──→ 把渲染目标切换到这个 Activity 的 Surface
    
    // 当 FlutterActivity 进入后台
    FlutterActivity.onPause()
        │
        └──→ flutterEngine.detachFromActivity()
                  │
                  └──→ 暂停渲染
    
    ```

- 流程

  - ```java
    步骤 1：启动 App
    ─────────────────────────────────────────────────────
    Android 栈：[FlutterActivity A]
    Dart 栈：  [WidgetA]
    
    FlutterActivity A 创建
      → attach 到 FlutterEngine
      → 通知 Dart 端显示 WidgetA
    
    
    步骤 2：WidgetA 跳转到 NativeActivity B
    ─────────────────────────────────────────────────────
    Android 栈：[FlutterActivity A, NativeActivity B]
    Dart 栈：  [WidgetA]  (不变)
    
    Dart: BoostNavigator.push('/nativeB')
      → MethodChannel 通知原生
      → 原生 startActivity(NativeActivity B)
      → FlutterActivity A 进入 onPause
    
    
    步骤 3：NativeActivity B 跳转到 WidgetC
    ─────────────────────────────────────────────────────
    Android 栈：[FlutterActivity A, NativeActivity B, FlutterActivity C]
    Dart 栈：  [WidgetA] [Widget C]
    
    原生: FlutterBoost.open('/widgetC')
      → 创建新的 FlutterActivity C
      → FlutterActivity C attach 到 FlutterEngine
      → 通知 Dart 端 push WidgetC
      → FlutterEngine 渲染 WidgetC 到 FlutterActivity C 的 Surface
    
    
    步骤 4：按返回键
    ─────────────────────────────────────────────────────
    Android 栈：[FlutterActivity A, NativeActivity B]
    Dart 栈：  [WidgetA]
    
    FlutterActivity C 收到返回键
      → 通知 Dart 端 pop WidgetC
      → finish() 自己
      → NativeActivity B 回到前台
    
    
    步骤 5：按返回键
    ─────────────────────────────────────────────────────
    Android 栈：[FlutterActivity A]
    Dart 栈：  [WidgetA]
    
    NativeActivity B 收到返回键
      → finish() 自己
      → FlutterActivity A 回到前台
      → FlutterEngine 重新 attach 到 FlutterActivity A 的 Surface
      → 渲染 WidgetA
    
    
    步骤 6：按返回键
    ─────────────────────────────────────────────────────
    Android 栈：[]
    Dart 栈：  []
    
    FlutterActivity A 收到返回键
      → finish() 自己
      → App 退出
    
    ```

## 05.Flutter异步

### 5.1 Flutter线程模型

#### 1.线程模型

- Flutter Engine 内部有 4 个线程：

  - ```java
    ┌─────────────────────────────────────────────────────────────────┐
    │                    Flutter Engine 线程                          │
    │                                                                 │
    │   1️⃣ Platform Thread (平台线程)                                 │
    │      = Android 主线程                                           │
    │      职责：处理平台事件（触摸、生命周期）                         │
    │                                                                 │
    │   2️⃣ UI Thread (UI 线程)                                        │
    │      = Dart 代码运行的线程                                       │
    │      职责：运行 Dart VM，执行你的代码，构建 Widget 树            │
    │                                                                 │
    │   3️⃣ Raster Thread (光栅化线程，也叫 GPU 线程)                  │
    │      职责：Skia 渲染，把 Layer 树转成像素                        │
    │                                                                 │
    │   4️⃣ IO Thread (IO 线程)                                        │
    │      职责：图片解码、文件读取等 IO 操作                          │
    │                                                                 │
    └─────────────────────────────────────────────────────────────────┘、
    ```

#### 2.执行网络请求

- 代码

  - ```java
    // 这样写不会阻塞 UI
    Future<void> fetchData() async {
      var response = await http.get(url);  // 不阻塞！
      setState(() {
        data = response.body;
      });
    }
    ```

- 网络请求执行流

  - ```java
    1. Dart 代码调用 http.get()
    2. 请求被交给 IO Thread 或操作系统处理
    3. UI Thread 继续执行其他代码（不等待）
    4. 网络响应回来后，回调被放入 Event Queue
    5. Event Loop 取出回调，执行 then/await 后面的代码
    ```

#### 3.flutter UI线程事件循环

- ```java
  ┌─────────────────────────────────────────────────────────────────┐
  │                    Dart 单线程模型                              │
  │                                                                 │
  │   ┌─────────────────────────────────────────────────────────┐   │
  │   │                    Event Loop                           │   │
  │   │                                                         │   │
  │   │   while (true) {                                        │   │
  │   │       // 1️⃣ 先处理微任务队列（优先级高）                  │   │
  │   │       while (microtaskQueue.isNotEmpty) {               │   │
  │   │           microtaskQueue.removeFirst().run();           │   │
  │   │       }                                                 │   │
  │   │                                                         │   │
  │   │       // 2️⃣ 再处理事件队列                              │   │
  │   │       if (eventQueue.isNotEmpty) {                      │   │
  │   │           eventQueue.removeFirst().run();               │   │
  │   │       }                                                 │   │
  │   │   }                                                     │   │
  │   │                                                         │   │
  │   └─────────────────────────────────────────────────────────┘   │
  │                                                                 │
  │   两个队列：                                                    │
  │   ┌─────────────────┐  ┌─────────────────────────────────────┐ │
  │   │ Microtask Queue │  │         Event Queue                 │ │
  │   │ (微任务队列)     │  │         (事件队列)                   │ │
  │   │                 │  │                                     │ │
  │   │ - scheduleMicro │  │ - I/O 完成回调                      │ │
  │   │ - Future.then   │  │ - Timer 回调                        │ │
  │   │   (部分情况)    │  │ - 用户输入事件                       │ │
  │   │                 │  │ - 绘制事件                          │ │
  │   └─────────────────┘  └─────────────────────────────────────┘ │
  │                                                                 │
  └─────────────────────────────────────────────────────────────────┘
  
  ```

### 5.2 Future - 异步任务

#### 1.需求

执行异步网络任务，成功后再UI更新，失败UI也要更新

#### 2.代码

- 方式一：then链式调用
  - ```java
    Future<String> fetchData() {
      return http.get(Uri.parse('https://api.example.com/data'))
          .then((response) => response.body);
    }
    
    // 使用
    fetchData()
        .then((data) => print('成功: $data'))
        .catchError((error) => print('失败: $error'));
    
    ```

- 方式 2：async/await（推荐）

  - ```java
    Future<void> loadData() async {
      try {
        // await 会"暂停"这里，但不会阻塞 UI
        // 实际上是把后面的代码注册为回调
        http.Response response = await http.get(Uri.parse('https://api.example.com/data'));
        
        setState(() {
          widgets = jsonDecode(response.body);
        });
      } catch (e) {
        print('错误: $e');
      }
    }
    
    ```

- await 本质是"语法糖"，把后面的代码变成 then 回调。

  - ```java
    // 这段代码
    Future<void> loadData() async {
      var response = await http.get(url);
      print(response.body);
    }
    
    // 等价于
    Future<void> loadData() {
      return http.get(url).then((response) {
        print(response.body);
      });
    }
    
    ```

#### 3.原理

- 这是原理

  - ```java
    Future + await 的本质：
    
    1. await = then 的语法糖
    
    2. Future 内的异步操作（如网络请求）
       → 调度到 IO Thread / 系统线程执行
    
    3. 执行完成后
       → 回调被放入队列（微任务队列或事件队列）
       → Event Loop 取出
       → 在 UI Thread 执行 then / await 后面的代码
    ```

### 5.3 Isolate - 多线程

#### 1.需求

如果线程不够用，我们还是想开自己的线程呢？

#### 2.方案

解决： 使用 Isolate，在独立线程中执行计算。

#### 3.原理

- Isolate 之间不共享内存，只能通过消息通信。

  - ```java
    ┌─────────────────────────────────────────────────────────────────┐
    │                                                                 │
    │   Main Isolate (主线程)              Worker Isolate (工作线程)  │
    │   ┌─────────────────────┐            ┌─────────────────────┐    │
    │   │                     │            │                     │    │
    │   │  UI 渲染            │            │  CPU 密集计算       │    │
    │   │  事件处理           │            │  (不影响 UI)        │    │
    │   │                     │            │                     │    │
    │   │  EventLoop          │            │  EventLoop          │    │
    │   │                     │            │                     │    │
    │   └──────────┬──────────┘            └──────────┬──────────┘    │
    │              │                                  │               │
    │              │         SendPort / ReceivePort   │               │
    │              │◄────────────────────────────────►│               │
    │              │         (消息传递，不共享内存)    │               │
    │                                                                 │
    └─────────────────────────────────────────────────────────────────┘
    
    ```

#### 4.代码

- 代码如下：

  - ```java
    import 'dart:isolate';
    
    // 在 Isolate 中执行的函数
    void heavyComputation(SendPort sendPort) {
      // 模拟耗时计算
      int result = 0;
      for (int i = 0; i < 1000000000; i++) {
        result += i;
      }
      
      // 把结果发送回主线程
      sendPort.send(result);
    }
    
    // 主线程调用
    Future<void> runInIsolate() async {
      // 创建接收端口
      ReceivePort receivePort = ReceivePort();
      
      // 创建 Isolate，传入函数和发送端口
      await Isolate.spawn(heavyComputation, receivePort.sendPort);
      
      // 等待结果
      int result = await receivePort.first;
      
      print('计算结果: $result');
    }
    ```

#### 5.疑问 lambda 和 闭包

疑问：

- 闭包：我们上面的这些通信是通过传递回调的形式，可是回调需要对应的context啊，比如成员变量属性。他回来执行的时候，怎么记录这个成员变量的熟悉呢？
- lambda：lambda和闭包的关系是什么？

闭包：

- 闭包的本质

  - ```java
    闭包 = 函数 + 它捕获的变量环境
    
    当你定义一个匿名函数/lambda 时：
    1. Dart 创建一个闭包对象
    2. 这个对象包含：
       - 函数代码的引用
       - 捕获的变量的引用（不是值拷贝）
    ```

lambda？

- lambda是语法糖，方便创建闭包

- ```java
  Lambda = 闭包的语法糖
  
  Lambda 表达式
      │
      │ 编译后
      ▼
  闭包对象
      │
      ├── 函数代码（对象的方法）
      │
      └── 捕获的变量引用
  ```

小结

- ```java
  Lambda = 创建闭包对象的简洁语法
  闭包 = 一个新的堆中的对象，持有  函数 + 捕获的变量引用
  
  所以：Lambda 是方便创建和传递闭包的语法糖。
  ```
