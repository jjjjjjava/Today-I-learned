## 02.基础概念理解

### 2.1 Flutter Channel 是什么？

Flutter 本质是一套 UI 框架，它只负责渲染界面。但实际 App 开发中，我们经常需要：

- 调用相机、GPS、传感器等硬件
- 访问本地文件系统
- 使用原生 SDK（微信支付、推送等）
- 获取设备信息

这些能力 Flutter 本身没有，必须通过 原生平台 来实现。

Platform Channel 就是 Flutter 官方提供的 跨端通信机制，让 Dart 代码能够与 Android/iOS 原生代码相互调用。

```
┌─────────────────┐                    ┌─────────────────┐
│   Flutter/Dart  │  ◄──── Channel ────►  │  Android/iOS   │
│   (UI 渲染)      │                    │  (平台能力)      │
└─────────────────┘                    └─────────────────┘
```

### 2.2 三种Channel类型

| Channel 类型        | 通信模式                 | 适用场景                               | 类比      | 使用频率 |
| ------------------- | ------------------------ | -------------------------------------- | --------- | -------- |
| MethodChannel       | 一次性调用，有返回值     | 调用原生方法（如获取 Token、弹 Toast） | HTTP 请求 | 90%      |
| EventChannel        | 持续数据流，原生主动推送 | 监听传感器、GPS、电量变化              | WebSocket | 8%       |
| BasicMessageChannel | 双向消息传递             | 快速连续传递简单数据                   | 消息队列  | 2%       |

补充说明：各 Channel 使用频率排序：`MethodChannel（90%）> EventChannel（8%）> BasicMessageChannel（2%）`，其中 MethodChannel 因满足绝大多数 “单次原生能力调用” 的业务需求，成为日常 Flutter 开发中最主流的通道类型。

### 2.3. MethodChannel 通信特点

```
// Flutter 端调用
final result = await _channel.invokeMethod('getUserToken', params);
```

关键特点：

- 异步通信：使用 await 等待结果
- 双向调用：Flutter 可以调 Native，Native 也可以调 Flutter
- 自动编解码：Map、List、基本类型自动转换
- 一对一匹配：通过 Channel 名称 + 方法名定位

### 3.2 Flutter 端封装（异常处理）

#### 1.常见异常类型

在 Flutter 端调用 MethodChannel 时，可能遇到三种异常：

- | 异常类型               | 触发原因                   | Android 端对应                       |
  | ---------------------- | -------------------------- | ------------------------------------ |
  | PlatformException      | 原生端主动报错             | result.error("CODE", "msg", details) |
  | MissingPluginException | Channel 未注册或名称不匹配 | 没有对应的 Handler                   |
  | TypeError              | 返回值类型转换失败         | 返回了错误的数据类型                 |

这是处理代码

- ```
  try {
    final result = await _channel.invokeMethod('someMethod', params);
  } on PlatformException catch (e) {
    // 1️⃣ 平台异常：原生端调用 result.error() 时抛出
    print('错误码: ${e.code}');
    print('错误信息: ${e.message}');
    print('详细信息: ${e.details}');
  } on MissingPluginException catch (e) {
    // 2️⃣ 插件未找到：Channel 名称不匹配或未注册
    print('未找到插件: ${e.message}');
  } on TypeError catch (e) {
    // 3️⃣ 类型转换错误：返回值类型与期望不符
    print('类型错误: $e');
  }
  
  ```

#### 2.封装示例：通用调用方法

```
import 'package:flutter/services.dart';

class PlatformService {
  static const MethodChannel _channel = MethodChannel('com.ovopark.flutter/native_data');

  /// 通用调用方法，统一处理异常
  static Future<T?> invokeMethod<T>(String method, [dynamic arguments]) async {
    try {
      final T? result = await _channel.invokeMethod<T>(method, arguments);
      return result;
    } on PlatformException catch (e) {
      // 原生端返回错误
      print('❌ PlatformException: ${e.code} - ${e.message}');
      return null;
    } on MissingPluginException catch (e) {
      // Channel 未注册
      print('❌ MissingPluginException: ${e.message}');
      return null;
    } on TypeError catch (e) {
      // 类型转换失败
      print('❌ TypeError: $e');
      return null;
    } catch (e) {
      // 兜底：其他未知异常
      print('❌ Unknown Error: $e');
      return null;
    }
  }

  // 具体业务方法
  static Future<String?> getUserToken() => invokeMethod<String>('getUserToken');
  
  static Future<Map<String, dynamic>?> getUserInfo() => 
      invokeMethod<Map<String, dynamic>>('getUserInfo');
}
```

### 3.3 Android 端封装

#### 1.基础封装

```
class FlutterMethodChannel(private val context: Context) : MethodCallHandler {
    
    companion object {
        const val CHANNEL_NAME = "com.ovopark.flutter/native_data"
        
        // 方法名常量化，避免拼写错误
        const val METHOD_GET_USER_TOKEN = "getUserToken"
        const val METHOD_GET_USER_ID = "getUserId"
    }

    override fun onMethodCall(call: MethodCall, result: Result) {
        when (call.method) {
            METHOD_GET_USER_TOKEN -> handleGetUserToken(result)
            METHOD_GET_USER_ID -> handleGetUserId(result)
            else -> result.notImplemented()
        }
    }
    
    // 每个方法单独抽取，保持 onMethodCall 简洁
    private fun handleGetUserToken(result: Result) {
        try {
            val token = LoginUtils.cachedUserToken
            result.success(token)
        } catch (e: Exception) {
            result.error("TOKEN_ERROR", "获取token失败: ${e.message}", null)
        }
    }
}

```

#### 2. 进阶封装：接口化

当方法越来越多时，可以用接口进一步解耦：

```
// 定义方法处理接口
interface MethodHandler {
    fun methodName(): String
    fun handle(call: MethodCall, result: Result)
}

// 每个方法独立实现
class GetUserTokenHandler : MethodHandler {
    override fun methodName() = "getUserToken"
    override fun handle(call: MethodCall, result: Result) {
        result.success(LoginUtils.cachedUserToken)
    }
}

// 主 Handler 通过注册管理
class FlutterMethodChannel : MethodCallHandler {
    private val handlers = mutableMapOf<String, MethodHandler>()
    
    init {
        register(GetUserTokenHandler())
        register(GetUserIdHandler())
    }
    
    private fun register(handler: MethodHandler) {
        handlers[handler.methodName()] = handler
    }
    
    override fun onMethodCall(call: MethodCall, result: Result) {
        handlers[call.method]?.handle(call, result) ?: result.notImplemented()
    }
}

```

## 04.EventChannel

### 4.1 使用示例：监听陀螺仪数据

#### 1.核心原理

```
EventChannel 结构：
├── StreamHandler（接口）
│   ├── onListen()  → Flutter 开始监听时触发，获得 eventSink
│   └── onCancel()  → Flutter 取消监听时触发，清理资源
│
└── EventSink（对象，在 onListen 中获得）
    ├── success(data)    → 发送数据给 Flutter
    ├── error(code, msg) → 发送错误给 Flutter
    └── endOfStream()    → 主动结束流（Flutter 端触发 onDone）

Flutter 端：
eventChannel.receiveBroadcastStream().listen(
  (data) { },      // 对应 eventSink.success()
  onError: (e) { }, // 对应 eventSink.error()
  onDone: () { },   // 对应 eventSink.endOfStream()
)
```

#### 2.Android端实现 

看看Android端代码：这里实现了StreamHandler和SensorEventListener两个接口

```
// 实现 StreamHandler 接口
class GyroscopeEventHandler(private val context: Context) : 
    EventChannel.StreamHandler, SensorEventListener {
    
    private var sensorManager: SensorManager? = null
    private var gyroscope: Sensor? = null
    private var eventSink: EventChannel.EventSink? = null  // 🔑 事件发送器

    // Flutter 开始监听时调用
    override fun onListen(arguments: Any?, events: EventChannel.EventSink?) {
        eventSink = events
        
        // 注册传感器监听
        sensorManager = context.getSystemService(Context.SENSOR_SERVICE) as SensorManager
        gyroscope = sensorManager?.getDefaultSensor(Sensor.TYPE_GYROSCOPE)
        sensorManager?.registerListener(this, gyroscope, SensorManager.SENSOR_DELAY_NORMAL)
    }

    // Flutter 停止监听时调用
    override fun onCancel(arguments: Any?) {
        sensorManager?.unregisterListener(this)
        eventSink = null
    }

    // 传感器数据变化时，推送给 Flutter
    override fun onSensorChanged(event: SensorEvent?) {
        event?.let {
            val data = mapOf(
                "x" to it.values[0],
                "y" to it.values[1],
                "z" to it.values[2]
            )
            eventSink?.success(data)  // 🔑 发送数据给 Flutter
        }
    }

    override fun onAccuracyChanged(sensor: Sensor?, accuracy: Int) {}
}

```

## 05.底层原理

### 5.1 整体流程和原理

#### 1.原理

很简单，将我们的方法名称和参数通过二进制编解码 + JNI 桥接实现跨语言通信。

比如：当我们调用invokeMethod时，本质是用codec将方法和参数编译成二进制形式；然后借助底层c++层处理，Engine 层就是个"传话筒"，把 Dart 的二进制消息通过 JNI 传给 Android；然后Android端通过Messenger找到对应的Handler并进行配置，然后经过解码调用Handler处理，最终将结果通过这一个链路回复。

#### 2.流程

```
┌─────────────────────────────────────────────────────────────────┐
│                    Framework 层 (Dart)                          │
│  MethodChannel → MethodCall → MethodCodec → BinaryMessenger     │
└─────────────────────────────────│───────────────────────────────┘
                                  │ 编码后的二进制数据
                                  ▼
┌─────────────────────────────────────────────────────────────────┐
│                    Engine 层 (C++)                              │
│  dart:ui → PlatformChannel → JNI                                │
└─────────────────────────────────│───────────────────────────────┘
                                  │
                                  ▼
┌─────────────────────────────────────────────────────────────────┐
│                    Embedder 层 (Android/Kotlin)                 │
│  FlutterJNI → DartMessenger → MethodChannel → Handler           │
└─────────────────────────────────────────────────────────────────┘

```

### 5.2 Framework 层 (Dart 端)

#### 1.MethodChannel 类

```
// Flutter SDK: packages/flutter/lib/src/services/platform_channel.dart

class MethodChannel {
  final String name;           // Channel 名称
  final MethodCodec codec;     // 编解码器（默认 StandardMethodCodec）
  final BinaryMessenger binaryMessenger;  // 二进制信使

  Future<T?> invokeMethod<T>(String method, [dynamic arguments]) {
    return _invokeMethod<T>(method, missingOk: false, arguments: arguments);
  }

  Future<T?> _invokeMethod<T>(String method, {required bool missingOk, dynamic arguments}) async {
    // 1️⃣ 创建 MethodCall 对象（方法名 + 参数）
    // 2️⃣ 使用 codec 编码成二进制 ByteData
    final ByteData input = codec.encodeMethodCall(MethodCall(method, arguments));
    
    // 3️⃣ 通过 BinaryMessenger 发送 （这里的name是通道名）
    final ByteData? result = await binaryMessenger.send(name, input);
    
    // 4️⃣ 解码返回结果
    if (result == null) {
      if (missingOk) return null;
      throw MissingPluginException('No implementation found for method $method on channel $name');
    }
    return codec.decodeEnvelope(result) as T?;
  }
}

```

#### 2.关键类说明

| 类名            | 作用                               |
| --------------- | ---------------------------------- |
| MethodCall      | 封装方法调用信息（方法名 + 参数）  |
| MethodCodec     | 编解码器，将 MethodCall 转成二进制 |
| BinaryMessenger | 二进制信使，负责实际发送           |

### 5.3 Engine 层 (C++)

这层是 Flutter 引擎，用 C++ 实现，我们简单了解流程：

```
Dart 端 binaryMessenger.send()
    ↓
dart:ui 库（Dart 与 C++ 的桥梁）
    ↓
PlatformConfiguration::SendPlatformMessage()  // C++
    ↓
Shell::OnEngineHandlePlatformMessage()
    ↓
PlatformViewAndroid::HandlePlatformMessage()
    ↓
JNI 调用 Java 层
    ↓
FlutterJNI.handlePlatformMessage()  // 进入 Android 层

```

核心理解：Engine 层就是个"传话筒"，把 Dart 的二进制消息通过 JNI 传给 Android。

### 5.4 Embedder 层 (Android 端)

#### 1.FlutterJNI → DartMessenger

```
// FlutterJNI.java
public void handlePlatformMessage(String channel, ByteBuffer message, int replyId) {
    // 转发给 platformMessageHandler（即 DartMessenger）
    platformMessageHandler.handleMessageFromDart(channel, message, replyId);
}
```

#### 2.DartMessenger 分发消息

```
// DartMessenger.java
public void handleMessageFromDart(String channel, ByteBuffer message, int replyId) {
    // 根据 channel 名称找到对应的 Handler
    BinaryMessageHandler handler = messageHandlers.get(channel);
    if (handler != null) {
        handler.onMessage(message, reply -> {
            // 回复结果给 Dart
            flutterJNI.invokePlatformMessageResponseCallback(replyId, reply);
        });
    }
}

```

### 6.1 FlutterBoost 路由通信

用途：Flutter 页面跳转到原生页面，或原生跳转到 Flutter 页面

#### 1.Flutter 端调用

```

BoostNavigator.instance.push(

#### 2.Android 端处理 (WDZBoostDelegate.kt)

```
class WDZBoostDelegate : FlutterBoostDelegate {
    
    // Flutter 要跳转原生页面时调用
    override fun pushNativeRoute(options: FlutterBoostRouteOptions) {
        when (options.pageName()) {
            "openShopList" -> {
                // 打开原生门店列表页面
                val intent = Intent(activity, WdzFlutterActivity::class.java)
                intent.putExtra("data", options.arguments())
                activity.startActivityForResult(intent, options.requestCode())
            }
            "openVideoStoreTour" -> {
                // 打开视频巡店
                CommonIntentUtils.goToPlayVideo(...)
            }
            // ... 更多页面
        }
    }
    
    // 原生要跳转 Flutter 页面时调用
    override fun pushFlutterRoute(options: FlutterBoostRouteOptions) {
        val intent = FlutterBoostActivity.CachedEngineIntentBuilder(...)
            .url(options.pageName())
            .urlParams(options.arguments())
            .build(activity)
        activity.startActivity(intent)
    }
}
```

#### 3.原理

Flutter 跳转到 Android：

- ```
  当前 FlutterActivity → startActivity() → 新的原生 Activity
  ```

Android 跳转到 Flutter：

- ```
  当前 Activity → startActivity() → 新的 FlutterBoostActivity（承载 Flutter Widget）
  ```

但是有一个细节，FlutterBoost 会进行Engine 复用 + Surface 切换，避免了每次都重新初始化 Dart VM 和加载 Flutter 代码的开销。

- 这是代码

- ```
  // WDZBoostDelegate.kt
  override fun pushFlutterRoute(options: FlutterBoostRouteOptions) {
      val intent = FlutterBoostActivity.CachedEngineIntentBuilder(activityClass)
          .destroyEngineWithActivity(false)  // 🔑 不销毁引擎，复用！
          .url(options.pageName())           // 告诉 Flutter 显示哪个页面
          .urlParams(options.arguments())
          .build(activity)
      activity.startActivity(intent)
  }
  
  ```

- 对应如下图

- ```
  ┌─────────────────────────────────────────────────────────────────┐
  │                     FlutterEngine（全局唯一）                    │
  │  ┌─────────────────────────────────────────────────────────┐   │
  │  │  Flutter Widget 树                                       │   │
  │  │  ├── MainPage                                           │   │
  │  │  ├── ShopListPage                                       │   │
  │  │  └── ...                                                │   │
  │  └─────────────────────────────────────────────────────────┘   │
  └─────────────────────────────────────────────────────────────────┘
                                ▲
                                │ 复用
                                │
  ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
  │ FlutterBoost │    │ FlutterBoost │    │ FlutterBoost │
  │ Activity A   │    │ Activity B   │    │ Activity C   │
  │ (显示 MainPage)│    │ (显示 ShopList)│    │ (显示 ...)   │
  └──────────────┘    └──────────────┘    └──────────────┘
  
  ```

- 这是流程

- ```
  新建 FlutterActivity 
      → 复用 FlutterEngine 
      → Engine attach 到新 Activity 的 Surface 
      → 通过路由切换 Widget 
      → 在新 Surface 上渲染
  ```
