## 03.基础部分

### 3.1 状态

#### 1.命令式 UI vs 响应式 UI

状态的概念要从两种UI的设计思想说起，他们分别是命令式UI和响应式UI

这是命令式UI，我们手动直接更改UI的属性，缺点是耦合度高，复杂度上来不好统一管理，优点是直接，高效

- ```
  // Android 传统方式 - 手动控制 UI
  TextView textView = findViewById(R.id.text);
  textView.setText("新文本");  // 直接操作 UI
  textView.setVisibility(View.VISIBLE);  // 直接改变 UI 属性
  
  ```

这是响应式 UI（Flutter）

- ```
  // Flutter 方式 - 声明式
  class MyWidget extends StatefulWidget {
    @override
    _MyWidgetState createState() => _MyWidgetState();
  }
  
  class _MyWidgetState extends State<MyWidget> {
    String _text = "旧文本";  // 👈 状态
    
    @override
    Widget build(BuildContext context) {
      return Text(_text);  // 👈 UI = f(state)
    }
    
    void updateText() {
      setState(() {
        _text = "新文本";  // 👈 只改状态，UI 自动响应
      });
    }
  }
  
  ```

UI = f(State)，即 UI 是状态的函数。我们只负责控制状态的改变，当状态改变时，框架会自动重新计算并更新 UI。

#### 2.全局状态和局部状态

局部状态就是单个Widget内部的状态，比如：点击button，更改他的选中状态

- ```
  class CheckboxWidget extends StatefulWidget {
    @override
    _CheckboxWidgetState createState() => _CheckboxWidgetState();
  }
  
  class _CheckboxWidgetState extends State<CheckboxWidget> {
    bool _isChecked = false;  // 👈 局部状态
    
    @override
    Widget build(BuildContext context) {
      return Checkbox(
        value: _isChecked,
        onChanged: (value) => setState(() => _isChecked = value!),
      );
    }
  }
  
  ```

全局状态，在多个Widget中共享的状态。比如：我们在顶级的Widget中获取状态，然后他的多个子Widget处都需要用到

- ```
  // 1. 定义全局状态模型
  class UserModel extends ChangeNotifier {
    String _userName = "";
    bool _isLoggedIn = false;
    
    String get userName => _userName;
    bool get isLoggedIn => _isLoggedIn;
    
    void login(String name) {
      _userName = name;
      _isLoggedIn = true;
      notifyListeners();  // 👈 通知所有监听者
    }
    
    void logout() {
      _userName = "";
      _isLoggedIn = false;
      notifyListeners();
    }
  }
  
  // 2. 在顶层提供
  void main() {
    runApp(
      ChangeNotifierProvider(
        create: (_) => UserModel(),
        child: MyApp(),
      ),
    );
  }
  
  // 3. 在任意页面访问
  class HomePage extends StatelessWidget {
    @override
    Widget build(BuildContext context) {
      final user = Provider.of<UserModel>(context);
      return Text('欢迎 ${user.userName}');
    }
  }
  
  class ProfilePage extends StatelessWidget {
    @override
    Widget build(BuildContext context) {
      final user = Provider.of<UserModel>(context);
      return Text('个人中心 - ${user.userName}');
    }
  }
  ```

#### 3.状态管理的困难

好的，看了局部状态和全局状态的分类。我们需要理解要一个问题，全局状态管理存在哪些困难呢？我们上面是使用了Provider，如果没有他呢？

第一个困难点：状态透传

- ```
  // ❌ 需要一层层传递，非常繁琐
  GrandParent(count: 10)
    └─> Parent(count: 10)
         └─> Child(count: 10)
              └─> GrandChild(count: 10)  // 终于用上了
  
  ```

第二个困难点：状态同步

- ```
  // ❌ A 中 setState，B 如何知道要更新？
  class WidgetA extends StatefulWidget {
    _WidgetAState createState() => _WidgetAState();
  }
  
  class _WidgetAState extends State<WidgetA> {
    int count = 0;
    
    void increment() {
      setState(() => count++);
      // ❌ 如何通知 WidgetB 更新？做不到！
    }
  }
  
  class WidgetB extends StatelessWidget {
    // ❌ 如何获取 WidgetA 的 count？做不到！
  }
  ```

我们在A中setState，B中是不知道被更新的啊。这是为什么呢？

我们得从setState的原理说起

- 每个StatefulWidget 都有自己独立的 State 对象；State 对象由 Element 持有；不同的 Element 持有不同的 State；setState() 只能修改当前 State 对象的数据；也就是说，我们的setState只能让当前的element置为脏，不能影响到其他的element

  - ```
    Widget Tree          Element Tree         State
        │                    │                  │
    ┌───┴───┐            ┌───┴───┐         ┌───┴───┐
    │Widget A│           │Element A│────────│State A│
    └───┬───┘            └───┬───┘         └───────┘
        │                    │
    ┌───┴───┐            ┌───┴───┐         ┌───────┐
    │Widget B│           │Element B│────────│State B│
    └───────┘            └───────┘         └───────┘
    
    ```

那么我们该如何解决这个透传和状态同步的难点呢？Flutter中提供了一个最原始的方案：InheritedWidget，我们将在3.2中看到 

### 3.2 Flutter 原生状态管理方式_InheritedWidget 

#### 1.透传如何解决？

核心思想： 把数据放在"顶层"，子 Widget 可以直接"向上查找"获取。

- ```
          UserData (InheritedWidget，是一个无状态的Widget)  👈 数据在这里
               │
               │
            MyApp
               │
               │
            HomePage
               │
          ┌────┴────┐
          │         │
     HeaderWidget  ContentWidget
          │         │
       可以直接    可以直接
       向上查找    向上查找
        
  ```

看看代码

- 第一步：创建InheritedWidget

  - ```
    // InheritedWidget 就像一个"数据容器"
    class UserData extends InheritedWidget {
      // 1️⃣ 定义要共享的数据
      final String userName;
      
      // 2️⃣ 构造函数
      const UserData({
        required this.userName,
        required Widget child,  // 👈 child 是它的子 Widget 树
      }) : super(child: child);
      
      // 3️⃣ 提供一个静态方法，让子 Widget 方便地获取数据
      static UserData? of(BuildContext context) {
        // 这行代码的作用：向上查找最近的 UserData
        return context.dependOnInheritedWidgetOfExactType<UserData>();
      }
      
      // 4️⃣ 决定什么时候通知子 Widget 更新
      @override
      bool updateShouldNotify(UserData oldWidget) {
        // 如果 userName 变了，返回 true，通知子 Widget 重建
        return userName != oldWidget.userName;
      }
    }
    
    ```

- 第二步：在顶层提供数据

  - ```
    void main() {
      runApp(
        // 👇 用 UserData 包裹整个应用
        UserData(
          userName: "张三",  // 👈 数据在这里
          child: MyApp(),    // 👈 所有子 Widget
        ),
      );
    }
    
    class MyApp extends StatelessWidget {
      @override
      Widget build(BuildContext context) {
        return MaterialApp(
          home: HomePage(),  // 👈 不需要传递 userName 了！
        );
      }
    }
    ```

  - 此时，Widget 树结构如下

  - ```
    UserData (userName: "张三")
        │
        └─ MyApp
             │
             └─ MaterialApp
                  │
                  └─ HomePage
    
    ```

- 第三步：子 Widget 访问数据

  - ```
    class HomePage extends StatelessWidget {
      @override
      Widget build(BuildContext context) {
        return Scaffold(
          body: Column(
            children: [
              HeaderWidget(),   // 👈 不需要传递参数
              ContentWidget(),  // 👈 不需要传递参数
            ],
          ),
        );
      }
    }
    
    class HeaderWidget extends StatelessWidget {
      @override
      Widget build(BuildContext context) {
        // 👇 通过 context 向上查找 UserData
        final userData = UserData.of(context);
        
        // 👇 直接使用数据
        return Text('欢迎 ${userData?.userName}');
      }
    }
    
    class ContentWidget extends StatelessWidget {
      @override
      Widget build(BuildContext context) {
        // 👇 这里也可以直接获取
        final userData = UserData.of(context);
        
        return Text('用户：${userData?.userName}');
      }
    }
    ```

那么原理呢？

- 要理解context.dependOnInheritedWidgetOfExactType<UserData>() 做了什么？

  - ```
    static UserData? of(BuildContext context) {
      return context.dependOnInheritedWidgetOfExactType<UserData>();
    }
    ```

- context 是什么？

  - context 就是当前 Widget 对应的 Element
  - Element 持有对父 Element 的引用

- 向上查找过程：

  - ```
    当前 Widget (HeaderWidget)
        │ context
        ↓
    当前 Element
        │ parent
        ↓
    父 Element (Column)
        │ parent
        ↓
    父父 Element (Scaffold)
        │ parent
        ↓
    ... 继续向上
        │
        ↓
    UserData Element  👈 找到了！
    ```

  - 类似Android

  - ```
    // 类似于 View 的 getParent() 向上查找
    View currentView = findViewById(R.id.header);
    ViewGroup parent = (ViewGroup) currentView.getParent();
    ViewGroup grandParent = (ViewGroup) parent.getParent();
    // ... 一直向上找，直到找到目标 ViewGroup
    ```

#### 2.状态同步如何解决？

我们解决了状态透传的问题，通过一个顶层的Widget + 查找parent context，最终获取了顶层Widget的状态。

那么状态同步呢？ InheritedWidget 本身是不可变的（Immutable），要修改数据需要配合 StatefulWidget。我们使用一个StatefulWidget封装他

这是完整的代码

- 第一步：构建StatefulWidget，提供状态和修改状态的方法

  - ```
    // ========== 第1部分：StatefulWidget 持有可变状态 ==========
    class UserDataProvider extends StatefulWidget {
      final Widget child;
      
      const UserDataProvider({required this.child});
      
      @override
      _UserDataProviderState createState() => _UserDataProviderState();
    }
    
    class _UserDataProviderState extends State<UserDataProvider> {
      // 👇 可变的状态
      String _userName = "张三";
      
      // 👇 提供修改方法
      void updateUserName(String newName) {
        setState(() {
          _userName = newName;  // 修改状态
        });
        // setState 会触发 build() 重新执行
      }
      
      @override
      Widget build(BuildContext context) {
        // 👇 每次 build 都创建新的 InheritedWidget
        return UserData(
          userName: _userName,           // 👈 传递数据
          updateUserName: updateUserName, // 👈 传递修改方法
          child: widget.child,
        );
      }
    }
    ```

- 第二步：通过一层状态透传，让InheritedWidget持有可变的状态并提供修改方法（这里是因为只有InheritedWidget能够直接向下层传递）

  - ```
    // ========== 第2部分：InheritedWidget 传递数据和方法 ==========
    class UserData extends InheritedWidget {
      final String userName;
      final void Function(String) updateUserName;  // 👈 修改方法
      
      const UserData({
        required this.userName,
        required this.updateUserName,
        required Widget child,
      }) : super(child: child);
      
      static UserData? of(BuildContext context) {
        return context.dependOnInheritedWidgetOfExactType<UserData>();
      }
      
      @override
      bool updateShouldNotify(UserData oldWidget) {
        // 👇 比较新旧数据，决定是否通知子 Widget
        return userName != oldWidget.userName;
      }
    }
    
    // ========== 第3部分：使用 ==========
    void main() {
      runApp(
        UserDataProvider(  // 👈 使用 Provider 而不是直接用 UserData
          child: MyApp(),
        ),
      );
    }
    
    class MyApp extends StatelessWidget {
      @override
      Widget build(BuildContext context) {
        return MaterialApp(
          home: HomePage(),
        );
      }
    }
    
    class HomePage extends StatelessWidget {
      @override
      Widget build(BuildContext context) {
        // 👇 获取数据和方法
        final userData = UserData.of(context);
        
        return Scaffold(
          body: Column(
            children: [
              // 显示用户名
              Text('用户名：${userData?.userName}'),
              
              // 修改用户名的按钮
              ElevatedButton(
                onPressed: () {
                  // 👇 调用修改方法
                  userData?.updateUserName("李四");
                },
                child: Text('改名为李四'),
              ),
            ],
          ),
        );
      }
    }
    
    ```

好，我们来看看流程

- 首先是代码对应的Widget树

  - ```
    UserDataProvider (StatefulWidget)
        │
        └─ _UserDataProviderState (State)
            │ 持有：_userName = "张三"
            │ 持有：updateUserName() 方法
            │
            └─ build() 返回 ↓
                │
            UserData (InheritedWidget)
                │ 接收：userName = "张三"
                │ 接收：updateUserName 函数引用
                │
                └─ child
                    │
                MyApp
                    │
                MaterialApp
                    │
                HomePage
                    │
                ├─ HeaderWidget
                └─ ContentWidget
    
    ```

- 数据获取流程

  - ```
    // 在 HeaderWidget 中
    class HeaderWidget extends StatelessWidget {
      @override
      Widget build(BuildContext context) {
        // 1️⃣ 调用 UserData.of(context)
        final userData = UserData.of(context);
        
        // 2️⃣ 内部执行：
        //    context.dependOnInheritedWidgetOfExactType<UserData>()
        
        // 3️⃣ Flutter 向上遍历 Element 树：
        //    HeaderWidget Element
        //        ↓ parent
        //    Column Element
        //        ↓ parent
        //    Scaffold Element
        //        ↓ parent
        //    ... 继续向上
        //        ↓ parent
        //    UserData Element  👈 找到了！
        
        // 4️⃣ 返回 UserData 实例
        //    包含：userName 和 updateUserName 方法
        
        // 5️⃣ 建立依赖关系
        //    HeaderWidget 依赖 UserData
        //    当 UserData 更新时，HeaderWidget 会收到通知
        
        return Text(userData?.userName ?? "");
      }
    }
    
    ```

- 数据修改过程

  - ```
    // 用户点击按钮
    ElevatedButton(
      onPressed: () {
        // 1️⃣ 调用 updateUserName("李四")
        userData?.updateUserName("李四");
        
        // 2️⃣ 这是一个函数引用（闭包），指向：
        //    _UserDataProviderState.updateUserName()
        
        // 3️⃣ 执行 _UserDataProviderState.updateUserName()
        void updateUserName(String newName) {
          setState(() {
            _userName = newName;  // "张三" → "李四"
          });
        }
        
        // 4️⃣ setState() 触发 _UserDataProviderState.build()
        @override
        Widget build(BuildContext context) {
          return UserData(
            userName: _userName,        // 👈 新值 "李四"
            updateUserName: updateUserName,
            child: widget.child,
          );
        }
        
        // 5️⃣ 创建新的 UserData 实例
        //    oldWidget: UserData(userName: "张三")
        //    newWidget: UserData(userName: "李四")
        
        // 6️⃣ Flutter 调用 updateShouldNotify()
        @override
        bool updateShouldNotify(UserData oldWidget) {
          return userName != oldWidget.userName;
          // "李四" != "张三" → 返回 true
        }
        
        // 7️⃣ 通知所有依赖 UserData 的 Widget
        //    - HeaderWidget 依赖了 → 重建
        //    - ContentWidget 依赖了 → 重建
        //    - OtherWidget 没依赖 → 不重建
        
        // 8️⃣ HeaderWidget.build() 重新执行
        @override
        Widget build(BuildContext context) {
          final userData = UserData.of(context);
          return Text(userData?.userName ?? "");  // 显示 "李四"
        }
      },
      child: Text("修改用户名"),
    )
    
    ```

那么原理呢？原理是：通过StateFulWidget重建InheritedWidget并触发其updateShouldNotify方法，所以核心是updateShouldNotify

让我们看看updateShouldNotify 的原理和通知机制

- 依赖关系的建立：当子 Widget 调用 of(context) 时

  - ```
    // 子 Widget 中
    final userData = UserData.of(context);
    
    // of() 方法内部
    static UserData? of(BuildContext context) {
      return context.dependOnInheritedWidgetOfExactType<UserData>();
      //              ↑
      //              关键方法：建立依赖关系
    }
    
    dependOnInheritedWidgetOfExactType() 做了什么？
    
    
    // Flutter 框架内部（简化版）
    T? dependOnInheritedWidgetOfExactType<T extends InheritedWidget>() {
      // 1️⃣ 向上查找 InheritedWidget
      final InheritedElement? ancestor = _inheritedWidgets[T];
      
      // 2️⃣ 建立依赖关系（关键！）
      if (ancestor != null) {
        // 将当前 Element 注册到 InheritedElement 的依赖列表中
        ancestor._dependents.add(this);  // this 是当前 Element
        //        ↑
        //        InheritedElement 维护了一个依赖者列表（感觉像是element的引用列表）
      }
      
      // 3️⃣ 返回 InheritedWidget
      return ancestor?.widget as T?;
    }
    
    ```

  - ok，此时我们有了如下的依赖者列表

  - ```
    UserData (InheritedElement)
        │
        ├─ _dependents (依赖者列表)
        │   ├─ HeaderWidget Element  👈 调用了 of(context)
        │   ├─ ContentWidget Element  👈 调用了 of(context)
        │   └─ ProfileWidget Element  👈 调用了 of(context)
        │
        └─ OtherWidget Element  👈 没调用 of(context)，不在列表中
    
    ```

- 通知流程

  - ```
    // 1️⃣ setState() 触发 StatefulWidget 重建
    _UserDataProviderState.setState(() {
      _userName = "李四";
    });
    
    // 2️⃣ build() 创建新的 InheritedWidget
    @override
    Widget build(BuildContext context) {
      return UserData(
        userName: _userName,  // 新值
        child: widget.child,
      );
    }
    
    // 3️⃣ Flutter 框架检测到 InheritedWidget 更新
    // 调用 updateShouldNotify()
    @override
    bool updateShouldNotify(UserData oldWidget) {
      return userName != oldWidget.userName;  // 返回 true
    }
    
    // 4️⃣ 如果返回 true，Flutter 框架执行通知逻辑
    // （Flutter 框架内部，简化版）
    void _notifyDependents(InheritedWidget oldWidget) {
      // 遍历依赖者列表
      for (Element dependent in _dependents) {
        // 👇 将依赖者标记为"脏"（需要重建）
        dependent.didChangeDependencies();
        //        ↑
        //        这个方法会触发 Element 的重建
      }
    }
    
    ```

#### 3.闭包

ok，这里还有一个概念：闭包。

我们如何在子Widget中调用方法，更改顶层StatefulWidget的状态？

- 这是我们闭包的传递

  - ```
    class _UserDataProviderState extends State<UserDataProvider> {
      String _userName = "张三";  // 👈 外部变量
      
      // 👇 这是一个闭包
      void updateUserName(String newName) {
        setState(() {
          _userName = newName;  // 👈 访问外部变量
        });
      }
      
      @override
      Widget build(BuildContext context) {
        return UserData(
          userName: _userName,
          updateUserName: updateUserName,  // 👈 传递函数引用
          child: widget.child,
        );
      }
    }
    
    ```

- 其最终会生成一个闭包对象

  - ```
    // Dart 编译器内部会创建一个闭包对象
    class _Closure {
      final _UserDataProviderState _context;  // 👈 持有外部对象引用
      
      _Closure(this._context);
      
      void call(String newName) {
        _context.setState(() {
          _context._userName = newName;  // 通过引用访问
        });
      }
    }
    
    ```


## 04.Provider基础用法

### 4.1 对比：原生方式 vs Provider

```
// ❌ 原生方式：需要写两个类
class UserDataProvider extends StatefulWidget { ... }  // 管理状态
class UserData extends InheritedWidget { ... }         // 传递数据

// ✅ Provider 方式：一个类搞定
class UserModel extends ChangeNotifier {
  String _userName = "张三";
  
  String get userName => _userName;
  
  void updateUserName(String name) {
    _userName = name;
    notifyListeners();  // 👈 相当于 setState + updateShouldNotify
  }
}
```

### 4.2 使用流程

#### 1.创建数据模型（ChangeNotifier）

我们这里以登陆状态为例

```
import 'package:flutter/material.dart';

class LoginStatusModel extends ChangeNotifier {
  bool _isLogin = false;

  bool get isLogin => _isLogin;

  void updateLoginStatus(bool isLogin) {
    _isLogin = isLogin;
    notifyListeners();  // 👈 通知所有监听者
  }
}
```

#### 2.提供状态（ChangeNotifierProvider）

```
void main() {
  runApp(
    ChangeNotifierProvider(
      create: (context) => LoginStatusModel(),  // 👈 创建数据模型
      child: const MyApp(),
    ),
  );
}
```

#### 3.消费状态（三种方式）

- 方式一：Provider.of()
  - ```
    // 获取数据 + 监听变化（会重建）
    final loginStatus = Provider.of<LoginStatusModel>(context);
    
    // 只获取数据，不监听（不会重建）
    final loginStatus = Provider.of<LoginStatusModel>(context, listen: false);
    
    ```

  - listen: true = dependOnInheritedWidgetOfExactType()（建立依赖）

  - listen: false = 只查找，不注册到 _dependents 列表

- 方式二：Consumer（推荐）

  - ```
    Consumer<LoginStatusModel>(
      builder: (context, loginStatus, child) {
        return Text('${loginStatus.isLogin}');
      },
    )
    ```

  - 优点： 只有 Consumer 包裹的部分会重建，缩小刷新范围

- 方式三：context 扩展

  - ```
    // 等价于 Provider.of(context, listen: false)
    context.read<LoginStatusModel>()
    
    // 等价于 Provider.of(context, listen: true)
    context.watch<LoginStatusModel>()
    
    // 细粒度监听（后面讲）
    context.select<LoginStatusModel, bool>((model) => model.isLogin)
    
    ```

### 4.3 性能优化

#### 1.思路

核心问题：不必要的重建

```
class HomePage extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    // ❌ 问题：整个 HomePage 都会因为 loginStatus 变化而重建
    final loginStatus = Provider.of<LoginStatusModel>(context);
    
    return Column(
      children: [
        Text('登录状态: ${loginStatus.isLogin}'),  // 需要重建
        HeavyWidget(),  // 不需要重建，但也被重建了！
        AnotherHeavyWidget(),  // 不需要重建，但也被重建了！
      ],
    );
  }
}
```

#### 2.Provider.of() 的 listen 参数

```
// ✅ 只获取数据，不监听变化（不会触发重建）
final loginStatus = Provider.of<LoginStatusModel>(context, listen: false);

// 适用场景：在按钮点击等事件中调用方法
ElevatedButton(
  onPressed: () {
    // 这里只是调用方法，不需要监听
    Provider.of<LoginStatusModel>(context, listen: false).logout();
  },
  child: Text('退出登录'),
)
```

#### 3.Consumer 缩小刷新范围

```
class HomePage extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        // ✅ 只有这个 Consumer 内部会重建
        Consumer<LoginStatusModel>(
          builder: (context, loginStatus, child) {
            return Text('登录状态: ${loginStatus.isLogin}');
          },
        ),
        HeavyWidget(),  // ✅ 不会重建
        AnotherHeavyWidget(),  // ✅ 不会重建
      ],
    );
  }
}
```

#### 4.Selector 细粒度刷新

当 Model 有多个属性，但你只关心其中一个时：

```
class UserModel extends ChangeNotifier {
  String _name = "张三";
  int _age = 25;
  String _avatar = "url";
  
  // ... getters and setters with notifyListeners()
   set name(String newName) {
    _name = newName;
    notifyListeners(); // 通知监听者数据已更改
  }

  set age(int newAge) {
    _age = newAge;
    notifyListeners();
}

// ❌ Consumer：name、age、avatar 任何一个变化都会重建
Consumer<UserModel>(
  builder: (_, user, __) => Text(user.name),
)

// ✅ Selector：只有 name 变化才重建
Selector<UserModel, String>(
  selector: (_, user) => user.name,  // 👈 只选择 name
  builder: (_, name, __) => Text(name),
)
```

## 05.源码原理

### 5.1 创建部分

#### 1.ChangeNotifier

- 这是我们的代码

  - ```
    class LoginStatusModel extends ChangeNotifier {
      bool _isLogin = false;
    
      bool get isLogin => _isLogin;
    
      void updateLoginStatus(bool isLogin) {
        _isLogin = isLogin;
        notifyListeners();  // 👈 这行是关键
      }
    }
    ```

- ChangeNotifier 的源码如下：

  - ```
    // Flutter Framework 提供的类（在 foundation 包中）
    mixin class ChangeNotifier implements Listenable {
      // 存储所有监听器的列表
      List<VoidCallback?> _listeners = [];
      
      // 添加一个监听器
      void addListener(VoidCallback listener) {
        _listeners.add(listener);
      }
      
      // 移除一个监听器
      void removeListener(VoidCallback listener) {
        _listeners.remove(listener);
      }
      
      // 通知所有监听器
      @protected
      void notifyListeners() {
        for (final VoidCallback? listener in _listeners) {
          listener?.call();  // 遍历调用每个回调函数
        }
      }
    }
    ```

- 当你调用 notifyListeners() 时：遍历 _listeners 列表；依次调用每个回调函数

- 这个listener是什么呢？

#### 2.ChangeNotifierProvider

- 这是我们的代码

  - ```
    ChangeNotifierProvider(
      create: (context) => LoginStatusModel(),
      child: MyApp(),
    )
    ```

- 这是ChangeNotifierProvider  和 ListenableProvider

  - ```
    class ChangeNotifierProvider<T extends ChangeNotifier?>
        extends ListenableProvider<T> {
      // ...
    }
    
    class ListenableProvider<T extends Listenable?> extends InheritedProvider<T> {
      
      static VoidCallback _startListening(
        InheritedContext<Listenable?> e,
        Listenable? value,
      ) {
        // 👇 关键：注册监听器
        value?.addListener(e.markNeedsNotifyDependents);
        
        // 返回移除监听的函数（用于销毁时清理）
        return () => value?.removeListener(e.markNeedsNotifyDependents);
      }
    }
    ```

  - create 函数返回的 LoginStatusModel() 实例，最终会作为 value 传给 _startListening。

  - 实际执行：loginStatusModel.addListener(e.markNeedsNotifyDependents);

  - 此时我们的Model的listener列表里有一个监听器，就是 markNeedsNotifyDependents。

- markNeedsNotifyDependents是什么？

  - 一个方法，作用是：标记依赖项需要被通知更新。

  - ```
    void markNeedsNotifyDependents() {
      markNeedsBuild();  // 标记当前 Element 需要重建
      _shouldNotifyDependents = true;  // 标记需要通知依赖项
    }
    ```

梳理一下：

- LoginStatusModel 继承自 ChangeNotifier，内部有一个 _listeners 列表用于存储监听器
- 我们通过 ChangeNotifierProvider 来创建 LoginStatusModel 实例
- ChangeNotifierProvider 继承自 ListenableProvider
- 创建后会调用 _startListening，把 markNeedsNotifyDependents 注册到 _listeners 中
- markNeedsNotifyDependents 的作用是：标记当前 Element 需要重建 + 标记需要通知依赖项
- 当你调用 notifyListeners() 时，最终会调用到 markNeedsNotifyDependents

### 5.2 _dependents 列表及状态通知

#### 1._dependents 列表

- 从我们的使用代码出发

  - ```
    class HeaderWidget extends StatelessWidget {
      @override
      Widget build(BuildContext context) {
        // 👇 这行代码会把 HeaderWidget 注册到 _dependents
        final loginStatus = context.watch<LoginStatusModel>();
        
        return Text('登录状态: ${loginStatus.isLogin}');
      }
    }
    
    ```

- context.watch() 做了什么？

  - ```
    // Provider 库提供的扩展方法
    extension WatchContext on BuildContext {
      T watch<T>() {
        return Provider.of<T>(this, listen: true);
        //                         ↑
        //                    listen: true 是关键
      }
    }
    
    ```

- 继续看 Provider.of()：

  - ```
    static T of<T>(BuildContext context, {bool listen = true}) {
      // 1. 查找 InheritedWidget
      final inheritedElement = _inheritedElementOf<T>(context);
      
      // 2. 如果 listen 为 true，建立依赖关系
      if (listen) {
        context.dependOnInheritedWidgetOfExactType<_InheritedProviderScope<T?>>();
        //      ↑
        //      这行代码把当前 Widget 注册到 _dependents
      }
      
      // 3. 返回数据
      return inheritedElement?.value as T;
    }
    
    ```

- dependOnInheritedWidgetOfExactType 做了什么？

  - ```
    // Element 类中
    T? dependOnInheritedWidgetOfExactType<T extends InheritedWidget>() {
      // 1. 向上查找 InheritedElement
      final InheritedElement? ancestor = _inheritedWidgets[T];
      
      // 2. 建立依赖关系（关键！）
      if (ancestor != null) {
        // 把当前 Element 引用添加到 ancestor 的 _dependents 列表
        ancestor._dependents.add(this);
      }
      
      // 3. 返回 InheritedWidget
      return ancestor?.widget as T?;
    }
    
    ```

- 此时 _dependents 列表的状态：

  - 假设你有三个 Widget 都调用了 watch：

  - ```
    // HeaderWidget 中
    context.watch<LoginStatusModel>();
    
    // ContentWidget 中
    context.watch<LoginStatusModel>();
    
    // ProfileWidget 中
    context.watch<LoginStatusModel>();
    
    ```

  - 那么 _dependents 列表里就有：

  - ```
    _dependents = {
      HeaderWidget 的 Element,
      ContentWidget 的 Element,
      ProfileWidget 的 Element,
    };
    ```

#### 2.markNeedsNotifyDependents 是怎么通知 _dependents 的？

- 我们的代码

  - ```
    // 你的代码
    void updateLoginStatus(bool isLogin) {
      _isLogin = isLogin;
      notifyListeners();  // 👈 触发点
    }
    ```

  - notifyListeners() → 调用 markNeedsNotifyDependents()

- markNeedsNotifyDependents 源码

  - ```
    // _InheritedProviderScopeElement 类中
    void markNeedsNotifyDependents() {
      markNeedsBuild();                    // 1. 标记自己需要重建
      _shouldNotifyDependents = true;      // 2. 设置标志位
    }
    ```

  - 注意：这里没有直接通知 _dependents，只是设置了一个标志位。

- 真正的通知发生在 build() 中

  - ```
    // _InheritedProviderScopeElement 类中
    @override
    Widget build() {
      // ... 省略其他代码
      
      // 👇 检查标志位
      if (_shouldNotifyDependents) {
        _shouldNotifyDependents = false;   // 重置标志位
        notifyClients(widget);             // 👈 真正通知依赖项
      }
      
      return super.build();
    }
    
    ```

- notifyClients 做了什么？

  - ```
    // InheritedElement 类中（Flutter Framework）
    void notifyClients(InheritedWidget oldWidget) {
      // 遍历 _dependents 列表
      for (final Element dependent in _dependents) {
        notifyDependent(oldWidget, dependent);  // 通知每个依赖项
      }
    }
    
    ```

- notifyDependent 做了什么？

  - ```
    // _InheritedProviderScopeElement 类中（Provider 重写了这个方法）
    @override
    void notifyDependent(InheritedWidget oldWidget, Element dependent) {
      // ... 省略 Selector 的细粒度判断逻辑
      
      // 👇 关键：让依赖项重建
      dependent.didChangeDependencies();
    }
    
    ```

  - didChangeDependencies() 会把这个 Element 标记为"脏"，下一帧 Flutter 会重建它。

- 完整流程
  - ```
    你调用 notifyListeners()
            │
            ↓
    遍历 _listeners，调用 markNeedsNotifyDependents()
            │
            ↓
    markNeedsBuild() + _shouldNotifyDependents = true
            │
            ↓
    下一帧 Flutter 调用 build()
            │
            ↓
    检查 _shouldNotifyDependents == true
            │
            ↓
    调用 notifyClients(widget)
            │
            ↓
    遍历 _dependents 列表
            │
            ↓
    对每个 dependent 调用 didChangeDependencies()
            │
            ↓
    HeaderWidget、ContentWidget、ProfileWidget 被标记为"脏"
            │
            ↓
    Flutter 重建这些 Widget
    ```

- 为什么不直接通知，而是用标志位？

  - 因为 notifyListeners() 可能在一帧内被调用多次：

  - ```
    void updateMultiple() {
      _name = "新名字";
      notifyListeners();  // 第1次
      
      _age = 30;
      notifyListeners();  // 第2次
      
      _avatar = "新头像";
      notifyListeners();  // 第3次
    }
    
    ```

  - 如果每次都直接通知，Widget 会重建 3 次。用标志位的话，只在下一帧 build() 时通知一次，合并多次更新。
