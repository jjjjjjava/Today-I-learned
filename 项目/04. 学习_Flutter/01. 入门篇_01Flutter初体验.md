### 3.2 FlutterActivity 核心原理解读

我们可以看到MainActivity继承自FlutterActivity

#### 1.类的定义 和 核心成员变量

- 类的定义 和 核心成员变量

  - ```java
    //类定义
    public class FlutterActivity extends Activity
        implements FlutterActivityAndFragmentDelegate.Host, LifecycleOwner
        
    // 代理对象，真正干活的是它！
    @VisibleForTesting protected FlutterActivityAndFragmentDelegate delegate;
    
    // 生命周期管理
    @NonNull private LifecycleRegistry lifecycle;
    ```

  - FlutterActivity 就是一个普通的 Android Activity，但它实现了两个接口：

    - FlutterActivityAndFragmentDelegate.Host：让它能托管 Flutter 内容
    - LifecycleOwner：支持 Android 生命周期感知

  - FlutterActivity 采用了委托模式（Delegate Pattern），把核心逻辑都交给 FlutterActivityAndFragmentDelegate 处理。这样 FlutterActivity 和 FlutterFragment 可以共享同一套逻辑

#### 2.onCreate方法

- onCreate方法，核心做了：创建代理对象，创建flutterView，关联生命周期事件

  - ```java
    @Override
    protected void onCreate(@Nullable Bundle savedInstanceState) {
        // 1️⃣ 切换主题（从启动页主题切换到正常主题）
        switchLaunchThemeForNormalTheme();
    
        super.onCreate(savedInstanceState);
    
        // 2️⃣ 创建代理对象
        delegate = new FlutterActivityAndFragmentDelegate(this);
        delegate.onAttach(this);
        delegate.onRestoreInstanceState(savedInstanceState);
    
        // 3️⃣ 生命周期事件
        lifecycle.handleLifecycleEvent(Lifecycle.Event.ON_CREATE);
    
        // 4️⃣ 配置透明窗口（如果需要）
        configureWindowForTransparency();
    
        // 5️⃣ 🔥 关键！创建 FlutterView 并设置为内容视图
        setContentView(createFlutterView());
    
        // 6️⃣ 配置状态栏
        configureStatusBarForFullscreenFlutterExperience();
    }
    
    //第五步是委托给delegate处理
     @NonNull
      private View createFlutterView() {
        return delegate.onCreateView(
            /* inflater=*/ null,
            /* container=*/ null,
            /* savedInstanceState=*/ null,
            /*flutterViewId=*/ FLUTTER_VIEW_ID,
            /*shouldDelayFirstAndroidViewDraw=*/ getRenderMode() == RenderMode.surface);
      }
    ```

### 3. 原理

- 原理：createFlutterView() 会创建一个 FlutterView（本质是 SurfaceView），然后通过 setContentView() 把它设置为 Activity 的内容。你的 Dart 代码渲染的 UI 就直接绘制在这个 View 上并显示出来。

- 好的，现在我们能回答上面的问题了，flutter如何在Activity中显示出来的？
  - flutter需要一个FlutterActivity作为桥梁，连接Android系统和Flutter引擎
  - FlutterActivity会提供一个FlutterView(SurfaceView / TextureView类型)作为画布，让flutter自己在上面绘制
  - 用户的Dart代码会借助flutterEngine引擎转换为对应的对FlutterView的绘制操作
  - 也就是说：FlutterActivity作为宿主，同时提供画布。供flutter处理。
- 我们现在简易的回答了绘制的操作，那么线程模型呢？事件机制呢？

### 3.3 FlutterActivityAndFragmentDelegate 核心原理解读

#### 1.为什么需要这个类

- 为什么需要这个类？源码注释说得很清楚：为了避免 Fragment 库带来的 100KB 体积增加，Flutter 同时提供了 FlutterActivity 和 FlutterFragment。这个 Delegate 类封装了它们共同的逻辑，避免代码重复。这是典型的委托模式（Delegate Pattern）

#### 2.核心方法doInitialFlutterViewRun()

- FlutterActivity在OnStart中调用

  - ```java
      @Override
      protected void onStart() {
        super.onStart();
        lifecycle.handleLifecycleEvent(Lifecycle.Event.ON_START);
        if (stillAttachedForEvent("onStart")) {
          delegate.onStart();
        }
      }
    ```

- delegate的onStart

  - ```java
     void onStart() {
        Log.v(TAG, "onStart()");
        ensureAlive();
        doInitialFlutterViewRun();
        // This is a workaround for a bug on some OnePlus phones. The visibility of the application
        // window is still true after locking the screen on some OnePlus phones, and shows a black
        // screen when unlocked. We can work around this by changing the visibility of FlutterView in
        // onStart and onStop.
        // See https://github.com/flutter/flutter/issues/93276
        if (previousVisibility != null) {
          flutterView.setVisibility(previousVisibility);
        }
      }
    ```

- 最后调用到doInitialFlutterViewRun()方法

  - ```java
    private void doInitialFlutterViewRun() {
        // 如果已经在执行 Dart 代码，就不重复执行
        if (flutterEngine.getDartExecutor().isExecutingDart()) {
            return;
        }
    
        // 1️⃣ 设置初始路由（默认是 "/"）
        String initialRoute = host.getInitialRoute();
        flutterEngine.getNavigationChannel().setInitialRoute(initialRoute);
    
        // 2️⃣ 找到 Dart 代码的位置（app bundle）
        String appBundlePath = FlutterInjector.instance().flutterLoader().findAppBundlePath();
    
        // 3️⃣ 配置 Dart 入口点（默认是 main() 函数）
        DartExecutor.DartEntrypoint entrypoint = new DartExecutor.DartEntrypoint(
            appBundlePath, 
            host.getDartEntrypointFunctionName()  // 默认是 "main"
        );
    
        // 4️⃣ 🔥🔥🔥 执行 Dart 代码！
        flutterEngine.getDartExecutor().executeDartEntrypoint(entrypoint, host.getDartEntrypointArgs());
    }
    
    ```

  - 这一行就是启动你的 main.dart 的 main() 函数的地方！

#### 3.核心方法：onCreateView创建 FlutterView

- 上面的FlutterActivity中的onCreate方法中创建FlutterView

  - ```java
     @NonNull
      private View createFlutterView() {
        return delegate.onCreateView(
            /* inflater=*/ null,
            /* container=*/ null,
            /* savedInstanceState=*/ null,
            /*flutterViewId=*/ FLUTTER_VIEW_ID,
            /*shouldDelayFirstAndroidViewDraw=*/ getRenderMode() == RenderMode.surface);
      }
    ```

- 这是delegate内部的create方法

  - ```java
    View onCreateView(...) {
        // 根据渲染模式选择不同的 View
        if (host.getRenderMode() == RenderMode.surface) {
            // 使用 SurfaceView（性能更好，但不支持透明）
            FlutterSurfaceView flutterSurfaceView = new FlutterSurfaceView(...);
            flutterView = new FlutterView(host.getContext(), flutterSurfaceView);
        } else {
            // 使用 TextureView（支持透明，但性能稍差）
            FlutterTextureView flutterTextureView = new FlutterTextureView(...);
            flutterView = new FlutterView(host.getContext(), flutterTextureView);
        }
    
        // 🔥 把 FlutterView 和 FlutterEngine 连接起来
        flutterView.attachToFlutterEngine(flutterEngine);
        
        return flutterView;
    }
    ```

#### 4.核心方法：setUpFlutterEngine()

- FlutterActivity中调用

  - ```java
    @Override
    protected void onCreate(@Nullable Bundle savedInstanceState) {
        // 1️⃣ 切换主题（从启动页主题切换到正常主题）

    ```

- delgate中onAttach

  - ```java
    void onAttach(@NonNull Context context) {
        ensureAlive();
    
        // When "retain instance" is true, the FlutterEngine will survive configuration
        // changes. Therefore, we create a new one only if one does not already exist.
        if (flutterEngine == null) {
          setUpFlutterEngine();
        }
    ```

- 最后调用到setUpFlutterEngine方法，生成flutterEngine

  - ```java
    void setUpFlutterEngine() {
        // 1️⃣ 优先使用缓存的 FlutterEngine（性能最好）
        String cachedEngineId = host.getCachedEngineId();
        if (cachedEngineId != null) {
            flutterEngine = FlutterEngineCache.getInstance().get(cachedEngineId);
            return;
        }
    
        // 2️⃣ 让宿主自定义提供 FlutterEngine
        flutterEngine = host.provideFlutterEngine(host.getContext());
        if (flutterEngine != null) {
            return;
        }
    
        // 3️⃣ 使用 FlutterEngineGroup 创建（多引擎共享资源）
        String cachedEngineGroupId = host.getCachedEngineGroupId();
        if (cachedEngineGroupId != null) {
            FlutterEngineGroup group = FlutterEngineGroupCache.getInstance().get(cachedEngineGroupId);
            flutterEngine = group.createAndRunEngine(...);
            return;
        }
    
        // 4️⃣ 都没有？那就新建一个
        FlutterEngineGroup group = new FlutterEngineGroup(host.getContext(), ...);
        flutterEngine = group.createAndRunEngine(...);
    }
    
    ```

#### 5.flutterEngine是什么？

flutterEngine是flutter代码的运行环境，他是一个容器，他应该包含以下几个部分

| Flutter 概念      | 类比 Android               |
| ----------------- | -------------------------- |
| **FlutterEngine** | **一个“Flutter 运行环境”** |
| Dart Isolate      | 一条 Dart 主线程           |
| Flutter Framework | 相当于 View/UI 框架        |
| Skia              | 相当于 RenderThread + GPU  |
| Platform Channel  | JNI / Binder               |

FlutterEngine就是上面的所有的线程，UI，渲染，通信框架，虚拟机的容器

### 3.4 flutter底层原理

- 这是原理图

  - ```
    ┌──────────────────────────────────────────────────────────────┐
    │  Dart 代码: FloatingActionButton(...)                        │
    │                      │                                       │
    │                      ▼                                       │
    │  Flutter Framework (Dart): Widget → Element → RenderObject   │
    │                      │                                       │
    │                      ▼                                       │
    │  Flutter Engine (libflutter.so / C++)                        │
    │                      │                                       │
    │                      ▼                                       │
    │  Skia: 生成渲染指令                                           │
    │                      │                                       │
    │                      ▼                                       │
    │  OpenGL ES / Vulkan: GPU 渲染                                │
    │                      │                                       │
    │                      ▼ (生产者)                               │
    │  GraphicBuffer (Surface 内部)                                │
    └──────────────────────────────────────────────────────────────┘
                           │
                           │ Binder IPC
                           ▼
    ┌──────────────────────────────────────────────────────────────┐
    │  SurfaceFlinger (消费者)                                      │
    │                      │                                       │
    │                      ▼                                       │
    │  合成所有窗口层 → 显示到屏幕                                   │
    └──────────────────────────────────────────────────────────────┘
    
    ```

- 这是原理：

  - Flutter在Android中绘制的底层基础是Surface，通常由SurfaceView/TextureView承载。也就是说：我们FlutterActivity创建的FlutterView其实是一个SurfaceView或TextureView。
  - 如果绘制一个button，其通过Dart的API，经过flutter的Framework层处理，生成对应的RenderObject，并调用 Flutter Engine（C++）so，借助skia生成对应的渲染指令，最终通过 OpenGL / Vulkan 等 GPU API 渲染到SurfaceView上。
  - 其作为生产者将图形绘制到SurfaceView所掌握的Surface的GraphicBuffer中，然后通过BinderIpc调用SurfaceFlinger将其混合绘制显示到屏幕上

### 4.1 main函数

#### 1.需求

这是上面执行的dart中的main函数代码

```java
void main() {
  runApp(const MyApp());
}
```

他要完成下面的任务：启动 Flutter 应用，让你的 Widget 显示到屏幕上。

具体来说：他要做下面的事情

- 初始化 Flutter的UI框架
- 把你的 Widget（MyApp）交给框架管理
- 触发第一帧渲染

#### 2.代码

```java
void runApp(Widget app) {
  // 第一步：初始化框架
  final WidgetsBinding binding = WidgetsFlutterBinding.ensureInitialized();
  
  // 第二步：包装你的 Widget，准备挂载
  // 第三步：调度挂载和渲染
  _runWidget(binding.wrapWithDefaultView(app), binding, 'runApp');
}

void _runWidget(Widget app, WidgetsBinding binding, String debugEntryPoint) {
  binding
    ..scheduleAttachRootWidget(app)  // 把 Widget 挂载到框架
    ..scheduleWarmUpFrame();          // 触发第一帧渲染
}
```

### 4.2 WidgetsFlutterBinding.ensureInitialized()

#### 1.目的

很简单，初始化Flutter的UI框架，让我们的UI可以正确的显示

#### 2.原理

连接native层的flutterEngine，也就是libflutter.so

```
┌─────────────────────────────────────────────────────────┐
│                    Dart 层                              │
│                                                         │
│   你的代码 ←→ Flutter Framework ←→ Binding             │
│                                         │               │
└─────────────────────────────────────────│───────────────┘
                                          │ 连接
┌─────────────────────────────────────────│───────────────┐
│                                         ▼               │
│                    Engine 层 (C++)                      │
│                                                         │
│   Dart VM ←→ Skia ←→ Platform API                      │
└─────────────────────────────────────────────────────────┘
```

#### 3.代码

他其实就是创建每个Binding的instance

WidgetsFlutterBinding 是多个 Binding 的组合（通过 Mixin）：

```
class WidgetsFlutterBinding extends BindingBase 
    with GestureBinding,      // 手势识别
         SchedulerBinding,    // 帧调度（vsync）
         ServicesBinding,     // 平台服务
         PaintingBinding,     // 图片缓存
         SemanticsBinding,    // 无障碍
         RendererBinding,     // 渲染管线
         WidgetsBinding {     // Widget 管理
  
  static WidgetsBinding ensureInitialized() {
    if (WidgetsBinding._instance == null) {
      WidgetsFlutterBinding();  // 创建单例
    }
    return WidgetsBinding.instance;
  }
}
```

初始化时，每个 Binding 的 initInstances() 会被调用

```
// WidgetsBinding 的初始化
mixin WidgetsBinding on BindingBase, ... {
  @override
  void initInstances() {
    super.initInstances();
    _instance = this;
    
    // 创建 BuildOwner，它负责管理 Widget 的构建
    _buildOwner = BuildOwner();
    buildOwner!.onBuildScheduled = _handleBuildScheduled;
    
    // 监听系统事件
    platformDispatcher.onLocaleChanged = handleLocaleChanged;
    SystemChannels.navigation.setMethodCallHandler(_handleNavigationInvocation);
  }
}
```

### 4.3 attachRootWidget（挂载）

本质就是 把 Widget 挂载到框架中，让框架能够管理它。这是因为Widget 只是配置描述，它本身不能显示任何东西。必须通过挂载，创建出真正的 Element 和 RenderObject，才能渲染到屏幕。

#### 1.原理

挂载的本质是：根据 Widget 创建 Element，根据需要创建 RenderObject。

```
Widget (配置)
    │
    │ createElement()
    ▼
Element (实例)
    │
    │ createRenderObject() [如果是 RenderObjectWidget]
    ▼
RenderObject (渲染)

```

这个过程是递归的：

- 挂载根 Widget
- 根 Widget 的 Element 调用 build() 获取子 Widget
- 子 Widget 继续挂载
- 直到整棵树构建完成

#### 2.架构

```
scheduleAttachRootWidget(app)
        │
        │ Timer.run() 异步执行
        ▼
attachRootWidget(rootWidget)
        │
        │ 创建 RootWidget 包装
        ▼
attachToBuildOwner(RootWidget)
        │
        │ 调用 RootWidget.attach()
        ▼
RootWidget.attach(buildOwner)
        │
        ├── createElement() → 创建 RootElement
        │
        └── element.mount(null, null) → 开始递归挂载

```

#### 3.代码

```
// 第一步：调度挂载（异步）
void scheduleAttachRootWidget(Widget rootWidget) {
  Timer.run(() {
    attachRootWidget(rootWidget);
  });
}

// 第二步：创建 RootWidget 包装
void attachRootWidget(Widget rootWidget) {
  attachToBuildOwner(RootWidget(
    debugShortDescription: '[root]',
    child: rootWidget,  // 你的 MyApp
  ));
}

// 第三步：挂载到 BuildOwner
void attachToBuildOwner(RootWidget widget) {
  _rootElement = widget.attach(buildOwner!, rootElement);
}
```

RootWidget.attach() 的实现

```
// RootWidget.attach() 的实现
RootElement attach(BuildOwner owner, [RootElement? element]) {
  if (element == null) {
    // 首次挂载
    owner.lockState(() {
      element = createElement();  // 创建 RootElement
      element!.assignOwner(owner);
    });
    owner.buildScope(element!, () {
      element!.mount(null, null);  // 挂载！递归构建整棵树，，null 表示没有父节点（因为是根）
    });
  } else {
    // 更新
    element._newWidget = this;
    element.markNeedsBuild();
  }
  return element!;
}

```

  _parent = parent;
  _slot = newSlot;
  _depth = _parent != null ? _parent!.depth + 1 : 1;
  
  // 如果是 ComponentElement（StatelessElement/StatefulElement）
  // 会调用 build() 获取子 Widget，然后继续挂载子 Element
}

// StatefulElement.mount() 会额外做：

### 4.4 三棵树的构建

#### 1.为什么需要三棵树

为了分离，分离的好处：

- Widget 可以频繁重建（轻量级）
- Element 尽量复用（避免重复创建）
- RenderObject 只在必要时更新（性能优化）

#### 2.原理

三棵树的对应关系

```
Widget 树                Element 树              RenderObject 树
(配置)                   (实例)                  (渲染)

MyApp                    StatelessElement        
  │                           │                  
  └─ MaterialApp         ComponentElement        
       │                      │                  
       └─ Scaffold       RenderObjectElement ──→ RenderFlex
            │                 │                      │
            ├─ AppBar    RenderObjectElement ──→ RenderBox
            │                 │                      │
            └─ Center    RenderObjectElement ──→ RenderPositionedBox
                 │            │                      │
                 └─ Text RenderObjectElement ──→ RenderParagraph
```

这里是不是很困惑，MyApp是StatelessWidget 。MaterialApp是StatefulWidget 。但是他们都只有 Element，没有 RenderObject

这涉及到Widget的分类

```
Widget
  │
  ├── RenderObjectWidget (有 RenderObject)
  │     ├── SingleChildRenderObjectWidget
  │     ├── MultiChildRenderObjectWidget
  │     └── LeafRenderObjectWidget
  │
  └── ComponentWidget (无 RenderObject，只组合其他 Widget)
        ├── StatelessWidget
        └── StatefulWidget
```

注意：

- 只有 RenderObjectWidget 的子类才会创建 RenderObject
- 这里就类似于ViewGroup和View的概念，View是实际渲染的，因此需要RenderObject。ViewGroup只是构建布局约束，不实际显示

#### 3.代码

以MyHomePage 为例：

- ```
  class MyHomePage extends StatefulWidget {
    @override
    State<MyHomePage> createState() => _MyHomePageState();
  }
  
  class _MyHomePageState extends State<MyHomePage> {
    int _counter = 0;
    
    @override
    Widget build(BuildContext context) {
      return Scaffold(...);  // 返回子 Widget
    }
  }
  ```

挂载过程：

- ```
  1. MyHomePage.createElement()
     → 创建 StatefulElement
  
  2. StatefulElement.mount()
     → 调用 MyHomePage.createState()
     → 创建 _MyHomePageState
     → 调用 _state.initState()
  
  3. StatefulElement._firstBuild()
     → 调用 _state.build(context)
     → 返回 Scaffold Widget
  
  4. Scaffold.createElement()
     → 创建 ScaffoldElement (这是 StatefulElement)
     → 继续递归...
  
  5. 当遇到 RenderObjectWidget 时
     → 调用 createRenderObject()
     → 创建 RenderObject
     → 加入 RenderObject 树
  
  ```

### 4.5 首帧渲染

三棵树构建完成后，如何显示到屏幕？

#### 1.原理

渲染管线：

- ```
  scheduleWarmUpFrame()
          │
          ▼
  handleBeginFrame()     ← vsync 信号
          │
          ▼
  handleDrawFrame()
          │
          ├── buildScope() → 构建脏 Widget
          │
          ├── flushLayout() → 布局计算
          │
          ├── flushPaint() → 生成绘制指令
          │
          └── compositeFrame() → 提交到 Engine
                  │
                  ▼
          Flutter Engine (Skia)
                  │
                  ▼
          GPU 渲染 → 屏幕
  
  ```

#### 2.代码

```
// 调度第一帧
void scheduleWarmUpFrame() {
  Timer.run(() {
    handleBeginFrame(null);  // 开始帧
  });
  Timer.run(() {
    handleDrawFrame();       // 绘制帧
  });
}

// 绘制帧
void handleDrawFrame() {
  // 1. 构建脏 Widget
  buildOwner!.buildScope(rootElement!);
  
  // 2. 布局
  pipelineOwner.flushLayout();
  
  // 3. 绘制
  pipelineOwner.flushPaint();
  
  // 4. 提交
  renderView.compositeFrame();
}

```

RenderView.compositeFrame()

```
// RenderView.compositeFrame()
void compositeFrame() {
  final ui.SceneBuilder builder = ui.SceneBuilder();
  final ui.Scene scene = layer!.buildScene(builder);
  
  // 提交到 Engine！
  _view.render(scene);
  
  scene.dispose();
}

```

_view.render(scene) 就是把绘制结果提交给 Flutter Engine，然后 Skia 渲染到屏幕。

完整流程

```
main()

  └─→ runApp(MyApp)
        │
        ├─→ WidgetsFlutterBinding.ensureInitialized()
        │     初始化框架，创建 BuildOwner
        │
        ├─→ scheduleAttachRootWidget(app)
        │     │
        │     └─→ attachRootWidget()

        │           └─→ RootWidget.attach()
        │                 │
        │                 └─→ element.mount()

        │                       └─→ 递归构建三棵树
        │                             Widget → Element → RenderObject

        └─→ scheduleWarmUpFrame()
              │
              └─→ handleDrawFrame()
                    │
                    ├─→ buildScope() 构建
                    ├─→ flushLayout() 布局
                    ├─→ flushPaint() 绘制
                    └─→ compositeFrame() 提交
                          │
                          └─→ Engine → Skia → GPU → 屏幕

```
