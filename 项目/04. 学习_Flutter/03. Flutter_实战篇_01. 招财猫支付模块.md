核心思想：高层模块不依赖低层模块，都依赖抽象

// UseCase依赖抽象，不依赖具体实现
class ProcessPaymentUseCase {
  final PaymentRepository _repository; // 依赖接口，不是实现
  
  ProcessPaymentUseCase(this._repository);
}

```

    ↓

2. PaymentNotifier接收Intent

3. 切换状态：Initial → Loading

    ↓

    ↓
【Data层】
    ↓

    ↓
【返回Presentation层】
    ↓

    ↓
9. 触发扫码Intent
   notifier.handleIntent(const ScanQRCode());
    ↓
10. 切换状态：Ready → Processing
    state = PaymentProcessing(statusMessage: '正在扫码...');
    ↓
【Platform Channel】
    ↓
11. 调用原生扫码
    final authCode = await _platformChannel.scanQRCode();
    // 当前Mock返回：'134567890123456789'
    ↓
【Data层】
    ↓
12. 查询连接状态
    await _repository.processPayConnect(authCode, orderSn);
    // Mock: 延迟200ms，5%概率失败
    ↓
13. 处理支付
    await _repository.processPayment(orderSn);
    // Mock: 延迟1000ms，10%概率失败
    ↓
14. 轮询支付状态（最多10次，每次500ms）
    for (int i = 0; i < 10; i++) {
      final status = await _repository.queryPaymentStatus(orderSn);
      if (status == success || status == failed) break;
      await Future.delayed(500ms);
    }
    ↓
【返回Presentation层】
    ↓
15. 切换状态：Processing → Success/Failed
    state = PaymentSuccess(result);
    或
    state = PaymentFailed(message);

##### 2.2 paymentProvider 是什么？

```
// payment_provider.dart
final paymentProvider = StateNotifierProvider<PaymentNotifier, PaymentState>((ref) {
  final useCase = ref.watch(processPaymentUseCaseProvider);
  return PaymentNotifier(useCase);
});
```

这是一个Provider 的定义，告诉 Riverpod：

- "我叫 paymentProvider"
- "我管理的状态类型是 PaymentState"
- "我的控制器类型是 PaymentNotifier"
- "创建我的时候，需要先创建 processPaymentUseCaseProvider"

##### 2.3 ref.read(paymentProvider.notifier) 执行过程

```
1. ref.read() 告诉容器："我要读取 paymentProvider"
   ↓
2. 容器检查："paymentProvider 创建过吗？"
   - 如果没有 → 执行创建流程（见 Step 3）
   - 如果有 → 直接返回
   ↓
3. .notifier 表示："我要的是控制器，不是状态"
   ↓
4. 返回 PaymentNotifier 实例

```

#### Step 3: 首次创建 paymentProvider（依赖链触发）

当第一次 ref.read(paymentProvider) 时，触发创建：

```
// payment_provider.dart
final paymentProvider = StateNotifierProvider<PaymentNotifier, PaymentState>((ref) {
  // 🔥 这个函数现在被执行
  
  // 第1步：需要 useCase
  final useCase = ref.watch(processPaymentUseCaseProvider);
  // ↑ 这里又触发了另一个 Provider 的创建！
  
  // 第2步：创建 PaymentNotifier
  return PaymentNotifier(useCase);
});

```

依赖链自动触发：

```
ref.read(paymentProvider)
  ↓ 需要 useCase
ref.watch(processPaymentUseCaseProvider)
  ↓ 需要 repository 和 platformChannel
ref.watch(paymentRepositoryProvider) + ref.watch(paymentPlatformChannelProvider)
  ↓ repository 需要 dataSource
ref.watch(paymentDataSourceProvider)
  ↓ 创建 PaymentMockDataSource()
  ↓ 返回给 repository
  ↓ 创建 PaymentRepositoryImpl(dataSource)
  ↓ 返回给 useCase
  ↓ 创建 ProcessPaymentUseCase(repository, platformChannel)
  ↓ 返回给 paymentProvider
  ↓ 创建 PaymentNotifier(useCase)
  ↓ 返回给调用者
```

完整代码流程：

```
// 1️⃣ 最底层先创建
final paymentDataSourceProvider = Provider<PaymentMockDataSource>((ref) {
  print('🔧 创建 PaymentMockDataSource');
  return PaymentMockDataSource();
});

// 2️⃣ 然后创建 Repository
final paymentRepositoryProvider = Provider<PaymentRepository>((ref) {
  print('🔧 创建 PaymentRepository');
  final dataSource = ref.watch(paymentDataSourceProvider); // ← 触发上面的创建
  return PaymentRepositoryImpl(dataSource);
});

// 3️⃣ 创建 PlatformChannel（独立的）
final paymentPlatformChannelProvider = Provider<PaymentPlatformChannel>((ref) {
  print('🔧 创建 PaymentPlatformChannel');
  return PaymentPlatformChannel();
});

// 4️⃣ 创建 UseCase
final processPaymentUseCaseProvider = Provider<ProcessPaymentUseCase>((ref) {
  print('🔧 创建 ProcessPaymentUseCase');
  final repository = ref.watch(paymentRepositoryProvider); // ← 触发 2️⃣
  final platformChannel = ref.watch(paymentPlatformChannelProvider); // ← 触发 3️⃣
  return ProcessPaymentUseCase(repository, platformChannel);
});

// 5️⃣ 最后创建 PaymentNotifier
final paymentProvider = StateNotifierProvider<PaymentNotifier, PaymentState>((ref) {
  print('🔧 创建 PaymentNotifier');
  final useCase = ref.watch(processPaymentUseCaseProvider); // ← 触发 4️⃣
  return PaymentNotifier(useCase);
});

```

// payment_provider.dart
class PaymentNotifier extends StateNotifier<PaymentState> {
  final ProcessPaymentUseCase _useCase;
  
  PaymentNotifier(this._useCase) : super(const PaymentInitial());
  // ↑ 初始状态是 PaymentInitial
  
  void handleIntent(PaymentIntent intent) {
    print('📥 收到 Intent: ${intent.runtimeType}');
    
    switch (intent) {
      case ClickOrderButton():
        _handleClickOrderButton(intent);  // ← 执行这个
      // ... 其他 case
    }
  }
  
  Future<void> _handleClickOrderButton(ClickOrderButton intent) async {
    try {
      // 🔥 第1次状态变化
      print('🔄 状态变化: PaymentInitial → PaymentLoading');
      state = const PaymentLoading();
      // ↑ 修改 state 会通知所有监听者
      
      // 调用业务逻辑
      final paymentInfo = await _useCase.initializePayment(intent.cartData);
      
      // 🔥 第2次状态变化
      print('🔄 状态变化: PaymentLoading → PaymentReady');
      state = PaymentReady(paymentInfo: paymentInfo);
      
    } catch (e) {
      // 🔥 错误状态
      print('🔄 状态变化: PaymentLoading → PaymentLoadError');
      state = PaymentLoadError(e.toString());
    }
  }
}
```

Future<void> _handleScanQRCode() async {
  final currentState = state as PaymentReady;
  
  try {
    // 🔥 状态1：扫码中
    state = PaymentProcessing(
      paymentInfo: currentState.paymentInfo,
      statusMessage: '正在扫码...',
    );
    // ↓ PaymentDialog 重建，显示 PaymentProcessingOverlay
    
    // 执行扫码
    final result = await _useCase.executeScanPayment(currentState.paymentInfo);
    
    // 🔥 状态2：支付处理中
    state = PaymentProcessing(
      paymentInfo: currentState.paymentInfo,
      statusMessage: '支付处理中，请稍候...',
    );
    // ↓ PaymentDialog 重建，更新提示文字
    
    // 轮询支付状态
    final status = await _useCase.pollPaymentStatus(currentState.paymentInfo.orderSn);
    
    // 🔥 状态3：最终结果
    if (status == PaymentStatus.success) {
      state = PaymentSuccess(result);
      // ↓ PaymentDialog 重建，显示成功界面
    } else {
      state = PaymentFailed('支付失败或超时', paymentInfo: currentState.paymentInfo);
      // ↓ PaymentDialog 重建，显示失败界面
    }
    
  } catch (e) {
    state = PaymentFailed(e.toString(), paymentInfo: currentState.paymentInfo);
  }
}

#### 🎯关键设计：State 的不可变性

注意看这个细节：

```
// payment_state.dart
class PaymentReady extends PaymentState {
  final PaymentInfo paymentInfo;
  final PaymentMethod selectedMethod;
  
  const PaymentReady({  // ← const 构造函数
    required this.paymentInfo,
    this.selectedMethod = PaymentMethod.scanCode,
  });
  
  // 🔥 关键：copyWith 方法
  PaymentReady copyWith({
    PaymentInfo? paymentInfo,
    PaymentMethod? selectedMethod,
  }) {
    return PaymentReady(
      paymentInfo: paymentInfo ?? this.paymentInfo,
      selectedMethod: selectedMethod ?? this.selectedMethod,
    );
  }
}

```

为什么要不可变？

```
// ❌ 错误做法（可变状态）
class PaymentNotifier extends StateNotifier<PaymentState> {
  void selectMethod(PaymentMethod method) {
    if (state is PaymentReady) {
      final current = state as PaymentReady;
      current.selectedMethod = method;  // ❌ 直接修改，不会触发通知！
    }
  }
}

// ✅ 正确做法（不可变状态）
class PaymentNotifier extends StateNotifier<PaymentState> {
  void _handleSelectPaymentMethod(SelectPaymentMethod intent) {
    if (state is PaymentReady) {
      final currentState = state as PaymentReady;
      
      // 创建新的状态对象
      state = currentState.copyWith(selectedMethod: intent.method);
      // ↑ 这会触发通知，因为 state 引用变了
    }
  }
}

```

原理：

- Riverpod 通过对象引用判断状态是否变化
- 如果 state = newState，引用变了 → 触发通知
- 如果只修改对象内部属性，引用没变 → 不会触发通知
