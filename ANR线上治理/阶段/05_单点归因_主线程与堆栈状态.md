# 05 · 单点归因：主线程与堆栈状态

## 课程范围

## RUNNABLE

可能是 Java/Kotlin 计算、文件 IO、图片处理、数据库或同步 Binder；不等于正在持续占满 CPU。

```text
main RUNNABLE
→ FileOutputStream.write
→ saveImageToGallery
```

当前快照支持“主线程正在同步 IO 路径”，是否持续足够久还需多样本、源码或修复结果佐证。

案例：Camera 图片压缩和写文件运行在主线程。

## BLOCKED

表示主线程尝试进入 Java monitor，但锁被其他线程持有。

```text
main BLOCKED
waiting to lock A
held by thread 58
```

直接原因是主线程拿不到锁 A。根因需要继续追持锁线程：它是否做耗时工作、等待另一把锁，或形成 AB-BA 环。

案例：极验 AB-BA 死锁。

## WAITING

表示主线程在等待条件成立，不等同于等待进入 `synchronized`。

| 栈/API | 下一步 |
|---|---|
| `Object.wait()` | 找谁修改条件并 `notify` |
| `CountDownLatch.await()` | 找谁负责 `countDown` |
| `Future.get()` | 找任务是否执行与完成 |
| `Thread.join()` | 找被等待线程为何未退出 |

## NATIVE

`NATIVE` 是平台展示或栈形态，不是与前三项完全同维度的 Java `Thread.State`。必须读具体 native 栈：

| native 栈 | 方向 |
|---|---|
| `nativePollOnce` | 当前主线程栈通常信息量低 |
| `transactNative` | 同步 Binder 等待 |
| `read/write/fsync` | 文件或设备 IO |
| `futex/pthread_mutex` | native 锁等待 |
| `pthread_join` | 等待其他线程退出 |

案例：IJK 释放时主线程停在 `pthread_join`，等待音频线程从 `AudioTrack.write()` 返回并退出。
