## 核心掌握项

完成本课题后，你将能够：

### 一、从线上入口到单点问题

- [x] 能够根据日常线上看板与告警机器人两种入口，分别选择共性归因和爆发归因路径
- [x] 能够通过机型、地区、企业、页面和公共调用栈做共性切片，并把切片结果转化为代码排查假设
- [x] 能够对简单爆发问题执行确认、止损、多维切片，并识别何时已经超出当前处理边界

### 二、单点证据判断与根因追踪

- [x] 能够根据 ANR subject 判断主要 ANR 类型，并为不同类型选择正确的观察线程
- [x] 能够判断 `nativePollOnce`、空闲主线程及单次堆栈是否具有归因价值
- [x] 能够结合调用栈解释 RUNNABLE、BLOCKED、WAITING/TIMED_WAITING，而不是仅凭线程状态下结论
- [ ] 能够沿锁地址、调用链或 Binder 链追踪责任方，并区分直接原因、根本原因和证据链

### 三、修复、灰度与结果验证

- [ ] 能够根据主线程耗时、锁竞争、三方库和系统问题选择边界清晰的处置方案
- [ ] 能够设计具有可比实验组、对照组、核心指标和护栏指标的灰度验证方案
- [ ] 能够解释为什么“ANR 下降 50%”不足以证明修复有效，并给出继续放量、停止或回滚的判断依据

### 四、前置防线与案例复盘

- [ ] 能够为 Lint、StrictMode、自动化压力测试、灰度门禁和全量监控划分职责边界
- [ ] 能够把一次真实 ANR 处理整理为“入口—切片—单点证据—源码定位—修改—验证”的可复查记录

## 不在本课题范围内

- 不逐行讲解 ActivityManagerService、WindowManagerService 的完整 ANR 源码
- 不背诵所有 Android 版本及 OEM 的精确超时常量
- 不展开 Bugly 热修复、Tinker 等补丁合成、加载和发布实现
- 不教授公司内部灰度平台或热修复平台的具体操作
- 不覆盖与 ANR 无直接关系的常规卡顿、内存泄漏和崩溃治理
